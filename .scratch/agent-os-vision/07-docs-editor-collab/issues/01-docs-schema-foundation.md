# Docs schema foundation — ALTER TABLE docs + doc_links + doc_versions + doc_comments + doc_templates

## Parent
PRD: `.scratch/agent-os-vision/prds/07-docs-editor-collab.md` (issues lines P7-01..P7-02)

## What to build
Two MikroORM v7 migration classes establishing the complete Pillar 7 schema. Migration class 1 adds additive properties to the `Doc` entity (`parent`, `scope`, `docType`, `frontmatter`, `bodyMd`, `contentJson`, `sortPosition`, `archived`, `externalId`) plus all `docs_org_*` composite indexes. Migration class 2 creates `DocLink`, `DocVersion`, `DocComment`, `DocTemplate` entities with full property sets, CHECK constraints, FK cascades, and composite `(org_id, …)` indexes per Q22. Both migration classes auto-generated by `mikro-orm migration:create`. MikroORM entity types + Zod base shapes exported from `src/db/entities/docs/`.

## Acceptance criteria
- [ ] Migration class 1: `Doc` entity ALTERed idempotently — all nine properties present, re-run no-op
- [ ] Migration class 1: `docType` CHECK (`spec|adr|wiki|runbook|meeting|postmortem|rfc|note|scratch`), `scope` CHECK (`project|global`)
- [ ] Migration class 1: indexes `docs_org_project_scope`, `docs_org_doc_type`, `docs_org_parent`, `docs_org_external_id` UNIQUE PARTIAL (WHERE external_id IS NOT NULL) all present
- [ ] Migration class 2: `DocLink` entity with properties `(id, org, fromDoc, toDoc, toSlug, linkKind, anchor, createdAt)` with CHECK (`wikilink|task_ref|run_ref|mention`); `doc_links_org_from`, `doc_links_org_to` indexes
- [ ] Migration class 2: `DocVersion` entity with properties `(id, org, doc, versionNum, snapshot, delta, bodyMdSnapshot, author, restoreOf, createdAt)` with UNIQUE `(doc_id, version_num)`; index `doc_versions_org_doc_version`
- [ ] Migration class 2: `DocComment` entity with properties `(id, org, doc, anchorRange, author, bodyMd, parentComment, resolved, createdAt, updatedAt)`; index `doc_comments_org_doc`
- [ ] Migration class 2: `DocTemplate` entity with properties `(id, org, project, docType, name, frontmatterTemplate, bodyTemplate, isDefault, createdAt)` with UNIQUE `(org_id, project_id, doc_type, name)`; index `doc_templates_org_project_type`
- [ ] Logic: `Doc`, `DocLink`, `DocVersion`, `DocComment`, `DocTemplate` MikroORM entity types exported with correct nullability
- [ ] Logic: `DocTypeEnum` + `ScopeEnum` + `LinkKindEnum` Zod enums exported from `src/db/entities/docs/`
- [ ] Tests: both migration classes idempotent (`mikro-orm migration:up` twice = no error, same schema)
- [ ] Tests: `Doc.parent` ON DELETE SET NULL — delete parent entity, child `parent` becomes null; verified via repository read
- [ ] Tests: `DocLink.fromDoc` ON DELETE CASCADE — delete doc entity, all outbound links removed
- [ ] Tests: `DocComment.parentComment` ON DELETE CASCADE — delete thread root, replies removed
- [ ] Tests: `EXPLAIN` on `WHERE org_id=? AND project_id=? AND scope=?` uses `docs_org_project_scope`

## Notes / Tech-stack hints
- `contentJson` default `{}`; `frontmatter` default `{}`; `sortPosition float8` default `0` — set at entity property level via MikroORM `default`
- `externalId` format: `'confluence:<page_id>'` | `'notion:<page_id>'` — validated by Zod pattern in TS, not at DB level
- `DocVersion.restoreOf` FK ON DELETE SET NULL — restoring to a version that was itself a restore must not cascade-delete
- Failure gate: if PGlite WASM doesn't support the recursive CTE needed for tree queries, document the fallback to a closure table alongside (PRD tech-stack row)
