# Tasks table schema extension + composite indexes

## Parent
PRD: `.scratch/agent-os-vision/prds/06-tasks-and-scrum.md` (issues breakdown lines T6-01)

## What to build
MikroORM v7 additive migration extending the `Task` entity with six new properties (`sprint`, `customFields`, `points`, `parent`, `dependencies`, `externalId`) and creating the `TaskStatus` entity. Entity files: `src/db/entities/tasks/Task.ts` (updated), `src/db/entities/tasks/TaskStatus.ts` (new). Migration class auto-generated by `mikro-orm migration:create`. Three composite indexes on `tasks` (`tasks_org_sprint_status`, `tasks_org_parent`, GIN `tasks_custom_fields_gin`); unique partial index `tasks_org_external_id WHERE external_id IS NOT NULL`. MikroORM entity types + Zod validators exported from `src/db/entities/tasks/`.

## Acceptance criteria
- [ ] Schema migration class: `Task` entity gains all six new properties; re-running migration is no-op (MikroORM idempotency)
- [ ] Schema migration class: `TaskStatus` entity created with `category IN ('unstarted','started','completed','cancelled')` CHECK constraint and `UNIQUE(project_id, name)`
- [ ] Schema migration class: `tasks_org_sprint_status(org_id, sprint_id, status)`, `tasks_org_parent(org_id, parent_id)`, GIN `tasks_custom_fields_gin`, and `tasks_org_external_id` unique partial index all present (verified via `pg_indexes`)
- [ ] Logic: `Task` MikroORM entity carries all new properties with correct nullability; Zod validators exported from `src/db/entities/tasks/`
- [ ] Logic: `DependenciesSchema` Zod type `{blocks: string[], blocked_by: string[]}` validates default `{ blocks:[], blocked_by:[] }` shape
- [ ] Logic: `TaskStatus` MikroORM entity + `TaskStatusCategory` enum exported
- [ ] Tests: migration idempotency — apply twice via `mikro-orm migration:up`, same schema, no error
- [ ] Tests: FK cascade — `sprint` property ON DELETE SET NULL → `tasks.sprint_id` becomes null; verified via repository read-back
- [ ] Tests: `tasks_org_external_id` unique partial rejects duplicate `(org_id, external_id)` via repository insert
- [ ] Tests: `EXPLAIN` on `WHERE org_id=? AND sprint_id=? AND status=?` query uses `tasks_org_sprint_status`

## Notes / Tech-stack hints
- `dependencies` default `{ blocks: [], blocked_by: [] }` — set at entity property level via MikroORM `default`
- `externalId` format: `'jira:<key>'` | `'linear:<uuid>'` | `'github:<number>'` — validated by Zod pattern in the TS type, not at DB level
- `TaskStatus` default template seeded in slice 07 (task CRUD baseline); this slice only creates the entity + migration
- Failure gate: if PGlite WASM doesn't support GIN on jsonb, fall back to `tasks_custom_fields_btree (org_id, (custom_fields->>'status'))` as a targeted index emitted in migration body
