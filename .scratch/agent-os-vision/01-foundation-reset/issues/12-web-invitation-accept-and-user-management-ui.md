# Web invitation-accept page + admin user-management UI

## Parent
PRD: `.scratch/agent-os-vision/prds/01-foundation-reset.md`

## What to build
Two related web surfaces that complete the multi-user flow:

**Invitation accept (`src/web/src/routes/auth/invite/[token]/+page.svelte`)**
- Load: server-side validates token via `auth.acceptInvite` tRPC call (which calls `await invitationRepo.findOne({ token })` under the hood); if expired/invalid → show error page.
- Unauthenticated visitors see a "Create account" form (name + password + optional passkey enrollment); on submit creates user + accepts invite + logs in → redirect to dashboard.
- Authenticated visitors (already have a session) — invite accept skips account creation; just creates an `OrgMember` row via `em.create(OrgMember, {...}); em.persistAndFlush(...)` → redirect to dashboard.
- Always-on (tokens are generated by CLI `auth invite` and web admin UI).

**Admin user-management (`src/web/src/routes/settings/users/+page.svelte`)**
- Lists all org members via `orgs.members.list()` (which calls `orgMemberRepo.find({ org }, { populate: ['user'] })`).
- Invite by email form (calls `auth.invite`; displays generated token or sends email when `notify-email` flag on).
- Change role dropdown (calls `orgs.members.updateRole`; owner-only for promoting to admin/owner).
- Remove member button (calls `orgs.members.remove`; cannot remove last owner — guarded server-side via `orgMemberRepo.count({ org, role: 'owner' }) > 1`).
- Accessible only to `owner`/`admin` roles (route guard via `assertPermission`).

Cuts through: SvelteKit page routes → tRPC calls → repository operations → role-guard middleware → Playwright e2e tests.

## Notes
The invite-accept page is `publicProcedure`-backed for token validation (unauthenticated entry), but the account-creation step calls Better-Auth `signUp` inline (which goes through the MikroORM-backed adapter). Ensure the SvelteKit load function does not throw on invalid token — return a props object with `error` field so the page can render an error state.
