## What to build

MikroORM v7 migration class covering the `0009_repos_git` scope: additive properties on `Repo` entity and creating `RepoBranch`, `RepoCommit`, `RepoFilesIndex` entities, plus the `Task.repo` FK amendment. Entity files: `src/db/entities/repos/`. Migration class auto-generated by `mikro-orm migration:create` at `src/db/migrations/Migration<timestamp>.ts`. Every new entity carries composite `(org_id, …)` indexes per Q22. Migration must run clean on both PGlite and PostgreSQL.

## Acceptance criteria

- [ ] `Repo` entity gains: `name`, `slug`, `kind` (local|remote), `localPath`, `remoteUrl`, `defaultBranch`, `currentBranch`, `lastSyncAt`, `syncStatus` (idle|syncing|error), `lastTouchedAt`, `archived`.
- [ ] Unique index `repos_org_slug (org_id, slug)` present in `pg_indexes` after migration.
- [ ] Index `repos_org_touched (org_id, last_touched_at DESC)` present.
- [ ] Index `repos_kind_status (kind, sync_status)` present.
- [ ] `RepoBranch` entity created with all properties + UNIQUE `(repo_id, name)` + `(org_id, repo_id)` index.
- [ ] `RepoCommit` entity created with all properties + UNIQUE `(repo_id, sha)` + `(repo_id, committed_at DESC)` + `(org_id, repo_id)` indexes.
- [ ] `RepoFilesIndex` entity created with all properties + UNIQUE `(repo_id, path)` + `(org_id, repo_id, kind)` index.
- [ ] `Task` entity gains `repo` ManyToOne FK to `Repo` (nullable) + `tasks_org_repo (org_id, repo_id)` index.
- [ ] Migration class applies without error on PGlite (file-backed) and on PostgreSQL in CI.
- [ ] Migration class is reversible (down migration generated by MikroORM drops all new entities and properties).
- [ ] Unit test asserts each index name exists in `pg_indexes` after `mikro-orm migration:up`.
