## What to build

Gated `connector-gitlab` adapter (`FULCRUM_FEATURES=connector-gitlab`). Same pattern as `connector-github` but targeting GitLab API v4 via `@gitbeaker/rest`. Pulls merge requests and issues into `gitlab_mrs` and `gitlab_issues` tables (migration `0009c_gitlab`). PAT or OAuth token in `org_settings`. Failure gate: if `@gitbeaker/rest` is unmaintained → raw `xh` under thin adapter.

## Acceptance criteria

- [ ] Migration class covering `0009c_gitlab` scope: `GitlabMr` entity + `GitlabIssue` entity — same property shape as GitHub equivalents but `mrIid` / `issueIid` instead of `number`. `@Entity` classes at `src/db/entities/repos/`; migration class auto-generated by `mikro-orm migration:create`.
- [ ] `OrgSettings` gains `gitlab_pat text` and `gitlab_oauth_token text`.
- [ ] Graphile-worker task `connector.gitlab.sync`: fetches open MRs + issues for one repo; handles 429.
- [ ] Daily cron enqueues sync for every `kind='remote'` repo with `remote_url` matching `gitlab.com` or a user-configured self-hosted GitLab host.
- [ ] Flag OFF: zero `@gitbeaker` calls; no table writes.
- [ ] Integration test with mock GitLab API server; flag ON → rows populated.
- [ ] CLI: `fulcrum repo gitlab-mrs <id> [--json]` (gated).
- [ ] Web: `/repos/<id>` dashboard shows "Merge Requests" section (gated).
- [ ] TUI: parity with GitHub connector display (MR count in status bar when ON).
