## What to build

Gated `connector-github` adapter (`FULCRUM_FEATURES=connector-github`). One-way pull of GitHub metadata (PRs, issues, releases, workflow runs, check-runs) via `@octokit/rest` into `github_prs` and `github_issues` tables (migration `0009b_github`). OAuth token stored in `org_settings`. Daily graphile-worker cron syncs open PRs and issues for all GitHub-remote repos. Failure gate: if GitHub changes OAuth flow → fall back to raw `xh` calls under a thin adapter.

- [x] Flag ON: `github_prs` populated after sync; Playwright/integration test with mock Octokit server.

## Implementation notes

Adapted to existing product-kernel architecture (raw SQL + PGlite, no ORM, no tRPC). Migration `0004_github_connector.sql` instead of `0009b_github` (follows sequential numbering). Uses pluggable `GithubClient` interface for testability — mock client in tests, Octokit-based client with 429 backoff for production. `@octokit/rest` is an optional peer dependency (lazy dynamic import with `@ts-expect-error`). CLI, Web, and TUI acceptance criteria deferred — depend on surfaces not yet built (tRPC, CLI repo subcommand, web dashboard, TUI pane).
