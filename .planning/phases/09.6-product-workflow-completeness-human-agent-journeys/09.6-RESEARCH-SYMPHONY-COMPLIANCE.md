## Scope

Fulcrum must satisfy Symphony in two directions:

1. **Symphony implementer:** Fulcrum implements the Symphony service specification: workflow loader, config, tracker adapter, orchestrator, workspace manager, Codex app-server runner, logs/status/API, safety, conformance tests.
2. **Symphony project/context provider:** Fulcrum is also the product that supplies project/task/doc/repo/memory/context/artifact relationships into Symphony prompts, workspaces, traces, and agent outputs. A Symphony run started from Fulcrum must be reconstructable as a project workflow, not just a scheduler attempt.

Phase 9.6 cannot claim product completion until both directions are verified.

| Provider need | Fulcrum product entity | Required linkage |

## Required Trace Model

Every Symphony-backed agent run must have a trace graph:

```text
workspace/org
  -> project
    -> repo/local_path
    -> task/work item
      -> strict Symphony issue snapshot
      -> workflow runtime snapshot
        -> WORKFLOW.md source path + hash + parsed config + prompt hash
      -> context bundle
        -> docs included/excluded
        -> memories included/excluded
        -> artifacts included/excluded
        -> repo files included/excluded
        -> prior runs included/excluded
      -> routing decision
        -> agent profile + model + Codex command + sandbox/approval posture
      -> run attempt
        -> orchestration state
        -> attempt lifecycle state
        -> workspace root/key/path
        -> hooks lifecycle
        -> app-server process/session
          -> thread_id
          -> turn_id(s)
          -> session_id(s)
          -> protocol events
          -> token/rate-limit updates
          -> approval/user-input/tool-call events
        -> transcript/diff/artifacts
        -> memory candidates/follow-up tasks/doc updates
        -> audit/notifications
```

## Web/TUI/CLI Required Trace Surfaces

Web run detail:

- Overview: project, task, issue identifier, strict issue snapshot, orchestration state, attempt lifecycle, terminal reason.
- Workflow tab: `WORKFLOW.md` path, config, prompt hash/body preview, reload history, validation errors.
- Context tab: exact included/excluded docs/memory/artifacts/repo files/prior runs with source IDs and why selected.
- Workspace tab: root, key, path, repo path, hook execution, path safety status.
- Session tab: Codex command, protocol version/schema evidence, thread/turn IDs, session IDs, PID, heartbeat, events, tokens, rate limits.
- Output tab: transcript, tool calls, unsupported tool failures, approvals/user-input decisions, diff, artifacts.
- Recovery tab: retry queue, continuation retry, backoff, reconciliation, stall detection, cleanup decisions.

CLI:

- `fulcrum symphony spec status --json`
- `fulcrum symphony conformance --json`
- `fulcrum runs trace <runId> --json`
- `fulcrum runs workflow <runId> --json`
- `fulcrum runs context <runId> --json`
- `fulcrum runs session <runId> --json`
- `fulcrum runs retry-queue --project <slug> --json`

TUI:

- Run supervision detail pane must expose workflow/context/workspace/session/output/recovery tabs.
- Status bar must show workflow reload errors, active runs, retry queue count, and doctor/Symphony conformance state.

## Gaps That Phase 9.6 Must Target

1. `linear-tracker.ts` is ingest-only; full upstream Linear-compatible dispatch conformance requires real `fetch_candidate_issues`, `fetch_issues_by_states`, and `fetch_issue_states_by_ids` semantics for Linear project `slugId`, pagination, blockers, labels, GraphQL ID typing, and error mapping.
2. Fulcrum-native task tracker can be a provider extension, but must still produce strict Symphony issue snapshots and document non-Linear behavior.
3. Current `WorkflowConfigSchema` is narrower than upstream front matter; either expand it or document an adapter that preserves upstream keys.
4. Product run surfaces do not yet expose full §4.1.6 live session metadata, §13 snapshot shape, or §10 approval/user-input/tool-call decisions.
5. Context bundle linkage is not yet detailed enough: prompt input must be strict Symphony `issue`/`attempt`, while Fulcrum-specific docs/memory/artifacts/repo context must be a documented extension with trace/provenance.
6. Conformance trace maps §18.1 summary items, but Phase 9.6 needs §17 bullet-level tests plus extension tests for HTTP server and any client-side tools shipped.
7. "Symphony as project/context provider" is not represented in current conformance docs; add tests that a Fulcrum project task dispatch creates a complete trace graph.
