# Phase 9.6 Review: Product Completeness Blocking Findings

**Created:** 2026-05-08
**Mode:** CE-style product, architecture, agent-native, and verification review
**Verdict:** Block Phase 10. Existing Phase 9.6 scope is necessary and must execute as vertical journeys.

## Findings

### P0: Completion criteria were unit/surface based, not journey based

Evidence:

- User UAT reports web, TUI, CLI, and likely server behavior as disconnected CRUD.
- Phase 9.5 has many completion artifacts, but Phase 9.6 feedback shows no successful project-to-ship or task-to-agent-run-to-artifact-to-memory journey.

Required correction:

- Phase completion proof must cite H1-H6 and A1-A5 journey tests, not only route render tests, unit tests, or per-surface CRUD assertions.

### P0: Product hierarchy is not enforced enough

Evidence:

- Global and project routes coexist for boards, docs, runs, artifacts, repos, memory, and context.
- `apps/web/src/routes/+layout.svelte` still risks flat domain navigation despite `apps/web/src/lib/components/app/nav-data.ts`.

Required correction:

- Project context becomes default. Global views must be explicit portfolio/all-project views with filters.
- Work item detail becomes the relationship hub for docs, runs, repo, artifacts, memory, dependencies, comments, activity, and automations.

### P0: Local startup and doctor issues invalidate readiness claims

Evidence:

- `feature_flags` migration drift, `orgs` missing, `MIKRO_ORM_ALLOW_GLOBAL_CONTEXT=1` workaround, stale memory schema doctor, and `product init --json` schema mismatch.

Required correction:

- Start Phase 9.6 with Workstream 0. No UI completeness claim before fresh and existing local state gates pass.

### P1: CLI/TUI parity must be workflow parity, not command/screen count parity

Evidence:

- User could only perceive TUI list navigation.
- CLI has many command families, but no proof of connected project create -> repo link -> task -> doc -> run -> artifact -> memory workflow.

Required correction:

- Add workflow commands/flows and tests that verify the same IDs and relations across Web, CLI JSON, and TUI screens.

### P1: Agent-native journey is underspecified unless dispatch starts from work

Evidence:

- Runs exist as global/project surfaces, but agent run value depends on task/repo/context/doc/artifact/memory provenance.

Required correction:

- Primary run creation path is task -> context preview -> route/profile -> dispatch -> supervise -> artifact/memory/follow-up acceptance.

## Review Gates

- Do not start Phase 10 until `09.6-CLOSURE-PROOF.md` exists and cites H1-H6/A1-A5 evidence.
- Do not accept isolated route screenshots as proof.
- Do not accept global CRUD pages without project-scoped relationship panels.
- Do not accept CLI/TUI parity by command/screen inventory; require same workflow data and entity IDs.
- Do not accept doctor warnings as known issues; fix or make repair command actionable.
