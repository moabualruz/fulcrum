<objective>
Implement project-first hierarchy and setup. Web, CLI, and TUI must create/select workspace/project/subproject scope, link a local repo path during setup, apply the built-in Agent OS Software Project template, and show the same project/repo/workflow IDs.
</objective>

<decision_coverage>
D-01, D-02, D-03, D-04, D-05, D-06, D-07, D-08, D-09, D-10, D-11, D-12, D-13, D-14, D-33, D-34, D-40, D-41, D-44, D-48, D-51, D-57, D-58.
</decision_coverage>

<technical_decisions>
- Represent hierarchy as one projects tree with `parent_id`, `kind`, `path`, `depth`, and inherited module policy.
- Add project policy services for repo/docs/memory/automations/reports/run policy/context source inheritance. Parent locks win; otherwise child override wins.
- Build `src/application/templates/**` before hardcoding setup. Built-in template compiles to same normalized schema as local `FULCRUM_TEMPLATE.md` and `fulcrum-template.yaml`.
- Web setup preview can remove modules before creation. Executable template effects are dry-run by default unless trust policy allows.
- Match Jira/Linear/Plane for project hierarchy/work setup; match local-first repo path behavior from developer tools, not SaaS-only onboarding.
</technical_decisions>

<threat_model>
Threats:
- Template executable hooks/scripts run without trust. Mitigation: Manual/Assisted default, dry-run preview, signed/trusted source marker, audit event.
- Path traversal or unsafe repo path. Mitigation: normalize local paths, reject inaccessible/non-directory paths, record workspace root safely.
- Parent policy silently weakens child controls. Mitigation: effective policy endpoint shows inherited, overridden, locked source.
- All projects confusion. Mitigation: explicit `All projects` context only, no silent global fallback.
</threat_model>
