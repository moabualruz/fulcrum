# Phase 09.6 Pattern Map

**Created:** 2026-05-08
**Purpose:** Codebase-specific implementation map for the detailed Phase 9.6 plans.

## Architecture Rules To Preserve

- Web, CLI, and TUI are invocation and visualization layers only.
- Product behavior lives in `src/application/**`, `src/orchestration/**`, and server routers that call application services.
- Persistence goes through MikroORM/PGlite/PostgreSQL-compatible services, not surface-local stores.
- Every user-visible or agent-visible entity returns typed `links`, typed `trace`, and audit/causation ids.
- Local CI source of truth remains `bun run ci`.

## Integration Spine

Implementation must make this graph reachable through application services and every client:

```text
workspace -> project tree -> repo/local path -> work item -> docs/context
  -> routing decision -> run/live session -> artifacts/memory/follow-ups
  -> automation/audit/notifications/reports
```

Required trace fields where applicable:

- `workspace`
- `project`
- `parentProject`
- `subproject`
- `repo`
- `workItem`
- `doc`
- `contextBundle`
- `routingDecision`
- `run`
- `liveSession`
- `artifact`
- `memory`
- `automation`
- `audit`

## Event Producer/Consumer Contract

| Event | Producers | Consumers |
|---|---|---|
| `project.created` | Web setup, CLI `projects create`, TUI setup | repo linker, template applier, docs initializer, board initializer, audit |
| `repo.linked` | setup flow, CLI/TUI repo commands | doctor, context index, dashboard, Symphony worker |
| `work.created` | board/list/import/CLI/TUI/template | board/list/table/calendar/Gantt, task detail, docs linker, reports |
| `doc.linked` | doc editor, task detail, run detail, CLI/TUI | backlinks, context builder, search, audit |
| `context.bundle.created` | context preview, run dispatch, automation | routing, run attempt, audit, token report |
| `routing.selected` | route engine, human override, trusted automation | run attempt, audit, reports |
| `run.started` | Web dispatch, CLI, TUI, automation | live screens, notifications, audit, reports |
| `run.event.received` | app-server client, Symphony runtime | timeline, transcript, approvals, token accounting |
| `artifact.created` | run harvester, doc export, user upload | artifact list, task/run detail, search, memory candidate extractor |
| `memory.candidate.created` | run completion, doc promotion, manual capture | memory review, context selector, notifications |
| `task.status.updated` | human, automation, accepted run proposal | board/reports, audit, notifications |

## Dependency Decisions

- Reuse `svelte@^5.55.2` and local Svelte UI primitives.
- Reuse existing command palette components; replace command generation only.
- Reuse TipTap/Yjs for docs.
- Reuse OpenTUI and FakeTTY tests for TUI.
- Reuse `json-rules-engine@7.3.1` for automation.
- Reuse Symphony/Fulcrum orchestration; do not add Temporal/LangGraph/LangSmith runtime.
- Add `@tanstack/table-core` or `@tanstack/svelte-table` only if existing task tables cannot support saved-view-grade sorting/filtering/grouping.
- Add `@thisux/sveltednd` only if current board drag/drop blocks reliable Kanban behavior.
- Add `wx-svelte-gantt` or `svelte-gantt` only if current Gantt cannot support dependencies/tree/zoom at required quality.
