<objective>
Make work items the central product object. Task detail becomes a relationship hub with Planning, Docs, Repo/Workspace, Agent Run, Knowledge, and Audit/Activity modes. Board/list/table/calendar/Gantt/report views share one scoped work query and preserve project trace.
</objective>

<decision_coverage>
D-01, D-02, D-05, D-15, D-16, D-17, D-18, D-19, D-20, D-22, D-42, D-44, D-47, D-48, D-50, D-51, D-53, D-54.
</decision_coverage>

<technical_decisions>
- Use `Work item` as common type with built-ins Initiative, Epic, Story, Task, Subtask, Bug, Chore.
- Cycles and modules are built-in grouping dimensions; templates/projects can add dimensions.
- Task modes are generated views over real linked records; docs/runs/artifacts/memory remain individual addressable entities.
- Reuse current board/list/table/calendar/Gantt components first. Add `@tanstack/table-core`, `@thisux/sveltednd`, or Gantt package only if current code cannot satisfy saved-view-grade behavior.
- Match Jira/Linear/Plane patterns: issue detail right rail/relationship panels, cycles/modules, project board/list/table/report parity.
</technical_decisions>

<threat_model>
Threats:
- Work item mutations target parent when user intended child. Mitigation: visible target scope before commit and audit records actual child project.
- Automation or view drag/drop creates orphan/invalid hierarchy. Mitigation: service validates allowed parent/child rules and project id.
- CLI/TUI bypass relationship hub. Mitigation: shared `work inspect`/TUI detail payload from same application query.
</threat_model>

<tasks>
1. Extend work item service.
   - Files: `src/application/tasks/**`.
   - Action: configurable type metadata, hierarchy rules, cycle/module grouping, dependency edges, project scope enforcement.
   - Verify: tests for invalid parent type, cross-project link rejection unless explicit relation type allows, child override policy.
   - Acceptance: service can model project -> epic -> story/task -> subtask and custom type definitions.

2. Expand task detail aggregate.
   - Files: `src/application/tasks/task-detail.ts`, query modules listed in frontmatter.
   - Action: return hierarchy, dependencies, docs, repo/branch/files, runs, artifacts, memory, context bundles, comments, watchers, automations, audit.
   - Verify: task detail tests assert typed `links`, typed `trace`, counts, empty states.
   - Acceptance: no task detail payload is task-only.

3. Implement task modes.

   - Verify: Web component tests or Playwright assertions for each mode.
   - Acceptance: missing relationships show actionable empty state.

4. Unify work views.
   - Files: `src/application/saved-views/**`, `src/application/reports/**`, Web board/list/table/calendar/Gantt/report components.

   - Acceptance: all views show same task IDs and scope.
