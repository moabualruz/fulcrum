<technical_decisions>
- Create shared trace/link contracts in `src/application/trace/**` and `src/application/relationships/**`, backed by Zod schemas, instead of repeating untyped `links` blobs in Web/CLI/TUI.
- Add no-orphan checks at service boundaries and doctor level. Generated CRUD cannot create tasks/docs/runs/artifacts/memory without project/workflow linkage.
- Treat `FULCRUM_HOME` bootstrap, DB init, migrations, memory schema, product init, and web/server DB init as one local readiness chain.
- Doctor output must distinguish `pass`, `repairable`, and `reset-required`; reset must be explicit CLI command, not hidden env workaround.
- Preserve Symphony strict snapshot and SPEC lock while adding product graph trace around it.
</technical_decisions>

<threat_model>
Assets: local repo paths, local DB, memory, artifacts, audit, app-server session metadata, reset command.

Threats:
- Accidental destructive reset of user data. Mitigation: reset command must require explicit flag/confirmation and print target `FULCRUM_HOME`.
- Orphan data that later pollutes context. Mitigation: relationship service validation plus doctor no-orphan scan.
- Secret leakage in doctor/logs/audit. Mitigation: redact env values, local paths only where operationally needed, no prompt bodies in default doctor output.
- Bypassing policy via direct ORM use from clients. Mitigation: Web/CLI/TUI tests and static interface parity checks.

Blocking severity: high.
</threat_model>
