## Sequencing

1. Workstream 0 first; no UX work is valid if local startup is broken.
2. Workstreams 1 and 2 next; project context underpins every journey.
3. Workstreams 3 and 4 in parallel only if file ownership is split cleanly.
4. Workstream 5 after task/doc/project context is stable.
5. Workstream 6 after events from workstream 3/5 exist.
6. Workstream 7 throughout, final gate last.

## Risk Controls

- No completion claim from route count, test count, or unit pass alone.
- Every feature-bearing change must update relationship graph and journey tests.
- All surfaces must use same application commands/queries.
- Any failing doctor/startup issue blocks merge.
