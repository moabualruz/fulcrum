# Phase 9.6 Feedback Capture: Product Workflow Completeness

**Captured:** 2026-05-08
**Source:** User UAT after local server, web, CLI, and TUI demo run
**Status:** Blocking. Phase 10 must not start until this is resolved.

## Core Feedback

Fulcrum currently presents many isolated feature surfaces, but it does not behave like one integrated product. Individual units may be partially implemented, but full human and agent journeys do not hold together.

The web app is especially far from the intended product:

- No coherent hierarchy across workspace, project, board, docs, repos, memory, agent runs, context, artifacts, and automation.
- Project management does not feel like Jira, Linear, Plane, or GitHub Projects. Boards and tasks are not clearly anchored to projects, there is no reliable project selector in primary work areas, and project setup does not make local repository paths first-class.
- Documentation does not feel like Confluence or GitHub Wikis. Docs are not strongly organized around project/workspace knowledge, decisions, linked work, context, and agent output.
- Memory, orchestration, context, artifacts, and runs feel bolted on instead of integrated into task/project/doc workflows.
- Navigation and pages feel like unrelated CRUD screens rather than a workflow product.
- Prior completion claims were wrong because they verified files, routes, tests, and small units, not complete user journeys or agent journeys.

TUI and CLI likely have the same problem:

- TUI appears to be only list navigation at first use.
- CLI/TUI must be on par with web for data and actions, not merely expose disconnected commands/screens.
- Server logic must be reviewed for the same "big blob of disconnected capabilities" failure mode.

Startup/doctor issues are also blockers:

- Default local DB migration failed with `relation "feature_flags" already exists`.
- `fulcrum web` failed without `MIKRO_ORM_ALLOW_GLOBAL_CONTEXT=1`.
- Packaged web logged `relation "orgs" does not exist` during web DB init.
- `doctor --json` reported `memoryEngine.memories_schema` error: missing columns `scope`, `key`.
- `product init --json` failed with `column "kind" does not exist`.

## Required Outcome

Phase 9.6 must define and implement full product journeys before Phase 10:

- One human workflow and UX spec.
- One agent workflow and UX spec.
- Verification gates based on end-to-end journeys, not isolated route/unit completion.
- Web, CLI, TUI, server, docs, memory, orchestration, context, artifacts, and automation integrated into one product model.
- Notes and doctor/startup issues fixed, not documented as acceptable.

## Non-Negotiable Acceptance Principle

No Phase 10 work until a user can complete the critical human and agent journeys locally through Web, CLI, and TUI using the same data model and seeing the same relationships.
