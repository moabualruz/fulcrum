# Phase 09.6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-phase and verified inline against context/research.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | local Svelte 5 + shadcn-svelte/Bits-style primitives |
| Preset | operational console |
| Component library | existing local components under `apps/web/src/lib/components/ui/**`; do not add large UI kit |
| Icon library | existing app icon pattern; use lucide where app already uses it |
| Font | existing app/system sans stack; no new webfont required |

**Product feel:** local-first project operations console. Default mode is minimal/balanced with progressive disclosure. Advanced mode exposes dense operational panes, compact tables, relationship rails, and full trace views. Same data/actions exist in both modes.

**Do not build:** marketing hero, landing page, decorative gradient/orb backgrounds, isolated domain CRUD screens, card-heavy overview with no trace spine, global nav that hides active project.

---

## Information Architecture Contract

### Primary Hierarchy

```text
Workspace
  -> Project hierarchy
    -> Parent project
      -> Subproject
        -> Work item/task
          -> Docs / Repo / Context / Agent run / Artifact / Memory / Audit
```

### Topbar

Required left-to-right structure:

1. Project picker with full hierarchy tree.
2. Breadcrumb: workspace/root -> parent project -> subproject -> current entity.
3. Scope indicator: current project/subproject or explicit `All projects`.
4. Search/Cmd-K entry scoped to current scope with visible override.
5. Run/notification/doctor health indicators.
6. Density mode switch: Default / Advanced.

### Sidebar

Sidebar shows compact current scope, child shortcuts, and contextual sections. It must not become a giant portfolio tree.

Required groups:

```text
Current Scope
  Dashboard
  Work
    Triage
    Backlog
    Board
    List
    Table
    Calendar
    Gantt
    Reports
  Docs
  Runs
  Artifacts
  Memory
  Context
  Automations
  Repos
  Settings

Portfolio
  Projects
  All work
  All runs
  All artifacts
  Search

System
  Doctor
  Audit
  Agents
  Routing
  Templates
```

Global pages are explicit `All projects` portfolio views. No hidden fallback from project routes to global queries.

## Screen Contracts

### Project Setup

Flow:

1. Project identity: name, slug, description, type.
2. Template preview: `Agent OS Software Project`, module list, docs/tasks/scripts/hooks, trust mode, dry-run effects.
3. Hierarchy and inheritance: parent/subproject, inherited vs overridden modules.
4. Local repo path: path input, validate action, branch/remotes/status.
5. Initial docs/work: full doc template set and default epic/task.
6. Finish to project dashboard.

Required empty/validation states:

- Missing repo path: show `No local repo linked` with action `Link local repo`.
- Invalid repo path: show path-specific problem and `Choose another path`.
- Executable template effects: show dry-run table before apply.
- Trust escalation: show Manual/Assisted/Trusted/Full auto explanation and audit impact.

### Project Dashboard

Default mode panels:

- Project identity and scope.
- Repo path/branch/status.
- Current work summary.
- Active runs and blocked runs.
- Docs status.
- Artifacts and memory candidates.
- Automation/audit alerts.
- Report summary.
- Next actions.

Advanced mode adds:

- Parent/child drill-down table.
- Relationship rail.
- Trace spine panel.
- Inline bulk actions with target scope selector.
- Dense report cards.

Parent project dashboard can operate on child work. Every create/mutate action shows target child scope before commit.

### Task Detail Modes

Tabs/modes:

1. Planning
2. Docs
3. Repo/Workspace
4. Agent Run
5. Knowledge
6. Audit/Activity

Always visible:

- Task title/type/status/priority.
- Project/subproject scope.
- Parent/child/dependency counts.
- Linked docs/runs/artifacts/memory/audit counts.
- Trace action.
- Start run/context preview action.

Modes are generated views over real records. Linked docs, runs, artifacts, memory, and audit entries remain directly addressable.

### Docs Space

Required:

- Project docs tree.
- Templates: Spec, ADR, PRD, runbook, meeting note, retro, agent prompt, handoff, incident, release note, decision log.
- Backlinks panel.
- Linked work panel.
- Version/history panel.
- Section actions: create task, create memory candidate, start run with section context, link artifact.

### Run Detail

Default review mode:

- Run status, summary, current step.
- Project/task/repo/context links.
- Approvals/user input.
- Outputs, artifacts, memory candidates, follow-up proposals.
- Retry/cancel/continue actions.

Advanced trace mode tabs:

- Overview
- Workflow
- Context
- Workspace
- Session
- Output
- Recovery
- Audit

Advanced trace must expose strict Symphony issue snapshot, workflow runtime snapshot, workspace root/key/path, live session thread/turn/session, app-server events, approvals/tool calls, token/rate-limit updates, retry/reconciliation, artifacts, memory candidates, audit.

### Search

Default scope: current project/subproject.

Required global trigger:

- Web: visible `All projects` toggle.
- CLI/API: explicit `--scope all` or equivalent.
- TUI: scope selector.

Every result row shows kind, title, project/subproject, source entity, last activity, match reason, and trace link.

### TUI

First screen:

- Resume last context.
- Fallback active project workbench.
- Workspace portfolio available via navigation.

Layout:

```text
Top/status: workspace | project/subproject | repo health | doctor | run state
Left: work queue / nav
Center: current workflow surface
Right: relationship/trace pane
Bottom: key hints and mode
```

Required keys:

- `p` switch project
- `g` dashboard
- `b` board
- `l` list
- `d` docs
- `r` runs
- `c` context
- `m` memory
- `a` artifacts
- `/` search/filter
- `k` or `Ctrl-K` palette
- `n` create contextual entity
- `Enter` open
- `Space` select/bulk
- `x` cancel/close/reject
- `R` retry run
- `A` approve gated action

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, status dot gaps, table cell inner gaps |
| sm | 8px | Compact element spacing, button/icon gap, mode tab gap |
| md | 16px | Default panel padding, form field stack spacing |
| lg | 24px | Page section padding, dashboard panel gaps |
| xl | 32px | Major layout columns and project setup step gaps |
| 2xl | 48px | Major section breaks in default mode only |
| 3xl | 64px | Rare setup/onboarding page vertical breaks only |

Exceptions: none. Advanced mode may reduce panel padding to `sm`/`md`, but values remain multiples of 4.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.45 |
| Label | 12px | 500 | 1.35 |
| Heading | 20px | 600 | 1.25 |
| Display | 28px | 650 | 1.15 |
| Table cell | 13px | 400 | 1.35 |
| Status/meta | 12px | 400 | 1.3 |
| Code/IDs | 12px | 500 monospace | 1.35 |

Rules:

- No viewport-scaled font sizes.
- Letter spacing is `0`.
- Dense tables use 13px cells but preserve readable line height.
- Buttons and compact controls must not truncate critical verbs or IDs; wrap or use tooltip for secondary detail.

## Color

Use existing app CSS variables where present. Do not introduce a one-hue palette.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Existing neutral background token (`--background`) | App background |
| Secondary (30%) | Existing card/sidebar muted tokens (`--card`, `--muted`) | Panels, sidebar, topbar, table header |
| Accent (10%) | Existing primary/accent token (`--primary`) | Active scope, selected tab, primary CTA, focus ring |
| Success | Existing success/green token or `#16a34a` | Passing checks, completed runs, accepted memory |
| Warning | Existing warning/amber token or `#d97706` | Stale context, inherited override warnings, retry queued |
| Destructive | Existing destructive token or `#dc2626` | Delete/reset/rebuild/destructive actions only |

Accent reserved for: active project/scope, selected navigation item, primary CTA, focus indicators, active run state. Never use accent for all interactive elements.

Status cannot rely on color alone; pair color with text/icon/state label.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Create project` |
| Project setup repo CTA | `Link local repo` |
| Template dry-run CTA | `Preview template` |
| Run CTA | `Preview context` before `Start run` |
| Empty project heading | `No work in this project yet` |
| Empty project body | `Create a task, link a repo, or apply a template to start the project workflow.` |
| Empty docs heading | `No project docs yet` |
| Empty docs body | `Create a spec, ADR, runbook, or handoff from a template.` |
| Empty runs heading | `No runs for this work item` |
| Empty runs body | `Preview context before starting an agent run from this task.` |
| Error state | `{problem}. {specific repair action}.` |
| Destructive confirmation | `{Action name}: this changes local project state. Review dry-run output before continuing.` |
| Full auto confirmation | `Full auto can run approved actions without stopping. Enable only for trusted project workflows.` |

Rules:

- Use product nouns consistently: Workspace, Project, Subproject, Work item, Task, Run, Trace, Template, Context bundle, Artifact, Memory candidate, Automation, Audit event.
- Do not explain UI features in body copy when controls are self-evident.
- Error states must include repair path, not blame.

## Interaction Contracts

### Scope And Hierarchy

- Every work surface shows current project/subproject or `All projects`.
- Parent aggregate actions show target scope selector before commit.
- Inherited/overridden/locked module state is visible in settings, template preview, CLI JSON, and TUI detail.

### Trust And Safety

Trust labels:

- Manual
- Assisted
- Trusted
- Full auto

Always gate:

- destructive actions
- executable template/scripts/hooks/shell/network actions
- authority escalation

Authority escalation includes Full auto enablement, project policy loosening, agent admin permissions, and template trust changes.

### Density

- Default mode: minimal/balanced, progressive disclosure.
- Advanced mode: dense operational console.
- Presentation mode does not change permissions, available actions, or data.

## Registry Safety

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn/local UI primitives | buttons, tabs, dialogs, menus, tables, command, badges, inputs, forms | Use existing local components; no registry fetch required |
| lucide/icons if already configured | project, repo, run, trace, docs, memory, artifact, alert, audit icons | Use package already present or existing icon pattern; no custom SVG unless required |
| `@thisux/sveltednd` | Kanban drag/drop only if existing board DnD blocks quality | Add only after audit; keep local board design |
| TanStack Table | Saved-view-grade table if current table lacks required grouping/sorting/columns | Add only if planner verifies current table insufficient |
| Svelte Gantt package | Dependency/critical path Gantt if current component insufficient | Add only after audit |
