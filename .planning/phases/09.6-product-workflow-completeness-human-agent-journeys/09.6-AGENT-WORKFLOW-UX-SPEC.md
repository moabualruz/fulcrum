# Phase 9.6 Agent Workflow and UX Spec

**Created:** 2026-05-08
**Audience:** Agent operator and agents acting inside Fulcrum.

## Agent Product Model

Agent runs are not standalone logs. They are workflow executions attached to project work.

Required relationship graph:

```text
Agent profile
  -> Routing rule / workflow config
  -> Project
  -> Task / issue
  -> Context bundle
  -> Run attempt
  -> Trace / transcript / tool calls
  -> Workspace diff
  -> Artifacts
  -> Memory candidates
  -> Follow-up tasks / docs / decisions
  -> Audit + notifications
```

## Agent Journey A1: Dispatch From a Task

Goal: start an agent run from a real work item.

Required steps:

1. Human or automation selects project task.
2. Fulcrum assembles context from task, linked docs, repo state, recent runs, memory, artifacts, and skill prompts.
3. Operator previews context bundle.
4. Routing chooses agent/profile/model or asks for confirmation.
5. Run starts with explicit project/task/repo/workspace path.

Acceptance:

- `agent_runs` row has project, task, repo/workspace, profile, context bundle, status, attempt, and actor.
- Web, CLI, and TUI all show the same dispatch options and context preview.
- Dispatch from a task is the primary run path; global run creation is advanced/secondary.

## Agent Journey A2: Supervise Execution

Goal: observe and intervene in an active run.

Required steps:

1. View active run in project and global run views.
2. See lifecycle state, transcript, tool events, current step, elapsed time, last heartbeat, and retry policy.
3. Cancel, retry, continue, or approve gated action.
4. Receive notification on blocked, failed, succeeded, artifact-created, memory-candidate events.

Acceptance:

- Web run detail shows trace timeline, transcript, diff, artifacts, memory candidates, context bundle, and audit events.
- CLI supports `fulcrum runs watch <id>`, `cancel`, `retry`, `continue`, `artifacts list`, `context show`.
- TUI run screen supports live supervision, key actions, and detail panes.

## Agent Journey A3: Produce Artifacts and Diffs

Goal: make agent output inspectable and reusable.

Required steps:

1. Agent creates or modifies files.
2. Fulcrum captures workspace diff.
3. Fulcrum harvests artifacts.
4. Artifacts link to run, task, project, repo commit/path, and search index.
5. Human accepts, rejects, archives, downloads, or promotes artifacts into docs/memory.

Acceptance:

- Artifact detail shows source run, task, project, file path, MIME/kind, checksum, retention, preview, and linked docs/memory.
- CLI/TUI can inspect/download/archive artifacts.
- Search returns artifacts with project/task/run context.

## Agent Journey A4: Convert Output Into Knowledge

Goal: capture useful decisions and facts without polluting memory.

Required steps:

1. Run completes with transcript and artifacts.
2. Fulcrum extracts memory candidates with source refs.
3. Human reviews candidates.
4. Accepted candidates become project or global memory.
5. Future context bundles cite those memory entries and source runs/docs.

Acceptance:

- Memory candidate UI exists in run detail and project memory view.
- Memory entries include scope, key/topic, source kind/id, confidence, created by, and last used.
- Doctor memory schema check passes on fresh and migrated DB.
- CLI/TUI support list/review/promote/demote memory candidates.

## Agent Journey A5: Close the Loop

Goal: agent work updates the product graph.

Required steps:

1. Run result proposes task status update, follow-up tasks, doc updates, and automation outcomes.
2. Human accepts or edits proposed changes.
3. Fulcrum records audit events and notifications.
4. Project dashboard reflects updated status.

Acceptance:

- A succeeded run can update task status only through explicit accepted action or configured automation.
- Follow-up tasks link back to source run.
- Doc updates link to run and task.
- Audit differentiates agent, human, automation, and system actors.

## Agent UX Completion Gate

End-to-end tests must start from a task, dispatch a no-sandbox local run, capture a trace/artifact/memory candidate, verify relationships in web, verify JSON via CLI, and inspect same run in TUI.
