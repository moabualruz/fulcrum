<objective>
Center agent runs on work. Dispatch flows task -> context preview -> routing decision -> Symphony-compatible run -> live session -> artifacts/memory/follow-ups -> audit. Run detail becomes full observability across Web, CLI, TUI, and API.
</objective>

<technical_decisions>
- Reuse Fulcrum Symphony internal orchestration and Codex app-server adapter. Do not add LangGraph, Temporal, LangSmith, or OpenAI Agents SDK as runtime.
- Model run UI after LangSmith trace detail and Temporal workflow visibility: overview, workflow, context, workspace, session, output, recovery, audit.
- Effective agent permissions = intersection of agent profile, workflow/template defaults, project policy, and task/run overrides; explicit user override required to loosen.
- Approval gates are workflow/profile-defined and project-overridable; default loose but visible.
- Persist app-server thread/turn/session/PID/events/token/tool/approval data into product trace, not logs only.
</technical_decisions>

<threat_model>
Threats:
- Agent mutates project/docs/memory without authority. Mitigation: effective permission service and audit before action.
- Destructive/executable/authority escalation action bypasses approval. Mitigation: hard gates for destructive, executable, network, shell, Full auto, project policy loosening, template trust changes.
- Symphony trace diverges from product trace. Mitigation: strict snapshot id and runtime state linked to Fulcrum run id.
- Transcript/tool output leaks secrets. Mitigation: redaction in default views and CLI JSON, raw output explicit.
</threat_model>
