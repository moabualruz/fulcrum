Findings:

- `+layout.svelte` still defines `paletteItems` inline as global domain links. This bypasses `nav-data.ts` and makes Cmd-K global CRUD navigation rather than workflow action.
- `nav-data.ts` groups nav into Work/Agent OS/System/Settings but still presents domains rather than active project workflow areas.
- Active project exists but is not the product shell’s dominant organizing concept.
- Task detail application payload currently returns task, subtasks, edges, and events. It does not explicitly return relationship panels for docs, runs, artifacts, memory, repo/branch, comments, watchers, automation, dependencies, search hits, or context bundle history.
- Web component inventory has many strong pieces: board, saved views, docs tree, reports, command palette, project picker, run tables, artifacts filters, search. The issue is integration and hierarchy, not absence of widgets.

  System

Rules:

- Work pages under current project by default.
- Global pages must show explicit `All projects` mode and project filter.
- No hidden fallback from project route to global query.
- Command palette actions must include current project in payload by default.

## Project Dashboard Target

Project dashboard must be the first meaningful work screen after selecting/creating a project.

Required panels:

- Project identity: name, slug, status, owner, local repo path, remote connector, branch, sync health.
- Current work: active sprint/cycle, backlog count, blocked count, WIP count, due soon, untriaged.
- Board preview: columns with count and top cards.
- Docs preview: project docs tree root, recent specs/ADRs/runbooks/handoffs.
- Agent runs: active/blocked/recent runs with task links.
- Artifacts: recent generated artifacts with source run/task.
- Memory/context: recent promoted memories and next context gaps.
- Automation: enabled project rules and recent triggered events.
- Reports: mini burndown/CFD/cycle time/throughput.
- Next actions: create task, link repo, create doc, start run, triage inbox, review memory candidates.

## Project Setup Target

Project creation must include local repository path as a first-class step.

Required UX:

- Step 1: Project identity: name, slug, description, type.
- Step 2: Local repo path: path input, browse/validate action, detected git branch/remotes, status.
- Step 3: Initial workflow: choose template (`software`, `docs`, `agent orchestration`, `library`, `ops`).
- Step 4: Seed docs/work: optional spec/ADR/task templates.
- Step 5: Finish to project dashboard.

Required behaviors:

- `repo_path` optional only if user chooses "No local repo yet"; otherwise validate path exists and is git repo or create/link repository record.
- Resulting dashboard shows path, branch, sync status.

Target files:

- `apps/web/src/lib/components/projects/ProjectForm.svelte`
- `apps/web/src/routes/projects/new/**`
- `apps/web/src/routes/projects/[id]/repos/**`

## Work Management Target

Fulcrum views must work like Jira/Linear/Plane:

- Backlog: untriaged/accepted backlog, priority ordering, sprint/cycle assignment.
- Board: status columns, WIP, blocked indicators, drag/drop, keyboard move, swimlane/grouping.
- List/table: high-density editing, saved filters, display options, bulk edit.
- Calendar: due/start dates and sprint/cycle dates.
- Gantt/timeline: dependencies, milestones, critical path, start/due/target dates.
- Reports: burndown, velocity, cycle time, throughput, WIP, CFD, forecast, age, scope, workload.

Target implementation:

- One `SavedView` model shared across board/list/table/calendar/Gantt/reports.
- One filter builder.
- One task relationship graph.
- One event stream.

## Task Detail Target

Task detail is the core relationship hub.

Required panels:

- Identity/fields: title, type, status, priority, assignee, labels, estimates, due dates, custom fields.
- Hierarchy: parent, children, progress rollup.
- Dependencies: blocked by, blocking, related, duplicate, source/target direction.
- Docs: linked docs, create/link doc, backlink count.
- Repo: local path, branch, commits, diff, file references.
- Runs: start run, active run, recent runs, run outcomes.
- Context: preview current context bundle, stale/missing context warnings.
- Artifacts: generated artifacts with source run.
- Memory: relevant memories, candidates, promote/demote actions.
- Comments/watchers/activity.
- Automation/audit: rules affecting this task, recent automation/audit events.

## Command Palette Target

Commands must be contextual:

- In project: create task/doc/run, link repo, search project, open board/backlog/docs/runs/artifacts/memory/context.
- In task: start run, link doc, create subtask, change status, add dependency, promote context, view artifacts.
- In doc: create task from selection, promote section to memory, start run with doc context, link artifact.
- In run: cancel/retry/continue, open context, open artifacts, review memory candidates, create follow-up.

## Web Verification Gates

- Playwright H1: fresh workspace -> create project with repo path -> dashboard shows relationship panels.
- Playwright H2: create hierarchy -> move through backlog/board/sprint/list/calendar/Gantt -> report updates.
- Playwright H3: create project doc from task -> backlinks both directions -> promote memory candidate.
- Playwright H4: dispatch run from task -> context preview -> run detail -> artifact/memory/follow-up visible.
- Playwright H5: search project -> result includes related task/doc/run/artifact/memory.
- Playwright H6: automation rule -> event -> notification/audit linked to entity.
