<objective>
Close the workflow loop with project-scoped automations, notifications, reports, search, audit visibility, and aggregate endpoints. Parent dashboards aggregate descendants while every action records actual target scope.
</objective>

<decision_coverage>
D-01, D-02, D-05, D-06, D-07, D-22, D-32, D-39, D-40, D-41, D-44, D-46, D-47, D-48, D-49, D-50, D-51, D-53, D-54.
</decision_coverage>

<technical_decisions>
- Use existing `json-rules-engine@7.3.1` for automation rules.
- Automation inheritance supports self, children, selected descendants, and locked parent rules.
- Search defaults current scope; global/All projects is explicit in Web, CLI, TUI, and API.
- Aggregate endpoints support selectable includes; default returns adjacent summaries/counts/IDs.
- Reports read linked graph events, not per-view UI state.
</technical_decisions>

<threat_model>
Threats:
- Automation fires on wrong descendant scope. Mitigation: effective target scope stored and displayed.
- Notification/audit omits causation. Mitigation: every automation action requires causation id.
- Search leaks cross-project data silently. Mitigation: current scope default and explicit All projects override.
- Destructive automation action executes in trusted mode without safeguards. Mitigation: trust-mode gate and dry-run/snapshot for destructive effects.
</threat_model>

<tasks>
1. Automation inheritance and execution.
   - Files: `src/application/automations/**`.
   - Action: rule applies to self/children/selected descendants, child override unless locked; dry-run and last-fired state.
   - Verify: tests for inherited source, locked rule, child override, selected descendant.
   - Acceptance: trace shows inherited source and target scope.

2. Event consumers for workflow closure.
   - Files: `src/application/automations/**`, `src/application/notifications/**`, `src/application/audit/**`.
   - Action: consume task/run/artifact/memory events; create notifications/audit/report updates.
   - Verify: E2E creates rule, triggers event, verifies notification and audit with entity links.
   - Acceptance: automation events appear in task/project/run activity.

3. Parent dashboards and reports.
   - Files: `src/application/dashboard/**`, `src/application/reports/**`, Web reports/dashboard components, TUI dashboard.
   - Action: parent aggregates descendants; drill-down; smart target default for actions with visible override.
   - Verify: tests for parent view and child mutation target trace.
   - Acceptance: parent report updates after board move/run completion.

4. Scoped search.
   - Files: `src/application/search/**`, `apps/cli/src/commands/search.ts`, Web command/search surfaces, TUI palette/search.
   - Action: current scope default; explicit All projects/global; results include trace/provenance and linked entity counts.
   - Verify: tests ensure global result not returned in current-scope search unless requested.
   - Acceptance: Web/CLI/TUI/API share scope behavior.

5. Aggregate API includes.
   - Files: `apps/server/src/runtime/trpc/routers/**`, application query modules.
   - Action: `include=docs,runs,artifacts,memory,audit` pattern for project/task/run aggregates.
   - Verify: contract tests for default summaries and explicit includes.
   - Acceptance: UI modes and `work inspect --mode` map to aggregate includes.
</tasks>
