<objective>
Make CLI and TUI dual-primary product clients. CLI supports workflow commands plus domain commands with JSON trace. TUI starts at active project workbench, not flat domain list, and can supervise work/run/context/memory/artifact flows.
</objective>

<decision_coverage>
D-01, D-02, D-03, D-18, D-19, D-20, D-33, D-35, D-36, D-37, D-38, D-39, D-40, D-41, D-42, D-43, D-44, D-45, D-46, D-47, D-48, D-51, D-53, D-54.
</decision_coverage>

<technical_decisions>
- Canonical CLI domain groups: `projects`, `tasks`, `docs`, `runs`, `artifacts`, `templates`, plus `work`, `trace`, `memory`, `context`, `automations`, `audit`, `doctor`.
- Every relevant CLI JSON response includes entity data, typed `links`, typed `trace`, and audit/causation IDs.
- TUI resumes last context; fallback active project workbench; portfolio available through shortcut.
- TUI uses OpenTUI pane layout with left project/work selection, center workflow, right relationships/activity, status bar for workspace/project/subproject/repo/doctor/run.
- CLI/TUI call shared application/API services, never own business logic.
</technical_decisions>

<threat_model>
Threats:
- CLI global defaults create records in wrong project. Mitigation: active project required or explicit `--project`/`--all-projects`.
- JSON omits audit/trace, breaking agent use. Mitigation: contract tests for every workflow command.
- TUI keyboard shortcuts trigger destructive actions without gate. Mitigation: destructive/executable/authority escalation routes through same policy approval.
</threat_model>

3. CLI JSON contract.
   - Files: CLI command serializers, trace schemas.
   - Action: standard response envelope with `entity`, `links`, `trace`, `audit`, `warnings`, `nextActions`.
   - Verify: snapshot/contract tests for representative commands.
