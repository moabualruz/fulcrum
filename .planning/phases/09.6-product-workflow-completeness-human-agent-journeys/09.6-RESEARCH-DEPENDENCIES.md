## Web UI Libraries Researched

### Svelte 5 component foundation

Candidate: existing shadcn-svelte/Bits-style local components under `apps/web/src/lib/components/ui/**`.

Decision:

- Keep local UI primitives. Do not add a large UI kit. Existing component source ownership fits long-running product needs.
- Expand primitives only where missing: resizable panes, tabs, split view, tree, data table, command palette actions.

Sources:

- Svelte 5 UI library overview: https://cssauthor.com/svelte-5-ui-libraries/
- Bits/shadcn ecosystem: https://sveltethemes.dev/category/bits-ui

### Data table

Candidate packages:

- `@tanstack/table-core` or `@tanstack/svelte-table`
- Svelte TableCN pattern based on TanStack Table

Decision:

- Use TanStack Table for task table/list saved views if current `TaskTable.svelte` lacks column virtualization/editing/grouping. Prefer adding `@tanstack/table-core` if not already present.
- Avoid bespoke table sorting/filtering beyond small helpers.

Source:

- TableCN/TanStack Svelte 5 data grid pattern: https://next.jqueryscript.net/svelte/data-grid-tanstack-table/

### Drag/drop Kanban

Candidate packages:

- `@thisux/sveltednd`
- `flowbite-svelte` Kanban board

Decision:

- Prefer `@thisux/sveltednd` for Svelte 5 drag/drop if current board DnD remains custom or fragile. It explicitly demonstrates Kanban, nested containers, horizontal scroll, drag handles, interactive elements.
- Avoid adopting Flowbite as full UI kit; use only if its Kanban implementation is isolated enough. Current local UI kit should stay source of truth.

Sources:

- https://sveltednd.thisux.com/
- https://flowbite-svelte.com/kanban-board

### Gantt/timeline

Candidate packages:

- `wx-svelte-gantt` / SVAR Svelte Gantt.
- `svelte-gantt`.
- DHTMLX Svelte Gantt.

Decision:

- Current repo already has `GanttView.svelte`. If it lacks dependencies/critical path/large-data behavior, prefer `wx-svelte-gantt`/SVAR-style Svelte Gantt component. Must support dependencies, drag/drop, tree/table left panel, zooming, and large datasets.
- Do not hand-roll dependency arrows/critical path unless existing component already covers it cleanly.

Sources:

- SVAR Svelte: https://svar.dev/svelte/
- svelte-gantt: https://www.npmjs.com/package/svelte-gantt
- DHTMLX Svelte Gantt summary: https://madewithsvelte.com/dhtmlx-svelte-gantt

### Calendar

Candidate:

- Continue existing `TaskCalendar.svelte` unless insufficient.
- If adding library, choose one supporting resource/day/week/month and Svelte 5 compatibility.

Decision:

- Audit current calendar before adding dependency. Project management calendar needs task due/start dates, sprint/cycle dates, milestones, and clickable task detail.

### Command palette

Candidate:

- Existing local command components under `apps/web/src/lib/components/ui/command/**`.
- Existing `cmdk-palette.ts`.

Decision:

- Keep existing command palette primitives. Replace static global link items with contextual command generation.

Target files:

- `apps/web/src/routes/+layout.svelte`
- `apps/web/src/lib/components/command-palette/**`

### Docs editor/wiki

Candidate:

- Existing TipTap/Yjs/editor components.
- Existing Markdown editor/preview.

Decision:

- Reuse TipTap/Yjs and docs tree. Add relational embeds/backlinks/templates around it rather than replacing editor.

## Server/Application Libraries

### Workflow orchestration

Current:

- Symphony/orchestration code already exists.
- `json-rules-engine` exists for automation.

Decision:

- Do not add Temporal as runtime dependency in Phase 9.6. Use Temporal as product/UX model: durable state, activities/tool events, retries, heartbeats, visibility.
- Add missing run state/events in Fulcrum application layer instead of introducing a second workflow engine.

Sources:

- Temporal docs: https://docs.temporal.io/

### Agent tracing

Decision:

- Do not add LangSmith/OpenAI tracing SDK as required runtime. Use their trace/span/project/thread model as internal data/UI target.
- Persist tool calls/spans in Fulcrum tables/events and expose through Web/CLI/TUI.

Sources:

- LangSmith observability: https://docs.langchain.com/oss/python/langchain/observability
- OpenAI Agents SDK tracing: https://openai.github.io/openai-agents-python/ref/tracing/create/

### MCP

Decision:

- Phase 9.6 must make Fulcrum data/actions MCP-ready through structured app services, but not necessarily ship new MCP server unless already in roadmap.
- Product must expose agent-accessible operations equivalent to Plane/Atlassian MCP: project/work item/docs/page/search/run/artifact/memory operations.

Sources:

- Plane developer docs: https://developers.plane.so/
- Atlassian MCP announcement: https://www.atlassian.com/blog/announcements/remote-mcp-server
- atlassian-mcp package: https://pypi.org/project/atlassian-mcp/
