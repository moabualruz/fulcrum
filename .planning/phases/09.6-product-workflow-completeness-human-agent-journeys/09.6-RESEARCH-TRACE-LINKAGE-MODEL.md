# Phase 9.6 Research: Trace, Linkage, and Integration Model

**Created:** 2026-05-08
**Purpose:** Define the product graph Fulcrum must expose so Web, CLI, TUI, server, orchestration, docs, memory, context, artifacts, and Symphony runs behave as one product instead of disconnected CRUD.

## Required Trace Spine

Every human or agent workflow must preserve this spine:

```text
workspace
  -> project
  -> repository/local_path/workspace_root
  -> work item
  -> planning doc/spec/decision/runbook
  -> context bundle
  -> routing decision/workflow config
  -> run attempt/live session
  -> tool events/transcript/status/tokens
  -> diff/artifacts
  -> memory candidates/follow-up tasks/doc updates
  -> audit/notifications/reports
```

Any surface that shows one node in the spine must expose backlinks and forward links to adjacent nodes. A task without project/repo/docs/runs/artifacts/memory links is incomplete. A run without task/context/workflow/session/artifacts/memory/audit links is incomplete. A doc without task/run/artifact/memory backlinks is incomplete.

## Cross-Surface Linkage Rules

Web:

- Global shell always shows active project or `All projects` state.
- Project dashboard exposes tasks, docs, repo, runs, context, memory, artifacts, automation, reports.
- Detail pages show relationship panels with live counts and direct actions.
- Every timeline row carries source entity, actor, timestamp, and target entity links.
- Run pages expose Symphony runtime state when present: workflow file, service key, workspace key/root, issue snapshot, live session, retry entry, cleanup status.

CLI:

- Every mutating command accepts `--project` or resolves active project.
- Every JSON response includes `links` object with adjacent entity ids.
- `fulcrum trace show <entity>` returns the trace spine for project/task/doc/run/artifact/memory.
- `fulcrum context preview --task <id> --json` emits source refs and reasons.
- `fulcrum runs watch --json` streams run events with causation ids.

TUI:

- First view is active project workbench, not a domain list.
- Left pane: project/work selection. Center pane: current workflow. Right pane: relationships/activity.
- A trace drawer is reachable from project/task/doc/run/artifact/memory rows.
- Live run view supports pending approvals, transcript cursor, artifacts, diff, context, and memory candidates.

Server:

- Read APIs return relationship counts and minimal linked entities needed for navigation.
- Write APIs create audit events with causation ids.
- Domain services do not create orphan tasks/docs/runs/artifacts/memory.
- Generated CRUD routes are insufficient unless wrapped in workflow services that enforce link creation.

## Data Flow: Human Work To Agent Run

1. Human creates/selects project with local repo path.
2. Server stores project and repo link; emits `project.created` and `repo.linked`.
3. Human creates task under project/board/cycle.
4. Docs, repo paths, prior runs, artifacts, and memory are linked to the task.
5. Context builder creates bundle with exact source refs and inclusion reasons.
6. Routing selects workflow/agent/model/profile; stores route decision.
7. Symphony-compatible runner receives strict issue snapshot plus workspace/config.
8. App-server session starts; events append to run timeline with token/tool/approval metadata.
9. Artifact harvester attaches diff/reports/files to run/task/project.
10. Memory candidate extractor stores candidates with source refs.
11. Human accepts proposals; task/doc/memory updates create audit rows.
12. Dashboards and reports recompute from linked graph.

## Data Flow: External Symphony Into Fulcrum

Fulcrum as Symphony implementer/provider must ingest external Symphony issue/workflow state without losing Fulcrum graph semantics:

1. External issue/service config/workflow maps to Fulcrum project, repo, task, workflow config, and route.
2. Upstream strict issue fields are stored as immutable dispatch snapshot.
3. Worker workspace root and key map to repo/local path safety model.
4. Run attempt maps to Fulcrum run with Symphony runtime state.
5. App-server protocol events map to live session event stream.
6. Comments/status updates map to task activity and audit, preserving upstream ids.
7. Cleanup/reconciliation maps to run lifecycle and repo health.

## Files That Must Not Break

- `src/orchestration/symphony/schemas.ts`: schema compatibility and strict snapshots.
- `src/orchestration/symphony/orchestrator.ts`: state transitions, retries, cleanup, event flow.
- `src/orchestration/symphony/worker.ts`: workspace root/key, git safety, hook behavior.
- `src/orchestration/symphony/app-server-client.ts`: session events, approvals, token/tool metadata.
- `src/orchestration/symphony/linear-tracker.ts`: upstream tracker contract; current ingest-only behavior must be either completed or explicitly isolated.
- `src/orchestration/__tests__/symphony-conformance.test.ts`: conformance assertions; must expand to bullet-level SPEC §17/§18 trace tests.
- `tests/symphony/spec-lock.test.ts`: upstream SPEC lock; must keep live SHA trace.
- `apps/web/src/lib/navigation/nav-data.ts`: shell hierarchy; must move from domain nav to project-first workbench.
- `apps/web/src/routes/(app)/+layout.svelte`: active project context and global workflow shell.
- `src/application/tasks/task-detail.ts`: task relationship aggregation.
- CLI command registry/generator: project scope and trace JSON output.
- TUI navigation/store/view files: project workbench and trace drawer.
