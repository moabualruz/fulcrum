<objective>
Make project docs, context bundles, memory, and artifacts one explicit knowledge loop. Users and agents can create docs from work, link docs/runs/artifacts/memory, preview deterministic context, promote sections to memory candidates, and trace every output back to source.
</objective>

<decision_coverage>
D-01, D-02, D-06, D-07, D-09, D-19, D-20, D-26, D-27, D-28, D-29, D-30, D-31, D-32, D-33, D-44, D-46, D-47, D-48, D-51, D-52, D-53, D-54.
</decision_coverage>

<technical_decisions>
- Docs are first-class records with tree/path/version/backlinks. Task summaries are generated views that can snapshot/promote into docs.
- Context bundles are deterministic records with included/excluded source refs, reasons, token estimates, scope, stale/conflict warnings, and policy.
- Memory is scoped to workspace/project/subproject/task/run/doc/artifact/repo with source refs, confidence, status, supersession, last-used, and policy.
- Artifacts have lifecycle states: created, pending review, accepted, rejected, linked, promoted, archived, expired.
- Reuse TipTap/Yjs/editor and docs components; do not introduce embeddings/RAG/model dependency.
</technical_decisions>

<threat_model>
Threats:
- Context pollution from unreviewed docs/memory/artifacts. Mitigation: status/lifecycle gates and policy-based inclusion.
- Prompt or artifact secrets exposed in default previews. Mitigation: source refs by default; redact sensitive content; full content explicit.
- Memory auto-promotion too broad. Mitigation: low-risk scoped auto-promotion only unless Full auto grants direct accepted memory writes.
- Artifact retention deletes important work. Mitigation: retention policy, accepted artifacts protected, audit on expiration.
</threat_model>
