For EACH file, replace every `db.query(...)` call with equivalent MikroORM operation:

**Strategy for each function:**
1. Change function signature from `(db: ProductDb, ...)` to `(em: EntityManager, ...)`
2. Replace `db.query("SELECT ...")` with `em.find(Entity, { where })` or repository method
3. Replace `db.query("INSERT ...")` with `em.create(Entity, data); em.persistAndFlush(entity)`
4. Replace `db.query("UPDATE ...")` with `em.assign(entity, data); em.flush()`
5. Replace `db.query("DELETE ...")` with `em.removeAndFlush(entity)`

**File-specific notes:**

`tasks.ts` (5 calls): Has `updateTaskAction` and `deleteTaskAction` — these are imported by product-kernel/api/router.ts (layering violation to fix in plan 08). For now, migrate the raw SQL to MikroORM but keep the functions here.

`documents.ts` (11 calls): Remove `ensureDocLinksCompatibility` (DDL already migrated in plan 03). Migrate remaining SELECT/INSERT/UPDATE/DELETE to MikroORM Document entity operations.

`skills.ts` (12 calls): Skill CRUD operations. Use SkillRepository or direct EntityManager with Skill entity.

`orchestration.ts` (11 calls): Agent run and orchestration queries. Use appropriate entities from src/db/entities/orchestration/.

`task-detail.ts` (6 calls): Task detail with joins (comments, custom fields). Use MikroORM populate/relations.

**For each migration:**
- Identify the MikroORM entity matching the table
- Use `em.find()` with FilterQuery for SELECTs
- Use `em.create()` + `em.persistAndFlush()` for INSERTs
- Use `wrap(entity).assign()` + `em.flush()` for UPDATEs
- Complex JOINs: use QueryBuilder (`em.createQueryBuilder()`) — still typed, no raw SQL

**Callers:** Each web server file is called from page.server.ts files. Update the call sites to pass EntityManager instead of ProductDb. The EntityManager comes from the MikroORM instance initialized at startup (plan 04).
