  <action>
Rewrite each router to delegate to service classes:

**Pattern:**
```typescript
import { TaskService } from "../../../services/TaskService.ts";

export const tasksRouter = t.router({
  list: protectedProcedure
    .input(ListTasksInput)
    .output(z.array(TaskSchema))
    .query(async ({ ctx, input }) => {
      const svc = new TaskService(ctx.em);
      return svc.list(ctx.orgId, input);
    }),

  create: protectedProcedure
    .input(CreateTaskInput)
    .output(TaskSchema)
    .mutation(async ({ ctx, input }) => {
      const svc = new TaskService(ctx.em);
      return svc.create(ctx.orgId, input);
    }),
  // ... etc
});
```

**Target line counts:**
- tasks.ts: 508 → ~150-200 (procedure definitions + input/output schemas only)
- docs.ts: 763 → ~150-200

**Rules:**
- Router files contain ONLY: procedure definitions, input/output Zod schemas, service instantiation
- NO business logic in routers — just `svc.method(args)`
- Keep Zod schemas in the router file (or move to separate schema files if large)
- Keep `protectedProcedure` middleware calls
- Keep error mapping (TRPCError wrapping) in router if service throws domain errors
