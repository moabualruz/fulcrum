<objective>
Implement deterministic Codex app-server JSONL client with session startup/resume, thread/turn extraction, timeouts, non-stalling approval/user-input handling, structured issue/session logs, and cumulative token accounting keyed by `thread_id`.
</objective>

<threat_model>
Threats:
- T-03-10: malformed app-server output deadlocks orchestration.
- T-03-11: approval or user-input requests stall indefinitely.
- T-03-12: cumulative token updates are double-counted.
Mitigations:
- Protocol parser enforces JSON-RPC envelope and read/turn timeouts.
- Approval/user-input events route to documented policy and terminal/non-stall paths.
- Token aggregation stores last cumulative value per `thread_id`.
Block on: high.
</threat_model>

<must_haves>
<truths>
- D-09: approval/sandbox defaults are explicit.
- D-10: Codex is default primary, but architecture must not prevent other agents.
- D-18: CI uses protocol/provider fakes; real binary smoke when available.
- D-21: retry/continuation passes prior session info where supported.
- D-22: token accounting consumes `thread/tokenUsage/updated`, keyed by `thread_id`, no double-counting.
</truths>
</must_haves>
