<objective>
Ship Fulcrum-required Symphony HTTP extension and prove Web, CLI, and TUI dispatch paths all call canonical tRPC/service orchestration APIs with fake providers and machine-checkable outputs.
</objective>

<threat_model>
Threats:
- T-03-16: HTTP extension binds publicly by default or exposes mutation beyond intended control endpoints.
- T-03-17: one surface dispatches through stale product-kernel/raw SQL path and bypasses canonical checks.
- T-03-18: UI/CLI/TUI tests pass against stubs instead of creating `agent_runs` state.
Mitigations:
- HTTP server binds loopback by default and exposes only `/`, `/api/v1/state`, `/api/v1/<issue>`, `POST /api/v1/refresh`.
- Dispatch endpoint lives in canonical tRPC/service path and all surfaces consume it.
- E2E/fake-provider tests assert `agent_runs` row and run state transitions.
Block on: high.
</threat_model>

<must_haves>
<truths>
- D-15: both spec conformance gates and surface dispatch proof pass.
- D-18: CI uses fakes, real-binary smoke when available.
- D-19: full run records persist.
- D-09: approval/sandbox posture documented and visible.
</truths>
</must_haves>
