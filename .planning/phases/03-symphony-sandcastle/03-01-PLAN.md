<objective>
Build the RED-first Symphony workflow/config conformance harness and implement repo-owned `WORKFLOW.md` runtime loading with strict prompt rendering, typed config, env/path expansion, reload last-good behavior, Codex launch defaults, and generated conformance trace updates.
</objective>

<threat_model>
Threats:
- T-03-01: malformed `WORKFLOW.md` dispatches an agent with an empty prompt or unsafe policy.
- T-03-02: `$VAR` or `~` expansion reads unexpected values or silently erases missing config.
- T-03-03: hand-edited conformance docs claim spec coverage without tests.
Mitigations:
- Strict Zod schemas, typed errors, and strict Liquid variables/filters are mandatory.
- `$VAR` and `~` expansion happen in one tested resolver and missing env refs fail with a typed error.
- Generated trace and lock are checked by `fulcrum symphony conformance` and `bun run ci`.
Block on: high.
</threat_model>

<truths>
- D-06: `WORKFLOW.md` supports prompt body, typed config, `$VAR`, `~`, hooks, Codex command/policy fields, server config, and reload.
- D-07: invalid reload keeps last good config and emits visible error.
- D-08: unknown prompt variables or filters fail closed.
- D-09: approval/sandbox posture documents exact defaults.
- D-16: tests are RED-first slices.
- D-17: `docs/symphony-conformance.md` is generated source of truth.
</truths>
</must_haves>
