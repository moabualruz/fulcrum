| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge gaps, table cell internal icon spacing |
| sm | 8px | Compact controls, filter rows, action button groups |
| md | 16px | Default form rows, table padding, panel padding |
| lg | 24px | Page header spacing, major section padding |
| xl | 32px | Split-pane gaps on desktop |
| 2xl | 48px | Major page band separation only |
| 3xl | 64px | Not used inside Phase 04 operational screens |

Exceptions: icon-only buttons and table row action targets must keep a 36px minimum visual size and 44px minimum pointer target on coarse pointers; status dots are 8px or 12px fixed; monospaced JSON editors may use 12px vertical rhythm.

## Color

Use existing Tailwind CSS variables from `src/web/src/app.css`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` light `oklch(1 0 0)`, dark `oklch(0.145 0 0)` | Page background, full-width work surface |
| Secondary (30%) | `var(--card)`, `var(--muted)`, `var(--sidebar)` | Tables, panels, filters, sidebars, inactive tabs, read-only metadata blocks |
| Accent (10%) | `var(--primary)` | Primary saves, active tabs, selected rule rows, enabled agent chips, active status focus, progress fill |
| Destructive | `var(--destructive)` | Delete rule, delete learned draft, uninstall skill, remove model, override lock mismatch only |

Accent reserved for: `Save rule`, `Create rule`, `Test routing`, `Approve draft`, active tab trigger, active switch/thumb, selected rule row border, enabled agent chip, model pull progress, successful backend probe indicator when rendered as active/healthy. Do not use accent for every link, neutral table action, decorative background, or informational badge.

Status colors:
- Healthy/running: green utility color with text fallback label.
- Degraded/conflict/review-needed: amber utility color with explicit label.
- Unavailable/error/lock mismatch: destructive token with explicit label.
- Stopped/disabled/unconfigured: muted token with explicit label.

## Phase 04 Screen Contract

### Routing Rules Editor

Layout:
- Use one dense settings route with tabs: `Rules`, `Drafts`, `Test`, `LLM Gate`, `Evidence`.
- Top row has title, compact backend health summary, and `Create rule` button.
- Main content uses a table-first layout, not card grids. Table minimum width: 960px with horizontal scroll.
- Right-side sheet is the only editor container for create/edit/draft review on desktop; on mobile it becomes full-width sheet.
- Do not nest cards. Use bordered panels or table expanded rows for evidence.

Rules table columns:
- Priority, Name, Scope, Source, Conditions, Agent, Skill set, Status, Updated, Actions.
- Actions use lucide icon buttons with accessible labels: edit, duplicate, move up/down, test, delete.
- Status uses text plus badge, never color alone.

Rule builder:
- Structured builder is default. Required fields: rule name, scope, priority, enabled switch, conditions group, action agent, action skill set.
- Conditions builder supports all/any grouping, fact path input, operator select, value input, add/remove condition, add/remove group.
- Raw JSON editor is a tab inside the editor, monospaced, fixed min-height 240px, with validation errors pinned below editor.
- Switching between builder and raw JSON must preserve valid values and show parse errors without losing user input.

Save flow:
- `Save rule` disabled until strict validation passes.
- `Test routing` dry-run available before save and after edit.
- Invalid JSON/conditions show inline field errors plus top error summary.
- Successful save returns to table and highlights changed row for one render cycle.

### Learned Drafts, Conflicts, Evidence

Draft table columns:
- Draft ID, Proposed rule, Source, Confidence, Conflict state, Matching active rules, Created, Actions.

Draft states:
- `Review needed`: disabled draft; actions are preview, edit, approve, delete.
- `Conflict`: disabled draft; show matching active rule IDs as links or copyable chips; actions are edit, delete. `Approve draft` hidden until conflict resolved.
- `Abstained`: evidence-only row; no approve action.

Evidence panel:
- Use expanded table row or sheet section with fixed headings: Task facts, No-match reason, Proposed conditions, Proposed actions, Source, Confidence, Backend/model, Active conflicts.
- JSON evidence blocks use 12px monospace, max height 280px, scroll area, copy button.
- Confidence display uses numeric percent and threshold text. Do not encode confidence only as color.

### Inference Backend Status

Backend status table/cards:
- Show one row per configured backend: embedded, Ollama, LM Studio, OpenAI-compatible.
- Required fields: configured, enabled, status, reason, model, embed probe, generate probe, dimensions, last checked, action.
- `start` action appears only for embedded backend. External backends show `Probe`, not `Start`.
- Degraded/unavailable rows must include concrete reason text and remediation path.

Backend states:
- `running`: model probes pass.
- `stopped`: embedded not running or backend disabled.
- `degraded`: reachable but one required probe failed.
- `unavailable`: configured backend unreachable or auth/config invalid.
- `unconfigured`: optional backend absent; not an error.

Embedding dimension state:
- Show configured model dimension and schema dimension together.
- Mismatch banner copy: `Embedding dimensions do not match. Writes and search are blocked until migration or reindex completes.`
- Do not offer an override for dimension mismatch in UI.

### Skills And MCP Virtual Skills

Skill list layout:
- Table-first list with filters above table: source, conflict state, enabled agent, lock state, search.
- Source values: local, upstream, MCP virtual.
- MCP virtual skills appear in same list with `MCP virtual` badge and descriptor fields.

Required columns:
- Slug, Version/descriptor, Source, Capabilities, Lock state, Enabled agents, Updated, Actions.

MCP virtual skill details:
- Show server name, command/package/version/env hints, tool names, descriptor SHA-256, tool manifest hash when available.
- Copy must state descriptor-only behavior: `Invocation stays with the agent MCP runtime.`
- Do not show per-agent support differences in Phase 04.

Lock and sync states:
- SHA mismatch fails closed. Row disabled state must show expected SHA and actual SHA.
- Conflict rows expand to structured three-way metadata: local hash, upstream hash, base hash, suggested resolution.
- No inline conflict markers in displayed `SKILL.md`.
- Override action requires destructive dialog and audit note field.

### CLI/TUI Parity Expectations

Web remains richest surface, but CLI and TUI must expose same decisions and states.

CLI:
- Commands must support list, test, create, update, delete routing rules and learned drafts.
- `--json` output must include status labels matching Web: review_needed, conflict, abstained, degraded, unavailable, sha_mismatch.
- Override commands must print expected/actual SHA and require explicit flag or confirmation.

TUI:
- Routing-rules screen must include tabs or panes for Rules, Drafts, Test, and Backends.
- TUI must show badge text equivalents, not color-only states.
- JSON editor can be raw-only in Phase 04 if builder controls are too constrained, but validation, dry-run, approve, delete, and override semantics must match Web.

## Interaction Contracts

Accessibility:
- All icon buttons require accessible labels and hover/focus tooltips for unfamiliar actions.
- Keyboard order: filters, primary CTA, table, row actions, editor fields, footer actions.
- Dialogs trap focus and return focus to invoking action.
- Tables must retain visible focus states on row actions.

Responsiveness:
- Desktop: max content width 1280px; tables horizontal scroll instead of column collapse for operational data.
- Tablet: editor sheet may cover 80vw.
- Mobile: tabs stack horizontally scrollable; tables remain scrollable; destructive dialogs fit 320px width.

Loading and refresh:
- Status and probe actions show row-local loading indicators.
- Route tests show deterministic result area with skeleton while pending.
- Long-running model pull uses stable 128px progress bar; progress cannot resize row height.

Audit-sensitive actions:
- Approve draft, override lock mismatch, delete rule, delete draft, uninstall skill, remove model all require explicit confirmation.
- Confirmation text must include object name or hash values. Generic `Are you sure?` is not sufficient.
