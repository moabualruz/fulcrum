## 1. System Classification

**System Type:** Hybrid

**Description:**
Phase 4 builds Fulcrum's local-first AI infrastructure: model-agnostic inference backends, model-dimension-safe embeddings, routing decisions with LLM fallback, learned draft routing rules, and MCP servers exposed as virtual skills across Web, CLI, and TUI. Good behavior means routing and embedding outputs are correct, explainable, auditable, deterministic where rules apply, and safely degraded when configured backends are unavailable.

**Critical Failure Modes:**
1. Routing activates an incorrect or conflicting learned rule without review.
2. LLM fallback forces a low-confidence route instead of abstaining.
3. Embedding storage accepts vectors whose dimensions do not match the configured model/schema.
4. Backend health hides unavailable configured inference providers.
5. Skill/MCP sync accepts tampered or mismatched lock hashes.

## 2. Framework Decision

**Selected Framework:** LangGraph TypeScript

**Version:** <!-- Pin the version during planning from package metadata or official docs -->

**Rationale:**
LangGraph TypeScript fits Phase 4 because the system needs deterministic, auditable, stateful routing control across CLI/Web/TUI, disabled learned drafts, conflict states, LLM fallback gates, MCP virtual skills, and explicit persistence through Fulcrum's existing tRPC/service/MikroORM paths. It is model-agnostic and TypeScript-compatible, aligning with Fulcrum's local-first and provider-flexible constraints.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|-----------|------------------|
| LlamaIndex TypeScript | Stronger for retrieval-only pipelines than for routing state, draft promotion, conflict handling, and audit-oriented workflow control. May be used narrowly if retrieval quality needs specialized support. |
| CrewAI | Python-primary and role/task abstraction does not fit Fulcrum's TypeScript local-first service layer or fine-grained routing state. |
| OpenAI Agents SDK | Provider-native path conflicts with Phase 4 backend parity and model-agnostic requirements. |
| Anthropic/the agent SDK | Provider-native and code-agent-oriented; would add orchestration ownership outside Fulcrum's existing service layer. |

**Vendor Lock-In Accepted:** No
