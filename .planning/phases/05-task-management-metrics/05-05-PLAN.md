Create `src/services/ReportService.ts` (per D-31..D-55):

**Constructor:** `constructor(private readonly em: EntityManager) {}`

**Layer 2 queries (MetricsCache snapshots):**

- `getBurndown(orgId, input: { sprintId, dateRange? })` — Query MetricsCache where scopeType='sprint', scopeId=sprintId, ordered by date ASC. Return array of `{ date, pointsRemaining, pointsCompleted, scopeTotal: pointsTotal }`. Include ideal burndown line calculation: `idealRemaining = scopeTotal - (scopeTotal * dayIndex / totalDays)`.

- `getBurnup(orgId, input: { sprintId, dateRange? })` — Same MetricsCache query, return `{ date, pointsCompleted, scopeTotal }`.

- `getVelocity(orgId, input: { projectId, lastN?: number })` — Query MetricsCache snapshots for completed sprints (last N, default 10). Group by sprint, sum pointsCompleted. Return `{ sprintName, pointsCompleted, rollingAvg }`. Rolling average over last 3 sprints.

- `getWipOverTime(orgId, input: { projectId, dateRange })` — Query MetricsCache where scopeType in ('sprint','project'), return `{ date, wipCount }`.

- `getProgressRollup(orgId, input: { scopeType, scopeId })` — Latest MetricsCache row for scope. Return `{ tasksTotal, tasksCompleted: completedCount, pointsTotal, pointsCompleted, percentByTasks, percentByPoints }`.

**Layer 1 queries (Event table):**

- `getCycleTime(orgId, input: { projectId, dateRange })` — Query events where verb='task.status_changed'. For each task_id, find earliest "started" event and latest "completed" event. Return scatter points: `{ taskId, completionDate, cycleTimeHours }`. Calculate p50, p75, p95 percentile bands.

- `getLeadTime(orgId, input: { projectId, dateRange })` — Same as cycle time but measure from task.createdAt to completion event.

- `getThroughput(orgId, input: { projectId, dateRange })` — Count tasks with status_changed to completed, group by week. Return `{ week, completedCount, rollingAvg }`.

- `getCfd(orgId, input: { projectId, dateRange })` — Query MetricsCache snapshots, return `{ date, statusCounts }` where statusCounts is `{ backlog: N, unstarted: N, started: N, completed: N, canceled: N }` for stacked area chart.

**Table-based reports:**
- `getStaleIssues(orgId, input: { projectId, thresholdDays?: number })` — Tasks with no Event in last N days (default 14). Return task list sorted by days since last activity.
- `getBlockedItems(orgId, input: { projectId })` — Tasks with TaskRelationship where type='blocked_by'. Include blocker chain and days blocked.
- `getReopenedRate(orgId, input: { projectId, dateRange })` — Count events where verb='task.status_changed' and fromValue contains 'completed' and toValue is not completed. Return percentage per sprint.
- `getWorkloadDistribution(orgId, input: { projectId })` — Group tasks by assigneeId, count per status category.
- `getCapacityUtilization(orgId, input: { sprintId })` — Sum points per assignee vs sprint capacity allocation.
- `getScopeTracking(orgId, input: { scopeType, scopeId })` — MetricsCache time series showing pointsTotal (scope) vs pointsCompleted over time.
- `getDeadlineRisk(orgId, input: { projectId })` — Tasks with dueDate approaching, velocity extrapolation.

**Utility:**
- `exportCsv(orgId, input: { reportType, scopeType, scopeId, dateRange? })` — Call appropriate report method, serialize to CSV string with headers.

All queries MUST filter by orgId for tenant isolation.

After implementation, update `src/services/ReportService.test.ts` to make tests pass.

**metrics-rollup.ts** — Create `src/workers/metrics-rollup.ts` (per D-33):

Export interface `MetricsRollupPayload { scope_type: "sprint"|"project"|"epic"; scope_id: string; org_id: string; }`.

Export function `registerMetricsRollupJob(registry: WorkerRegistry, getEm: () => EntityManager)`:
- Call `registry.registerTask("metrics_rollup", validator, handler)`
- Validator: assertRecordPayload, assertStringField for scope_id, scope_type, org_id
- Handler: 
  1. Get EM via `getEm()`
  2. Query Task table for the scope (e.g., where sprint FK = scope_id for sprint scope, or projectId = scope_id for project scope)
  3. Aggregate: count tasks by status category → statusCounts, sum points → pointsTotal/pointsCompleted/pointsRemaining, count started tasks → wipCount, count total → tasksTotal
  4. Upsert MetricsCache row for (scopeType, scopeId, date=today): use `em.upsert(MetricsCache, { ...aggregated }, { onConflictFields: ['scopeType', 'scopeId', 'date'] })` or find-then-update pattern
  5. Flush

Export function `enqueueMetricsRollup(registry: WorkerRegistry, payload: MetricsRollupPayload)`:
- Enqueue the "metrics_rollup" task with the payload
