**AutomationService** — Create `src/services/AutomationService.ts` (per D-89..D-92):

**Properties:**
- `private readonly unsubscribes: Array<() => void> = []`
- `private readonly chainDepth = new Map<string, number>()` — cycle detection per D-91
- `private readonly MAX_CHAIN_DEPTH = 5`

**Methods:**
- `constructor(private readonly em: EntityManager) {}`
- `start()` — Subscribe to EventBus patterns: `task.status_changed`, `task.assigned`, `task.label_*`, `task.priority_changed`, `task.comment_added`, `task.created`. Store unsubscribe handles.
- `stop()` — Call all unsubscribes, clear array.
- `evaluateAutomations(event: { orgId, projectId, verb, payload, eventId })` — 
  1. Check chainDepth for eventId — if >= 5, log warning and return (D-91 cycle detection)
  2. Load all enabled ProjectAutomation rows for project where triggerType matches the event verb
  3. For each matching automation: evaluate condition (if condition is non-null, check if event payload satisfies it using simple field-equals logic)
  4. For matching rules: execute action (call executeAction)
  5. Increment automation.executionCount, flush
- `executeAction(orgId, automation: ProjectAutomation, event)` —
  Switch on automation.actionType:
  - "set_status" → update task status via TaskService
  - "set_assignee" → update task assignee
  - "add_label" / "remove_label" → modify task labels array
  - "set_priority" → update task priority
  - "move_to_sprint" → update task sprint FK
  - "add_comment" → create comment via CommentService
  - "subscribe_watcher" → subscribe via CommentService
  Each action that mutates a task emits its own event → can chain (tracked by chainDepth)

- `listTemplates()` — Return 4 predefined automation templates per D-92:
  1. "Auto-assign reviewer when status = In Review"
  2. "Add 'stale' label when no activity for 14 days"
  3. "Move to Done when all subtasks completed"
  4. "Notify watchers when priority changed to Urgent"

**CRUD methods (for router):**
- `list(orgId, projectId)` — find all ProjectAutomation for project
- `create(orgId, input)` — create ProjectAutomation entity
- `update(orgId, automationId, input)` — find and update
- `delete(orgId, automationId)` — find and remove
- `toggle(orgId, automationId)` — flip enabled boolean

**automationsRouter** — Create `src/server/trpc/routers/automations.ts`:
Procedures (all `permissionedProcedure({ resource: "automations", action: "<action>" })`):
- `list` (query) — input: { projectId: z.uuid() }
- `create` (mutation) — input: CreateAutomationInput schema
- `update` (mutation) — input: { id: z.uuid(), ...updates }
- `delete` (mutation) — input: { id: z.uuid() }
- `toggle` (mutation) — input: { id: z.uuid() }
- `templates` (query) — no input, returns template list

**AppRouter** — Mount `automations: automationsRouter` in index.ts.
