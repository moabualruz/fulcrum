**FieldDependencyEval.ts** (D-109, D-111 client-side):
```typescript
interface Rule { sourceFieldId: string; sourceValue: string; targetFieldId: string; action: 'show' | 'hide' | 'require'; }

export function evaluateFieldDependencies(
  rules: Rule[],
  fieldValues: Record<string, unknown>
): { visible: Set<string>; hidden: Set<string>; required: Set<string> }
```
- For each rule: if fieldValues[sourceFieldId] matches sourceValue → apply action to targetFieldId
- "show": add to visible, remove from hidden
- "hide": add to hidden, remove from visible
- "require": add to required (AND to visible)
- Default: all fields visible, none required (unless rule says otherwise)
- Called reactively in task form to show/hide/require fields instantly

**FieldDependencyConfig.svelte** (D-110):
- UI for managing field dependency rules per project
- List existing rules with edit/delete
- Add rule form: source field picker → source value input → target field picker → action selector (show/hide/require)
- Example from D-110: when "Type" = "Bug" → show "Severity" and "Steps to Reproduce"
- CRUD via new tRPC procedures (or inline in existing custom-fields router)

**FieldDependencyService.ts** (D-111 server-side, HIGH-03 backend):
- Constructor(em)
- `validate(orgId, projectId, fieldValues)`: load rules for project, evaluate, check all required fields have non-empty values. Throws if validation fails with list of missing required fields.
- `listRules(orgId, projectId)`: return all rules
- `createRule(orgId, rule)`: create FieldDependencyRule entity
- `deleteRule(orgId, ruleId)`: delete rule
- This service is called by TaskService.create/update (wired in Plan 06) for HIGH-03 fix.
