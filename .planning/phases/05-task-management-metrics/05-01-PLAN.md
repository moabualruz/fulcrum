**IMPORTANT: Migration split strategy (GO condition #1 from peer review)**

Migrations run in filename order. The schema change is split into TWO files:
1. `Migration20260505100000_phase5_schema_extensions.ts` — ALTER TABLE operations on existing tables. Runs FIRST. Includes backfill for non-null columns with defaults.
2. `Migration20260505100001_phase5_schema_new_tables.ts` — CREATE TABLE for all 9 new tables. Runs SECOND. References columns added in step 1.

This prevents FK constraint failures when new tables reference columns that don't yet exist on existing tables.
