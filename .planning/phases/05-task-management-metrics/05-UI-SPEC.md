## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge gaps, avatar cluster overlap offset |
| sm | 8px | Compact controls, comment meta row, chip gaps |
| md | 16px | Default card padding, form rows, list item padding |
| lg | 24px | Page header, section separators, chart container padding |
| xl | 32px | Column gaps on wide-layout dashboard |
| 2xl | 48px | Major view section breaks (board → list toggle area) |
| 3xl | 64px | Not used in Phase 05 screens |

Exceptions:
- Kanban column drag handles: minimum 44px touch target height per card.
- Watcher avatar stack: 24px per avatar with 8px overlap (net 16px stride).
- Chart canvas height: burndown 280px, velocity/throughput bar 220px, WIP area 200px, CFD stacked area 260px, cycle time line 220px. Heights are fixed per chart type; do not vary with viewport until below 768px.
- Gantt row height: 36px per task row, 8px gap between rows.
- Calendar day cell: minimum 80px height on desktop, 48px on mobile.
- Sprint capacity progress bar: 8px track height, full container width.

## Color

Use existing Tailwind CSS variables from `src/web/src/app.css`.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--background)` light `oklch(1 0 0)`, dark `oklch(0.145 0 0)` | Page background, chart canvas background, Gantt background, calendar grid |
| Secondary (30%) | `var(--card)`, `var(--muted)`, `var(--sidebar)` | Sprint cards, task cards, comment thread container, board columns, metrics panel, filter bar, Gantt row alternates, calendar day cells |
| Accent (10%) | `var(--primary)` | Primary CTA buttons, active view tab, selected task row border, sprint progress fill (on-track), chart series 1 (burndown ideal line), watched indicator dot |
| Destructive | `var(--destructive)` | Delete task (bulk), delete comment, unsubscribe-self confirmation, burndown behind-schedule highlight only |

Accent reserved for: `Create task`, `Add comment`, `Save retrospective`, `Start sprint`, `Close sprint`, active view-mode tab trigger, selected task row left border, sprint capacity fill (≤100%), burndown ideal-line series, watcher subscription active state. Do not use accent for every badge, status chip, or chart series.

Chart palette — use `var(--chart-N)` tokens defined in app.css:
- `--chart-1` (oklch 0.87): primary series (burndown actual, velocity current sprint)
- `--chart-2` (oklch 0.556): secondary series (burndown ideal, velocity trailing)
- `--chart-3` (oklch 0.439): WIP area fill, CFD series 3
- `--chart-4` (oklch 0.371): CFD series 4, cycle time median line
- `--chart-5` (oklch 0.269): CFD series 5, throughput series

Never encode chart meaning with color alone — each series must also have a labeled legend entry.

Status colors for task status chips:
- Todo: muted token + text label.
- In progress: amber utility color + text label.
- Done/completed: green utility color + text label.
- Blocked: destructive token + text label.
- Cancelled: muted-foreground + strikethrough text label.

Sprint status colors:
- Active: accent (primary) + text label.
- Closed: muted + text label.
- Planning: secondary-foreground + text label.

Gantt bar colors:
- Default task bar: `var(--primary)` at 70% opacity.
- Overdue task bar: `var(--destructive)` at 70% opacity.
- Dependency arrow: `var(--muted-foreground)` at 60%.

## Copywriting Contract

### Primary CTAs

| Screen | Primary CTA |
|--------|-------------|
| Task board / list | Create task |
| Task detail | Add comment |
| Sprint detail | Start sprint |
| Closed sprint (retrospective) | Save retrospective |
| Reports / metrics page | Refresh metrics |
| Watcher panel | Watch task |

### Empty States

| Context | Heading | Body |
|---------|---------|------|
| Board with no tasks | No tasks yet | Create your first task to start tracking work in this sprint. |
| Comments on a task | No comments yet | Add a comment to discuss this task or resolve blockers. |
| Watchers list (task detail) | No watchers | Watch this task to get notified when it is updated. |
| Burndown (no sprint data) | No data for this sprint | Assign tasks to this sprint and log progress to see the burndown. |
| Velocity (no sprint history) | Not enough sprint history | Complete at least two sprints to see velocity trends. |
| Gantt (no tasks with dates) | No scheduled tasks | Set start and due dates on tasks to view the Gantt timeline. |
| Calendar (no tasks with due dates) | Nothing due this month | Set due dates on tasks to see them on the calendar. |
| Saved views (no views) | No saved views | Save a filtered task list as a view to access it quickly. |

### Error States

| Context | Copy |
|---------|------|
| Metrics cache stale / load fail | Metrics could not load. Try refreshing — data updates within 30 seconds of task changes. |
| Comment create fail | Comment not saved. Check your connection and try again. |
| Bulk operation fail | Bulk update failed and was rolled back. No tasks were changed. Fix the error and try again. |
| Sprint close fail | Sprint could not be closed. Verify all required fields are set and try again. |
| Custom field validation fail | Invalid value for {field name}. {field-type-specific reason}. |
| Gantt render fail | Timeline could not render. Reload the page or check task date fields. |

### Destructive Confirmations

| Action | Confirmation Pattern |
|--------|---------------------|
| Delete task | Delete task: Deleting "{task title}" is permanent and cannot be undone. Confirm deletion. |
| Delete comment | Delete comment: This comment will be permanently removed. Confirm deletion. |
| Bulk delete tasks | Delete {N} tasks: Permanently delete all {N} selected tasks. This cannot be undone. |
| Close sprint with incomplete tasks | Close sprint: {N} tasks are still open. Move them to backlog or the next sprint before closing, or close anyway. |

### Resolve / Unresolve Comment

- Resolve: `Resolve` (icon: check-circle, lucide).
- Unresolve: `Unresolve` (icon: circle-dot, lucide).
- Resolved comment visual: body text at 60% opacity, border-left using muted token, "Resolved" label badge (12px label weight 600).

### Staleness Indicator

- When metrics cache is within 30-second window: no indicator shown.
- When last-updated > 30 seconds ago: show `Updated {N}s ago` as 12px muted-foreground text below chart title. No spinner — the 30-second window is by design.

## Phase 05 Screen Contract

### Task Board (Kanban)

Layout:
- Horizontal scroll of status columns. Each column: 280px min-width, flex-grow 0.
- Column header: status label (20px heading weight 600) + task count badge (12px label).
- `Create task` button in column header or board top-right — both acceptable.
- Task cards: title (14px body), assignee avatar (24px), priority icon (lucide, 16px), points badge (12px label), due date (12px label, destructive if overdue).
- Drag handle on card left edge; full card is draggable.
- Selected state: 2px accent left border on card.

Board empty column: show "No tasks" muted text centered in column — no button (create at board level only).

### Task List

Layout:
- Dense table with columns: checkbox (bulk select), Title, Status, Priority, Assignee, Points, Sprint, Due date, Labels, Actions.
- Row height: 40px.
- Bulk select shows contextual action bar above table: "X tasks selected" + actions: Change status, Change assignee, Move to sprint, Change priority, Add label, Delete.
- Bulk action bar slides in with 150ms ease-in; dismisses on deselect-all or action complete.
- Active filters shown as chip row above table. Each chip: label + value + remove × icon.

Saved views:
- View selector as tabs or dropdown above filter row.
- `Save current view` button in filter bar right side.
- Saved view name max 40 characters; truncate with tooltip.

### Task Detail

Layout:
- Two-column layout on desktop (≥1024px): 60% left (title + description + activity) / 40% right (metadata sidebar).
- Single column on mobile.

Metadata sidebar fields:
- Status (select), Priority (select), Assignee (avatar + name select), Sprint (select), Points (number input), Labels (multi-select chips), Due date (date picker), Custom fields (type-specific inputs per field type), Watchers (avatar stack, max 5 visible + overflow count).

Comments section (below description):
- Flat chronological list.
- Each comment: avatar (32px) + author name (12px label weight 600) + timestamp (12px muted-foreground) + resolved badge (if resolved) + body (14px body) + actions (resolve/unresolve, delete — icon buttons, appear on hover/focus).
- Resolved comments: body at 60% opacity, left border muted token, "Resolved" badge.
- Comment composer: textarea (min 80px, auto-expand) + `Add comment` button (right-aligned, disabled until non-empty body).
- No nested replies in Phase 05 (flat threading per D-01).

Watchers panel (in metadata sidebar):
- Avatar stack (24px avatars, 8px overlap) + "Watch task" button.
- "Watch task" → accent primary button when user is NOT watching.
- "Unwatch" → muted outlined button when user IS watching.
- Clicking avatar stack opens popover listing all watchers with unsubscribe option (own entry only).

### Sprint Detail

Layout:
- Page header: sprint name (28px display), status badge, date range (12px label), capacity progress bar.
- Tabs below header: `Board`, `List`, `Reports`, `Retrospective`.

Capacity bar:
- Track: 8px height, full container width, muted background.
- Fill: accent (primary) when ≤100%, destructive when >100%.
- Label: "X / Y pts" (14px body) left of bar, "Z% capacity" (12px label muted) right of bar.

Retrospective tab:
- TipTap rich-text editor, full width.
- `Save retrospective` button below editor (right-aligned).
- Read-only when sprint status is not `closed` — show muted "Notes can be edited after sprint is closed" placeholder.

### Reports / Metrics Page

Layout:
- Page: `/projects/[id]/reports` or `/sprints/[id]/reports`.
- Sprint selector dropdown at top (selects which sprint data to show).
- Grid of chart cards below: 2-column on desktop (≥1024px), 1-column on mobile.
- Each chart card: card shell, chart title (20px heading), staleness indicator (12px muted below title), chart canvas, legend below canvas.

Chart specifications:

| Chart | Type | X axis | Y axis | Series |
|-------|------|--------|--------|--------|
| Burndown | Line | Day (sprint days 0–N) | Points remaining | Actual (chart-1), Ideal (chart-2 dashed) |
| Velocity | Bar | Sprint name | Points completed | Current (chart-1), Trailing avg line (chart-2) |
| Cycle time | Line | Date | Median hours (in_progress→done) | Median (chart-4), P75 (chart-3 dashed) |
| Throughput | Bar | Date (daily) | Tasks completed | (chart-1) |
| WIP | Area | Date | Count of in-progress tasks | (chart-3) |
| CFD | Stacked area | Date | Task count per status | One series per status, chart-1..5 |

All charts: grid lines use `var(--border)`, axis labels 11px weight 400, tooltips use card token background + foreground, legend below chart with color swatch + label (never color alone).

Chart loading state: skeleton rectangle matching chart canvas height per type.

No data state: centered muted text per empty state table above. No skeleton when confirmed no data.

### Gantt View

Layout:
- Route: `/projects/[id]/gantt` or as a tab within project/sprint.
- Two-pane: 300px left task list (title, assignee avatar, status chip) + right SVG timeline.
- Timeline header: month/week labels at top (12px label weight 600), day columns below.
- Task row: 36px height, 8px gap between rows.
- Horizontal scroll on timeline pane; left task list sticky.

Task bar:
- Width proportional to (due_date - start_date).
- Color: primary at 70% opacity (default), destructive at 70% (overdue).
- Label inside bar if >60px wide; tooltip always on hover.
- No start_date set: bar renders as point marker at due_date.

Dependency arrows:
- SVG polyline from right edge of predecessor bar to left edge of successor bar.
- Color: `var(--muted-foreground)` at 60%, 1.5px stroke, arrowhead 6px.
- No dependency arrows if task has no dependencies.

Read-only: no drag interaction in Phase 05 per D-15. Click on bar opens task detail sheet.

### Calendar View

Layout:
- Route: `/projects/[id]/calendar`.
- Standard month grid: 7 columns, variable rows.
- Navigation: `< Prev` / `Next >` month buttons + month/year heading (20px heading).
- Day cell: minimum 80px height desktop / 48px mobile.
- Tasks in cell: compact chips (12px label, truncated at 24 chars, status color left dot + title).
- Overflow: "+N more" link opens popover listing all tasks for that day.

Read-only: no drag interaction in Phase 05 per D-15. Click task chip opens task detail sheet.

### Bulk Operations UX

Selection:
- Checkbox column in list view; "select all on page" in header checkbox.
- Shift-click selects range.
- Selected count shown in contextual action bar.

Bulk action result:
- Success: toast "X tasks updated." (bottom-right, 4s auto-dismiss).
- Failure: toast "Bulk update failed — rolled back. No tasks changed." (destructive, persist until dismissed).
- Max batch 200: if >200 selected, disable bulk actions and show "Select 200 or fewer tasks to use bulk actions" tooltip on action bar.

### TUI ASCII Charts (Phase 05 TUI Surface)

All six chart types render in terminal using box-drawing characters and Unicode block elements:
- Burndown: `▓` for actual, `░` for ideal, axis with day labels.
- Velocity: `█` bar per sprint, numeric label above each bar.
- Cycle time: `·` sparkline with median marker `┼`.
- Throughput: `▪` bar per day.
- WIP: `▓` area fill using block characters.
- CFD: stacked `▓░▒` per status with legend below.

TUI ASCII chart canvas height: 12 terminal rows for all chart types. Chart title above canvas (bold). Legend below canvas as `[■ Label]` per series.

No color-only encoding in TUI — all series labeled.

### CLI Metrics Surface

- `fulcrum metrics <sprint-id>` outputs JSON from `MetricsCache`.
- JSON fields: `sprintId`, `sprintName`, `completedCount`, `pointsCompleted`, `pointsRemaining`, `wipCount`, `velocity`, `cycleTimeMedianHours`, `throughputPerDay`, `cfdSnapshot[]`, `computedAt`, `isStale`.
- `--format table` flag renders a compact terminal table of scalar metrics (no chart rendering).
- No chart rendering in CLI per D-26.

## Interaction Contracts

### Accessibility

- All icon buttons require accessible labels and hover/focus tooltips.
- Chart canvases include `role="img"` + `aria-label` describing the chart type and sprint.
- Drag-and-drop in kanban board must have keyboard alternative: task context menu with "Move to column" submenu.
- Bulk select checkboxes: `aria-label="Select task: {title}"`.
- Keyboard order: view toggle tabs → sprint selector → filter chips → create CTA → table/board → row actions → bulk action bar.
- Dialogs trap focus and return focus to invoking element on close.
- Resolved comments: `aria-label` includes "Resolved:" prefix.

### Responsiveness

- Desktop (≥1024px): two-column task detail, 2-column chart grid, Gantt two-pane.
- Tablet (768–1023px): task detail single column, chart grid single column, Gantt collapses task list to 200px.
- Mobile (<768px): board horizontal-scrollable columns, list table horizontal-scrollable, calendar 48px cell height, Gantt hidden (replaced by list view), chart canvases reduce to 180px height.

### Loading and Refresh

- Charts show skeleton rectangle at exact configured height while loading.
- Sprint board column counts update optimistically on drag; revert on failure.
- Comment add: optimistic append with skeleton; replace on success, remove on failure with error toast.
- Watcher subscribe/unsubscribe: optimistic toggle; revert on failure.
- Bulk operations: lock action bar during in-flight request; show spinner on action button; unlock after result.
- Metrics refresh: `Refresh metrics` button triggers tRPC mutation to enqueue rollup job; button shows spinner for 2s then re-fetches; staleness indicator updates.

### Audit-Sensitive Actions

All four destructive confirmations (delete task, delete comment, bulk delete, close sprint with open tasks) use `AlertDialog` component. Confirmation must include object name or count in dialog body. Generic "Are you sure?" is not sufficient.
