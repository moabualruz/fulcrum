Create `src/services/WorkflowService.ts` (per D-22..D-25):

**Constructor:** `constructor(private readonly em: EntityManager) {}`

**Default transition graph:** Define a default allowed-transitions map for the 6 default statuses (Backlog, Todo, In Progress, In Review, Done, Canceled):
```typescript
const DEFAULT_TRANSITIONS: Map<string, Set<string>> = new Map([
  ["Backlog", new Set(["Todo", "Canceled"])],
  ["Todo", new Set(["In Progress", "Backlog", "Canceled"])],
  ["In Progress", new Set(["In Review", "Todo", "Canceled"])],
  ["In Review", new Set(["Done", "In Progress", "Canceled"])],
  ["Done", new Set(["In Progress"])], // reopen
  ["Canceled", new Set(["Backlog", "Todo"])], // restore
]);
```

**Methods:**
- `getTransitionGraph(orgId, projectId): Promise<Map<string, Set<string>>>` — Load project entity, check `workflow_config` jsonb column (added by Plan 01 migration on the projects table). If workflow_config is non-null, deserialize the transition map from it. Fall back to DEFAULT_TRANSITIONS for projects without custom workflow.
- `validateTransition(orgId, input: { projectId, taskId, fromStatus, toStatus }): Promise<{ allowed: boolean; reason?: string }>` — Load transition graph, check if edge exists from fromStatus to toStatus. Return `{ allowed: false, reason: "Transition from '${from}' to '${to}' is not allowed. Allowed next: ${[...allowed].join(', ')}" }` if not found.
- `getStatusCategory(statusName: string, orgId: string, projectId: string): Promise<string>` — Look up TaskStatus by name+project, return its category.
- `getDefaultStatuses(): { name: string; category: string }[]` — Return the 6 default statuses with their categories: Backlog→backlog, Todo→unstarted, In Progress→started, In Review→started, Done→completed, Canceled→canceled.
- `updateTransitions(orgId, projectId, transitions: Array<{ from: string; to: string }>)` — Store custom transition graph for project. Serialize transition edges as jsonb and write to the project's `workflow_config` column. Do NOT use project_automations sentinel — that is an antipattern.

**Auto-actions on status change (D-25):**
- `executeAutoActions(orgId, taskId, fromCategory, toCategory, em): Promise<void>`:
  - If toCategory === "started" → set `task.startedAt = new Date()` (for cycle time calculation)
  - If toCategory === "completed" → find all TaskRelationship where fromTaskId=taskId and type='blocks', auto-resolve them (delete the blocking relationship)
  - If toCategory === "completed" → set `task.completedAt = new Date()` if Task has that field (or use Event timestamp)
