# Phase 09.5 Plan 35: Canonical tRPC Application Adapter Summary

Canonical tRPC routers for agents, artifacts, document comments, document versions, documents, and orchestration now delegate persistence through application modules/services instead of owning ORM/entity logic in router bodies.

## Implementation Notes

- `agents.testProfile` now loads and updates stored profiles through `application/agents/queries.ts`; router keeps CLI allowlist and spawn result mapping.
- `doc_comments`, `doc_versions`, and `documents` now call `application/docs` commands/queries and keep legacy mount input/output compatibility where possible.
- `artifacts` now prefers `application/artifacts` command/query paths when an EntityManager exists, while preserving injected repository/storage adapters used by focused router tests.
- `orchestration.dispatchRun` and run detail reads now route through `application/runs`; legacy Symphony run listing remains behind `application/legacy/symphony.ts`.
