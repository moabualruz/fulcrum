# 09.5 API, tRPC, Router Boundary Gap Research

Source: Ampere API-contract subagent, 2026-05-07.

## Executive Finding

REST, tRPC, and router surfaces still contain fallback stores, direct ORM resolution, and persistence-selection logic. They should call application facades only; missing application dependencies should fail through canonical app errors.

## REST Gaps

- `src/api/routes/tasks.ts`: fallback task store around line 78.
- `src/api/routes/docs.ts`: fallback document store around line 34.
- `src/api/routes/memory.ts`: `fallbackMemories` around line 183.
- `src/api/routes/sprints.ts`: fallback sprint store around line 49.
- `src/api/routes/saved-views.ts`: fallback saved-view store around line 48.
- `src/api/routes/notifications.ts`: notification fallback store around line 34.
- `src/api/routes/search.ts`: stub search result path around line 37.
- `src/api/routes/kernel-reports.ts`: `FIXED_ORG` and fallback report data around line 56.

Replace these with injected public API/application facades. If a facade is unavailable, return canonical application error mapping, not empty or stub data.

## REST ORM Resolution Gaps

- `src/api/routes/repos.ts`
- `src/api/routes/search.ts`
- `src/api/routes/kernel-tasks.ts`
- `src/api/routes/kernel-sprints.ts`
- `src/api/routes/kernel-audit.ts`
- `src/api/routes/kernel-notifications.ts`

Move EntityManager resolution to API composition/application adapter modules, then pass application callers into routes.

## tRPC Gaps

- `src/server/trpc/routers/orgs.ts`: persistence selection belongs in application org service/facade.
- `src/trpc/routers/artifacts.ts`: repository/storage/events fallback wiring belongs in application artifact service.
- `src/trpc/context.ts`: direct `ctx.em` should stay composition-only; routers should use application caller/facade helpers.

## Router Runtime Gap

- `src/router/rules-engine.ts`: repository initialization and malformed-rule mutation are business/data operations. Move disable/mutation behavior into application routing service. Router should evaluate a supplied ruleset only.

## Guardrail Patterns

Ban in route/runtime adapter files:

- `@mikro-orm/postgresql`, `src/db/entities`, `src/db/repositories`
- `requireTrpcEntityManager`, `optionalTrpcEntityManager`, `ctx.em`
- `em.find`, `em.findOne`, `em.create`, `em.persist`, `em.flush`, `em.transactional`, `em.getRepository`
- `getKysely`, `.execute(`, `.query(`
- `new Map<`, `createFallbackStore`, `fallbackMemories`, `StubSearchResults`, `makeNotifStore`, `FIXED_ORG`
