## Standard Reuse Patterns

### Application Boundary

Use domain functions as only interface-callable business boundary:

```ts
import * as taskCommands from "../../application/tasks/commands.ts";
import * as taskQueries from "../../application/tasks/queries.ts";
import { CreateTaskInputSchema, TaskDtoSchema } from "../../application/tasks/schema.ts";
import type { AppContext } from "../../application/tasks/types.ts";
```

`createTask(em, ctx, input)` validates with Zod, opens `em.transactional`, uses `TaskRepository`, persists entity, flushes, and returns `TaskDto`. [VERIFIED: src/application/tasks/commands.ts:13]

`listTasks(em, ctx, input)` uses repository reads and returns serialized DTOs; `findVisibleTask` enforces org/project visibility. [VERIFIED: src/application/tasks/queries.ts:9]

### tRPC Adapter Pattern

Use `permissionedProcedure({ resource, action }).input(schema).output(schema).query/mutation(...)`, resolve `ctx.em`, call application command/query, then map `AppError` via `appErrorToTrpcError`. [VERIFIED: src/server/trpc/routers/tasks.ts, src/application/error-mapping.ts]

Existing root router is declarative mount-only; keep domain routers under `src/server/trpc/routers/**` or `src/trpc/routers/**` and mount in `src/trpc/router.ts`. [VERIFIED: src/trpc/router.ts]

Context7 tRPC docs verify `initTRPC`, router/procedure definitions with Zod `.input`, and server-side callers through `createCallerFactory(appRouter)`. [CITED: https://github.com/trpc/trpc/blob/main/www/docs/server/server-side-calls.md]

### CLI/TUI Command Routing

CLI should use `createLocalCaller({ container, requireSession: true })` when command has local runtime access; existing examples: `src/cli/import.ts`, `src/cli/sprints.ts`, `src/cli/artifact.ts`, `src/cli/connectors.ts`. [VERIFIED: rg createLocalCaller]

TUI should use `buildCaller(container)` from `src/tui/index.ts`; it imports `appRouter`, `createContext`, and uses `t.createCallerFactory(appRouter)`. [VERIFIED: src/tui/index.ts:1228]

Remote/HTTP CLI paths can use existing `callProcedure("domain.procedure", input)` pattern in `src/cli/trpc-client.ts`; `src/cli/audit.ts` uses this for `audit.query` and `audit.export`. [VERIFIED: src/cli/audit.ts]

### Hono/OpenAPI Adapter Pattern

Hono API should stay a thin adapter: route schemas from application Zod schemas, `c.req.valid(...)`, `resolveEntityManager(c)`, `appContext(c)`, call application command/query, map errors through `appErrorToHttpResponse`. [VERIFIED: src/api/routes/kernel-tasks.ts]

`createPublicApi()` sets deps into Hono context, applies API-key auth and `rateLimit()`, registers kernel routes when deps exist, registers static spec routes when deps absent, and exposes `/openapi.json`. [VERIFIED: src/api/hono.ts]

Context7 Hono/Zod OpenAPI docs verify typed route schemas with request validation and response schemas; Fulcrum uses equivalent `createRoute`/`api.openapi` API from `@hono/zod-openapi`. [CITED: https://github.com/paolostyle/hono-zod-openapi/blob/master/docs/getting-started.md]

### Validation Ownership

Use Zod schemas in `src/application/{domain}/schema.ts` as source of truth. `TaskDtoSchema`, `CreateTaskInputSchema`, `UpdateTaskInputSchema`, and bulk schemas already model this. [VERIFIED: src/application/tasks/schema.ts]

Zod 4 docs verify object `safeParse` and type inference remain standard validation path; no need for Valibot/Joi/Yup in application boundary. [CITED: https://zod.dev/v4]

### Event Outbox

Use `DomainEventOutbox` entity for durable events: fields include `org`, `projectId`, `verb`, `subjectKind`, `subjectId`, `eventKey`, `payload`, `createdAt`, `processedAt`, and `attempts`; indexes enforce pending scan and event-key uniqueness. [VERIFIED: src/db/entities/platform/DomainEventOutbox.ts]

Use `writeOutboxEvent(em, input)` / worker interfaces in `src/application/outbox.ts`; do not add BullMQ, Redis, NATS, or Kafka for Phase 09.5 local-first scope. [VERIFIED: src/application/outbox.ts, 09.5-CONTEXT.md]

MikroORM docs verify Unit of Work/flush transaction semantics and QueryBuilder/repository usage; this matches Phase 09.5 no-raw-SQL requirement. [CITED: https://github.com/mikro-orm/mikro-orm/blob/master/README.md]

## Pitfalls

- Do not create another service abstraction beside `src/application/**`; that would split contracts again. [VERIFIED: 09.5-CONTEXT.md]
- Do not keep Hono static seed routes as runtime business logic when deps are available; kernel routes show current runtime app-layer delegation pattern. [VERIFIED: src/api/hono.ts]
- Do not import product-kernel store functions from adapters; architecture gate forbids this in CLI/TUI/router/API/web adapter roots. [VERIFIED: src/architecture/boundary.test.ts]
- Do not broaden raw SQL gate to all application internals; current gate targets interface/runtime `em.(persist|flush|execute|getConnection)` and ignores tests/migrations. [VERIFIED: src/architecture/no-raw-sql.test.ts]
- Do not add `@trpc/client` just because tRPC is present; current CLI/TUI parity uses in-process server-side callers. [VERIFIED: rg @trpc/client/createLocalCaller/buildCaller]
