# Phase 9.5: Cross-Phase Audit — Unmet Requirements from Phases 1–9

**Date:** 2026-05-06
**Scope:** All 9 prior phases audited for unmet promises, parity gaps, false-positive UATs, and security findings.

## CRITICAL — Must Fix in Phase 9.5

### C-01: Rate Limiting Not Implemented (Phase 8)
- **Promise:** Phase 8 SC-4, API-05 — "rate limiting" for API surface
- **Reality:** `rg 'rate.limit|rateLimit|throttle' src/` returns zero matches
- **UAT Status:** 08-UAT.md falsely claims "API-05 PASS: rate-limit behavior covered by API route and platform checks" — no code exists
- **Fix:** Add rate-limiting middleware to Hono API + tRPC surface

### C-02: Webhook Encryption Not Implemented (Phase 1)
- **Promise:** Plan 01-02, SEC-04 — webhook secrets encrypted at rest
- **Reality:** `rg 'encryptSecret|decryptSecret' src/` returns zero matches
- **Fix:** Add encryption for webhook secret storage in `src/db/entities/flags/WebhookSubscription.ts` or application layer

### C-03: Phase 3 Code Review Critical Security Findings Unresolved
- **CR-01:** Path traversal in `workspace assertWorkspacePathInOrgRoot` — attacker can escape workspace directory
- **CR-02:** XSS in HTTP dashboard via unsanitized issue identifiers
- **CR-03:** Module-level mutable counter in linear-tracker → non-deterministic IDs across restarts
- **CR-04:** App-server approval race condition — concurrent approvals can bypass gate
- **WR-05:** `sweepTerminalWorkspaces` no path validation before `rm -rf`
- **Fix:** Verify each CR finding. If still present → fix in Phase 9.5. If already fixed → document evidence.

### C-04: ARCH-12 Dual Hono API Never Merged (Phase 1)
- **Promise:** Phase 1 ARCH-12 — merge `src/api/hono.ts` and `src/product-kernel/api/router.ts` into one API with one auth middleware and one OpenAPI spec
- **Reality:** Both files still exist as separate entry points
- **Fix:** Merge during application layer creation. Single Hono adapter over `src/application/`

## HIGH — Should Fix in Phase 9.5

### H-01: Playwright Journeys Mostly Skipped (Phase 8)
- **Promise:** 14 E2E journey tests in `phase08-surface-delivery.spec.ts`
- **Reality:** Only 2 of 14 tests actually execute. 12 skip via `gotoOrSkip` guards
- **UAT Status:** Claims all pass — false positive due to skip pattern
- **Fix:** Phase 9.5 Playwright Tiered Mandatory policy (D-47) must make journeys real, not skipped

### H-02: CLI Commands Are Generated Stubs (Phase 9)
- **Reality:** 50 CLI commands exist in `src/cli/` but most are generated stubs with structural tests only
- **Evidence:** `phase09-all-domains.test.ts` verifies commands exist, not that they produce correct output
- **Fix:** Phase 9.5 must add per-command integration tests (D-58, D-61)

### H-03: TUI Screens Have No Functional Tests (Phase 9)
- **Reality:** 45 TUI screens exist but only 4 accessibility tests in `accessibility.test.ts`
- **Evidence:** No per-screen rendering or workflow tests
- **Fix:** Phase 9.5 must add per-screen tests (D-59, D-62)

### H-04: Hono API Layer Thinly Tested (Phase 8)
- **Reality:** Only `repos.api.test.ts` + `phase08-api-parity.test.ts` for entire API surface
- **Fix:** Application layer + thin adapter pattern will restructure tests. Add per-route adapter tests.

### H-05: Missing tRPC Routers for 6 Domains
- **Domains without tRPC router:** notifications, search, orchestration, repos, connectors, webhooks
- **Impact:** CLI/TUI have commands for these domains but they can't route through tRPC caller path
- **Fix:** Create tRPC routers as thin adapters over application commands/queries for all 6 domains

### H-06: Settings Has No CLI Command
- **Reality:** Web has `/settings/*` routes, TUI has settings screens, CLI has zero `settings` subcommand
- **Fix:** Add CLI `fulcrum settings` command routed through application/tRPC
