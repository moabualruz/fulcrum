# Phase 9.5: Full Architecture Overhaul + Integration Preservation - Context

**Gathered:** 2026-05-06
**Updated:** 2026-05-06 (consolidated from gray area resolutions + new discussion)
**Status:** Ready for planning

<domain>
## Phase Boundary

Establish one unified data manipulation layer (`src/application/**`) that every interface (Web, CLI, TUI, API/tRPC, workers) calls for all data operations. Eliminate all direct DB access from interfaces, consolidate dual migration systems, repair navigation/routing, and prove integration with real E2E tests. Preserve every existing feature/logic/benefit — no regressions.

</domain>

<decisions>
## Implementation Decisions

### Framework Stack (LOCKED)
- **D-01:** Keep Hono + `@hono/zod-openapi` as REST/OpenAPI adapter. No framework switch.
- **D-02:** Keep tRPC as first-party typed adapter for CLI/TUI/web.
- **D-03:** Keep `needle-di` for dependency injection. Add application-service bindings to existing container.
- **D-04:** MikroORM is sole ORM and sole migration authority.
- **D-05:** Bun runtime, SvelteKit web framework — no changes.
- **D-06:** No adoption of NestJS, Elysia, Fastify, Express, Koa, hapi, GraphQL, Effect Platform, or Encore.ts.

### Application Layer Shape
- **D-07:** Move + reshape `src/services/` into `src/application/` domain modules. Structure: `src/application/{domain}/commands.ts`, `queries.ts`, `types.ts`.
- **D-08:** Existing service classes (TaskService, DocService, SprintService, etc.) decompose into domain module exported functions. Class methods → named exports.
- **D-09:** Legacy function-based files (`tasks.ts`, `runs.ts`, `artifacts.ts`) fold into their domain modules. One place per domain.
- **D-10:** Application commands/queries are the ONLY callable boundary from interfaces. Dependency direction: `interfaces → application → ORM repositories → database`.

### Application Layer Internals
- **D-11:** Application commands open write transactions. Queries do not open write transactions.
- **D-12:** Create `src/application/errors.ts` with typed error classes: `AppValidationError`, `AppUnauthorizedError`, `AppForbiddenError`, `AppNotFoundError`, `AppConflictError`, `AppInvariantError`, `AppExternalDependencyError`. Adapters map to transport-specific codes.
- **D-13:** Shared DTO types live in application `types.ts` files. Allows tRPC/OpenAPI/CLI output to share schemas.
- **D-14:** Continue per-request/per-command EntityManager forks via needle-di container.

### Database Access Rules
- **D-15:** NO raw SQL anywhere — all DB access through MikroORM QueryBuilder or repository methods. Application query modules may use QueryBuilder for complex aggregations but NOT `em.execute()` or `.query()` raw SQL.
- **D-16:** Dashboard loader and all `+page.server.ts` files must call application query modules, not direct EM/raw SQL.
- **D-17:** Web `OrmProductDb.query()` compatibility shim must be eliminated. All callers move to application services.
- **D-18:** Deprecated `openProductDb()` must be removed. `getProductDb()` stays only as startup bootstrap, not as data access.

### Migration Consolidation
- **D-19:** MikroORM migrations are the only runtime migration authority.
- **D-20:** Product-kernel SQL migrations become legacy compatibility input only.
- **D-21:** Tests must seed through MikroORM migrations unless explicitly testing legacy upgrade path.
- **D-22:** Keep existing MikroORM migration files; do not collapse into one giant file.

### Product-Kernel Entity Coverage
- **D-23:** Create MikroORM entities for ALL product-kernel domains that currently only have raw SQL store functions: bitbucket (PRs, issues, auth), gitlab (MRs, issues, auth), repo-files (tree, blame, content), audit (events, exports).
- **D-24:** Product-kernel store functions become legacy — replaced by application domain modules backed by new MikroORM entities.

### Interface Boundaries
- **D-25:** SvelteKit `+page.server.ts` / `+server.ts` / form actions parse input, call application services, render/serialize result, map errors. No business logic, no direct DB.
- **D-26:** tRPC routers become thin adapters over application commands/queries. No business logic in procedures.
- **D-27:** Hono REST routes become thin adapters over application commands/queries.
- **D-28:** CLI keeps `createLocalCaller()` in-process tRPC path. Convert direct PGlite CLI files (`import.ts`, `sprints.ts`, `artifact.ts`) to caller/application adapters. Exception: `fulcrum db migrate` may call DB/migrator layer directly.
- **D-29:** TUI keeps `buildCaller()` in-process tRPC path. Remove direct DB enrichment from `enrichTuiCaller()` — expose required data through application/tRPC queries.
- **D-30:** Workers call application commands/queries. No direct DB from worker code.

### Authorization & Tenant Enforcement
- **D-31:** Authorization and tenant enforcement move into application command/query entrypoints.
- **D-32:** tRPC middleware, REST auth middleware, web sessions, CLI auth, TUI auth become transport authentication/context builders only.

### Validation & Schema Ownership
- **D-33:** Zod schemas owned by application domain modules. Interface adapters reference them, not own separate schemas.

### Event System
- **D-34:** Full transactional outbox pattern: MikroORM outbox entity + polling/pg-notify worker. Events persisted in same transaction as domain write, dispatched async.
- **D-35:** Application commands emit domain events once through the outbox. No interface-specific event emission.
- **D-36:** Existing `EventDispatcher` logic moves from ProductDb/product-kernel into application layer.
- **D-37:** Search indexing triggered from application events/outbox, not interface-specific writes.

### Collab/Realtime System (audited 2026-05-06)
- **D-38:** Full audit + rewire of collab system through application events.
- **D-39:** PGlite bridge (`src/subscriptions/pglite-bridge.ts`) takes direct PGlite import — must be rewired to use MikroORM/application events. `emitNotify()` calls `pglite.query()` directly — must route through application event outbox.
- **D-40:** Bell notification broadcaster's `unreadCountForUser()` must come from application query, not direct DB.
- **D-41:** Collab server room manager (`src/docs/collab/bun-ws-collab-server.ts`) is in-memory, feature-flagged — preserve existing behavior but ensure doc persistence writes go through application layer.
- **D-42:** `src/subscriptions/event-bus.ts` (in-process EventBus) is transport — stays as-is but receives events from application outbox, not from direct PGlite LISTEN/NOTIFY.

### Search & Indexing
- **D-43:** Search indexing triggered from application events/outbox. Feature writes cannot bypass search indexing.

### REST/OpenAPI
- **D-44:** Hono + `@hono/zod-openapi` remains external/stable REST/OpenAPI adapter. Thin adapter over application commands/queries.

### UI/UX
- **D-45:** Fix stale navigation and command palette. Map route/action ownership.
- **D-46:** Keep operational-density design, not marketing layouts.

### Test Architecture
- **D-47:** Playwright E2E is real and mandatory using Tiered Mandatory policy: normal CI hard-fails smoke/critical journeys; full Playwright workflows gate Phase 9.5 acceptance.
- **D-48:** Module-boundary tests that fail on raw DB access from interfaces.
- **D-49:** Service/ORM integration tests through application layer.

### Feature Preservation
- **D-50:** Every move/delete has replacement mapping, test proof, and migration note.
- **D-51:** Feature preservation inventory required before any destructive changes.

### Performance & Startup
- **D-52:** Application layer must not add measurable startup penalty vs current direct-access pattern.

### Security
- **D-53:** Application layer enforces org/project/user permissions so all interfaces share authorization behavior.

### Rollout Strategy
- **D-54:** Vertical slice first: pick one domain (e.g., tasks), build full application module, wire all interfaces, prove E2E. Then expand domain by domain.

### Policies (User-Solidified)
- **D-55:** Backend Spike Policy: Paper First. No runnable NestJS/Elysia spikes unless application-layer design fails a concrete check.
- **D-56:** ProductDb/Product-Kernel Shim Policy: Strict Allowlist. Product-kernel SQL stores are legacy-only, not runtime data API.
- **D-57:** Playwright Gate Policy: Tiered Mandatory. Smoke/critical in CI; full journeys gate acceptance.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **13 service classes** in `src/services/`: TaskService, DocService, SprintService, CommentService, WorkflowService, AutomationService, FieldDependencyService, RecurrenceService, RelationshipService, ReportService, TemplateService, plus function-based tasks.ts, runs.ts, artifacts.ts. These ARE the business logic — reshape, don't rewrite.
- **needle-di container** in `src/db/db.module.ts`: 30+ repository bindings already registered. Add application-service bindings alongside.
- **tRPC caller paths**: CLI `createLocalCaller()` and TUI `buildCaller()` already create shared context with forked EntityManager. Pattern works — just need application layer beneath.
- **EventBus** in `src/subscriptions/event-bus.ts`: Process-singleton pub/sub, 4 topic channels. Reuse as transport; feed from outbox instead of PGlite bridge.
- **Collab system**: Feature-flagged (`real-time-collab-server`), self-contained. No actual Yjs dependency — custom Bun WS room manager + provider factory. Needs 2 PGlite violation fixes but otherwise clean.

### Established Patterns
- **Singleton DB** via `initProductDb()` / `getProductDb()` in web — will be replaced by application layer but startup pattern stays.
- **Feature flags** via `FULCRUM_FEATURES` env var comma-separated — collab system uses this consistently.
- **MikroORM migrations** in `src/db/migrations/` — 30+ TypeScript migration files. This is the winning migration path.
- **Product-kernel SQL migrations** in `src/product-kernel/db/migrations/` — 40+ SQL files. Legacy path to deprecate.

### Integration Points
- **Web hooks.server.ts** — Entry point for DB initialization. Must set up application layer here.
- **tRPC routers** — Already exist but contain business logic. Must become thin adapters.
- **Hono REST routes** in `src/web/src/routes/api/` — Direct DB access in CSV import/export, etc.
- **CLI commands** — 20+ files with direct PGlite/DB access to convert.
- **TUI desktop-app.ts** — Entry point for TUI with enrichment that bypasses services.

</code_context>

<specifics>
## Specific Ideas

- Vertical slice: start with **tasks** domain as first application module. It has the most interface coverage (web, CLI, tRPC, REST) and existing TaskService to reshape.
- Domain module structure: `src/application/tasks/{commands.ts, queries.ts, types.ts}` — exported functions, not classes.
- The collab system is feature-flagged and self-contained — fix PGlite violations but don't restructure the collab architecture itself.

</specifics>

<deferred>
## Deferred Ideas

- **Yjs/Hocuspocus upgrade**: Collab server currently uses custom Bun WS room manager. Evaluating Hocuspocus v4 or native Yjs integration is a separate phase.
- **Effect Platform adoption**: May be future internal service pattern but paradigm shift — not Phase 9.5.
- **GraphQL API surface**: Not needed for first-party TypeScript adapters. Evaluate post-v1.0 if third-party integrations require it.
- **Multi-node event delivery**: Full outbox covers local-first; distributed pub/sub (Redis, NATS) is SaaS-phase work.

</deferred>
