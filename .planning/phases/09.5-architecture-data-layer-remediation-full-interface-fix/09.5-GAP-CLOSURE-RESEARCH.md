## Codebase-Specific Integration Map

Required target data flow remains:

```text
Web route/action -> src/application/{domain}/{queries,commands}.ts -> MikroORM EntityManager/repository -> database
tRPC router      -> src/application/{domain}/{queries,commands}.ts -> MikroORM EntityManager/repository -> database
Hono route       -> src/application/{domain}/{queries,commands}.ts -> MikroORM EntityManager/repository -> database
CLI/TUI          -> createLocalCaller()/buildCaller() -> tRPC/application -> MikroORM -> database
Worker/search    -> application command/query -> outbox/indexer/event-bus -> database
```

Event producer/consumer map:

| Producer | Current Risk | Target Consumer Path |
| --- | --- | --- |
| Web route/actions | Some routes open `openProductDb()` or use raw `em.getConnection()` directly | Application command writes entity plus `DomainEventOutbox`; EventBus/search/notifications consume outbox |
| tRPC/Hono adapters | Some adapters expose `ProductDb` or service wrappers | Adapter parses input and calls application module only |
| Search indexers | `ProductDb`-typed indexers and query services keep grep gates red | Application search module owns query API; indexer internals use neutral repository/query protocols or move legacy compatibility under `src/product-kernel/` |
| Doctor/connector/collab infrastructure | ProductDb types leak outside kernel | Use neutral minimal protocols (`SqlExecutor`, `LegacyDbProbe`) or product-kernel-owned adapter files |
| Tests/fixtures | PGlite/ProductDb opened ad hoc across tests | Central test-support helpers expose app/ORM fixtures without `ProductDb` naming in test files |

Files that must not break:

- `src/api/hono.ts` — single REST/OpenAPI entry point.
- `src/cli/local-caller.ts` — CLI in-process tRPC path.
- `src/tui/index.ts` — TUI caller and screen registry.
- `src/db/mikro-orm.config.ts` and `src/db/migrator-service.ts` — migration authority.
- `src/application/outbox.ts` and `src/db/entities/platform/DomainEventOutbox.ts` — event persistence.
- `src/architecture/boundary.test.ts` and `src/architecture/no-raw-sql.test.ts` — executable architecture contract.

## Dependency/Library Research

No new npm package is needed. Existing libraries and patterns cover the work:

- `@mikro-orm/postgresql` QueryBuilder and repositories replace raw `em.getConnection().execute()`.
- Existing `needle-di`/repository bindings in `src/db/db.module.ts` remain the integration pattern.
- Existing Hono app in `src/api/hono.ts` remains the REST surface.
- Existing Bun test and Playwright suites remain verification tools.

Competing platform pattern match:

- Linear/Jira-style application boundaries: UI/server adapters parse transport input, delegate mutation/query logic to domain services, and keep database adapters behind repositories.
- GitHub CLI-style local caller: CLI commands delegate to API/application callers and preserve stdout/exit contracts rather than opening persistence directly.

## Planning Decision

Do not loosen Plan 13 gates. The failure is real architecture debt. New plans must remove or relocate direct-access naming and raw SQL from every path matched by the closure commands, then rerun Plan 13 proof as a new proof-only plan.
