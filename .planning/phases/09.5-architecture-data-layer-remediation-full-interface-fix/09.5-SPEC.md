# Phase 9.5: Full Architecture Overhaul + Integration Preservation — Specification

**Created:** 2026-05-06
**Ambiguity score:** 0.07 (gate: ≤ 0.20)
**Requirements:** 15 locked

## Goal

Every interface (Web, CLI, TUI, API/tRPC, workers) calls a unified `src/application/**` layer for all data operations — eliminating direct DB access from interfaces, consolidating dual migration systems, and proving cross-interface parity with real E2E tests — while preserving every existing feature without degradation.

## Background

Phase 10 (SaaS Hardening) was blocked because Phase 1–9 accumulated architectural debt: web routes execute raw SQL via `OrmProductDb.query()`, CLI commands open PGlite directly, TUI enrichment bypasses services, tRPC routers contain business logic, and two migration systems (MikroORM + product-kernel SQL) coexist. The Integration Failure Audit (F-001 through F-006) documented 6 critical findings. 13 service classes exist in `src/services/` but interfaces bypass them. 30+ web `+page.server.ts` files import `openProductDb`. 3 CLI files call `openPglite()`. 9 TUI screens need migration. 75 MikroORM entities exist but 7 product-kernel domains lack entity coverage.

## Requirements

1. **Unified application layer**: All data operations route through `src/application/**` domain modules.
   - Current: No `src/application/` directory exists. Business logic scattered across `src/services/` (13 classes), web routes (raw SQL), CLI commands (direct PGlite), tRPC routers (inline EM access).
   - Target: `src/application/{domain}/{commands,queries,types}.ts` modules — the ONLY callable boundary from interfaces.
   - Acceptance: `rg 'openPglite|openProductDb|getProductDb|em\.find|em\.persist|em\.flush|em\.execute|conn\.execute' src/web/src/routes src/cli src/tui src/router src/api` returns zero matches in non-test files.

2. **Web route migration**: All 30+ web `+page.server.ts` and `+server.ts` files call application services instead of direct DB.
   - Current: 30+ files import `openProductDb`/`getProductDb`, `dashboard.ts` has 9 raw `conn.execute()` queries, `product-queries.ts` has 11 raw `db.query()` calls.
   - Target: Every web route imports from `src/application/` modules only. Zero raw SQL in web routes.
   - Acceptance: Every web route returns HTTP 200 for valid requests. Playwright smoke test hits all 19 nav items without SSR 500.

3. **CLI migration**: All 6 CLI files with direct PGlite/product-kernel access route through `createLocalCaller()` → application.
   - Current: `import.ts`, `sprints.ts`, `artifact.ts` call `openPglite()`. `export.ts`, `connectors.ts`, `notify.ts` import product-kernel stores.
   - Target: All CLI commands use `createLocalCaller()` tRPC path to application services. Exception: `fulcrum db migrate` may call migrator directly.
   - Acceptance: All 20+ CLI test files pass. Every CLI command produces identical output before/after migration. Exit codes unchanged.

4. **TUI migration**: TUI screens route through `buildCaller()` → application. No direct DB enrichment.
   - Current: `settings-screens.ts` imports product-kernel types. `enrichTuiCaller()` bypasses services.
   - Target: All 9 TUI screens get data via tRPC queries backed by application layer. `enrichTuiCaller()` eliminated.
   - Acceptance: All 12+ TUI test files pass. Parity test (`phase08-tui-parity.test.ts`) passes.

5. **tRPC thin adapters**: tRPC routers contain zero business logic — only parse input, call application, serialize output.
   - Current: `src/router/telemetry.ts` does direct `em.persist()` + `em.flush()`. `conflict-detector.ts` queries repositories directly. `no-match-prompt.ts` creates entities inline.
   - Target: tRPC procedures call application commands/queries. No `em.` calls in router code.
   - Acceptance: `rg 'em\.(persist|flush|find|fork|getConnection)' src/router/ --type ts | grep -v test` returns zero matches.

6. **Hono/API thin adapters**: REST routes contain zero business logic.
   - Current: 5 API routes (`kernel-audit.ts`, `kernel-tasks.ts`, `kernel-notifications.ts`, `kernel-sprints.ts`, `auth.ts`) import product-kernel stores.
   - Target: API routes call application commands/queries only.
   - Acceptance: `rg 'from.*product-kernel' src/api/ --type ts | grep -v test` returns zero matches.

7. **Migration consolidation**: MikroORM is the sole migration authority everywhere, including tests and seeds.
   - Current: Product-kernel SQL migrations (40+ files) and MikroORM migrations (30+ files) coexist. Tests seed via product-kernel path.
   - Target: MikroORM migrations only. Tests seed through MikroORM. Product-kernel SQL migrations are inert legacy files.
   - Acceptance: No runtime code calls `runMigrations()` from product-kernel. `rg 'runMigrations' src/ --type ts | grep -v product-kernel/db/migrations | grep -v test` returns zero matches for product-kernel migration runner.

8. **New MikroORM entities**: All product-kernel domains have MikroORM entity coverage.
   - Current: 7 domains (bitbucket, gitlab, github, repo-files, audit, settings/credentials, notifications) only have raw SQL store functions.
   - Target: MikroORM entities for all 7 domains. Entity count increases from 75 to ~90+.
   - Acceptance: Every product-kernel store function has a corresponding MikroORM repository method. `rg 'ProductDb' src/application/ --type ts` returns zero matches.

9. **No raw SQL**: Zero `em.execute()`, `conn.execute()`, `.query()` raw SQL calls anywhere in application or interface code.
   - Current: Dashboard has 9 raw SQL queries, product-queries has 11, notifications/defaults.ts has 2.
   - Target: All queries use MikroORM QueryBuilder or repository methods.
   - Acceptance: `rg '\.execute\(|\.query\(' src/ --type ts | grep -v node_modules | grep -v test | grep -v product-kernel/db` returns zero matches outside product-kernel legacy files.

10. **Transactional event outbox**: Domain events persisted in same transaction as writes, dispatched async.
    - Current: Events emitted through scattered `EventDispatcher` calls. PGlite bridge calls `pglite.query()` directly.
    - Target: MikroORM outbox entity. Application commands write events + outbox in one transaction. Polling/pg-notify worker dispatches. Search indexing, notifications, collab all fed from outbox.
    - Acceptance: Outbox entity exists. Creating a task via application command produces an outbox row in the same transaction. Worker processes outbox rows.

11. **Collab/realtime PGlite violation fix**: Subscriptions bridge and notification broadcaster route through application.
    - Current: `pglite-bridge.ts` imports PGlite directly. `emitNotify()` calls `pglite.query()`. `realtime-bell.ts` `unreadCountForUser()` reads DB directly.
    - Target: Event transport fed from outbox. Bell count from application query.
    - Acceptance: `rg 'PGlite' src/subscriptions/ --type ts` returns zero matches. `rg 'pglite' src/notifications/realtime-bell.ts` returns zero matches.

12. **Web navigation repair**: No orphan pages, stale nav items, dead forms, or broken command palette.
    - Current: 19 nav items in `nav-items.ts`. `/repos` may be dead (no top-level route). 5 settings items bloat primary nav.
    - Target: Every nav item links to a working route. Command palette matches actual routes/actions. Nav grouped logically.
    - Acceptance: Playwright test visits every nav item URL and gets HTTP 200 (not error page). Command palette search returns only valid actions.

13. **Cross-interface parity**: Shared feature workflows produce equivalent results across Web, CLI, TUI, API.
    - Current: Interfaces call different code paths — web uses raw SQL, CLI uses PGlite, TUI uses enriched caller.
    - Target: All interfaces call same application commands/queries. Same data, same business rules, same validation.
    - Acceptance: For tasks/sprints/runs/notifications domains: create via web, verify via CLI; create via CLI, verify via web. Data matches.

14. **Worker migration**: Workers call application commands/queries, not direct EM.
    - Current: Orchestration symphony files have 12+ `em.fork()` calls. `notifications/defaults.ts` has raw `em.getConnection().execute()`.
    - Target: Worker state mutations go through application commands. Read-side orchestration queries acceptable via EM for performance.
    - Acceptance: `rg 'getConnection\(\)\.execute' src/ --type ts | grep -v test` returns zero matches.

15. **Test infrastructure migration**: Tests and seeds use MikroORM exclusively.
    - Current: Test fixtures use product-kernel paths. Seed scripts use product-kernel SQL.
    - Target: All test infrastructure uses MikroORM migrations and repositories.
    - Acceptance: `rg 'openPglite|ProductDb' src/ --type ts | grep -v product-kernel/` returns zero matches (including test files).

## Boundaries

**In scope:**
- Create `src/application/` with ~17 domain modules (tasks, docs, sprints, runs, etc.)
- Migrate 30+ web routes from direct DB to application service calls
- Migrate 6 CLI files from PGlite/product-kernel to tRPC/application
- Migrate 9 TUI screens from direct DB enrichment to tRPC/application
- Migrate 5 API routes from product-kernel stores to application
- Migrate 4 tRPC router files from inline EM access to application calls
- Create MikroORM entities for 7 product-kernel domains (~15 new entities)
- Implement transactional event outbox (entity + worker)
- Fix PGlite violations in subscriptions bridge and notification broadcaster
- Repair web navigation (19 nav items audit + command palette)
- Convert 20+ raw SQL queries to QueryBuilder/repository calls
- Migrate test infrastructure from product-kernel to MikroORM
- Cross-interface parity tests for shared feature workflows

**Out of scope:**
- Framework switch (NestJS, Elysia, etc.) — decided: keep Hono + tRPC (D-06)
- Yjs/Hocuspocus upgrade — collab is feature-flagged, preserve only (deferred)
- GraphQL API surface — not needed for first-party TypeScript adapters (deferred)
- Multi-node event delivery (Redis/NATS) — SaaS-phase work (deferred)
- Effect Platform adoption — paradigm shift, not Phase 9.5 (deferred)
- New features — zero new capabilities, architecture fix only
- DI framework switch — keep needle-di (D-03)
- UI visual redesign — preserve operational-density design (D-46)

## Constraints

- **Zero feature degradation**: Every existing feature must work identically after migration. No "temporarily broken" paths accepted. All equal priority.
- **Framework lock**: Hono, tRPC, MikroORM, needle-di, Bun, SvelteKit. No switches.
- **Paper First spike policy**: No runnable framework spikes unless application-layer design fails a concrete check.
- **Vertical slice rollout**: Tasks domain first (most interface coverage), prove E2E, then expand domain by domain.
- **No raw SQL**: Application layer uses QueryBuilder/repository methods only. No `em.execute()` or `.query()`.
