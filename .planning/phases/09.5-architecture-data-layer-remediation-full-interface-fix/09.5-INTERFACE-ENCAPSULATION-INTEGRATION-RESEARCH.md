## Data-Flow Target Architecture

```text
Browser/SvelteKit route or form action
  -> web adapter: parse cookies/session/FormData, validate transport schema, map redirects
  -> application command/query interface
  -> EntityManager/repository/unit-of-work owned by application service
  -> entities/migrations/database
  -> application event facade writes Event + DomainEventOutbox
  -> outbox dispatcher publishes to event bus, search, notifications
  -> adapter returns DTO only

CLI command
  -> createLocalCaller/session-context factory
  -> tRPC/application caller
  -> same application command/query path

TUI screen
  -> buildCaller/session-context factory
  -> tRPC/application caller
  -> same application command/query path

Public Hono API
  -> api-key auth/rate-limit/transport schema
  -> application command/query path

tRPC router
  -> permissionedProcedure + zod schemas + app-error mapping
  -> application command/query path
```

This target keeps transport concerns in web/CLI/TUI/API/tRPC/router and persistence/business rules in `src/application/*`; `src/product-kernel/*` remains legacy/kernel internals until deleted or isolated behind application ports. [VERIFIED: src/server/trpc/routers/tasks.ts; VERIFIED: src/api/routes/kernel-tasks.ts; ASSUMED]
