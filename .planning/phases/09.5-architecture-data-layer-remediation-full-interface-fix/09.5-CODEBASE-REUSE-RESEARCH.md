# Phase 9.5 Codebase Reuse Research

Date: 2026-05-06

## Goal

Move and reuse as much existing code as possible while fixing the architecture.

This phase should avoid full rewrites of files/functions unless a function is actively harmful and cheaper to replace than extract.

Preferred remediation style:

1. Inventory existing code.
2. Identify canonical implementations.
3. Move/extract with `git mv`/`mv` where safe.
4. Add thin adapter imports.
5. Remove duplicate interface logic.
6. Add boundary tests to prevent regression.

### Existing Thin-ish tRPC Routers

Keep/reuse as adapters.

Good pattern:

- `apps/server/src/runtime/trpc/routers/tasks.ts` already mostly delegates to `TaskService`.
- `apps/server/src/runtime/trpc/routers/comments.ts`
- `apps/server/src/runtime/trpc/routers/sprints.ts`
- `apps/server/src/runtime/trpc/routers/reports.ts`
- `apps/server/src/runtime/trpc/routers/docs.ts`
- `apps/server/src/runtime/trpc/routers/relationships.ts`
- `apps/server/src/runtime/trpc/routers/workflows.ts`
- `apps/server/src/runtime/trpc/routers/templates.ts`
- `apps/server/src/runtime/trpc/routers/recurrence.ts`

Fix required:

- Routers must import from `src/application/**`, not `src/services/**`.
- Schemas should move or remain shared under `src/application/<domain>/<domain>.schema.ts`.
- Routers cannot resolve repositories directly if application services can own that.
- No router should return fallback empty arrays on missing EM for accepted features.

### Existing CLI/TUI tRPC Caller Path

Keep/reuse:

- `apps/cli/src/local-caller.ts`
- `apps/tui/src/index.ts` `buildCaller()`
- CLI command files under `apps/cli/src/commands/**`
- TUI screen files under `apps/tui/src/screens/**`

Reason:

- CLI and TUI already often use in-process tRPC callers.
- This is a good adapter pattern if tRPC routers delegate to the application layer.

Fix required:

- Remove remaining direct PGlite/ProductDb CLI files:
  - `apps/cli/src/import.ts`
  - `apps/cli/src/sprints.ts`
  - `apps/cli/src/artifact.ts`
  - any command not using `apps/cli/src/local-caller.ts`
- TUI enrichers may query DB directly for auth/status details; these must move to application/tRPC queries.

### Existing REST/Hono Routes

Keep/reuse as REST/OpenAPI adapters where possible:

- `apps/server/src/api/hono.ts`
- `apps/server/src/api/auth.ts`
- `apps/server/src/api/routes/**`
- `@hono/zod-openapi` schemas/route definitions

Fix required:

- Routes cannot import product-kernel stores.
- Routes cannot call DB directly.
- Routes call application commands/queries or tRPC callers only.
- Fallback in-memory stores in REST routes must be removed or explicitly test-only.

Example current bad pattern:

- `apps/server/src/api/routes/kernel-tasks.ts` imports product-kernel repositories and service action wrappers.

Target:

```text
apps/server/src/api/routes/kernel-tasks.ts
  -> validate OpenAPI input
  -> taskCommands.create(ctx, input)
  -> serialize output
```

## Recommended Remediation Order

### Step 1: Create `src/application`

Do not rewrite. Move the most canonical services first.

Start with tasks because it has the clearest existing service/router/CLI/TUI path.

### Step 2: Tasks Vertical Slice

Reuse:

- `src/services/TaskService.ts`
- `apps/server/src/runtime/trpc/routers/tasks.ts`
- `apps/cli/src/commands/tasks.ts`
- TUI caller path and task screens
- `src/db/entities/tasks/Task.ts`
- `src/db/repositories/tasks/TaskRepository.ts`

Fix:

- Remove duplicate `src/services/tasks.ts` raw SQL action functions or merge them into `task.commands.ts`.
- Replace REST kernel task route direct product-kernel store calls.
- Replace web board/task actions to call application/tRPC adapter.
- Add Playwright + CLI + TUI + service integration proof.

### Step 3: Sprints/Reports

Reuse:

- `src/services/SprintService.ts`
- `src/services/ReportService.ts`
- `apps/server/src/runtime/trpc/routers/sprints.ts`
- `apps/server/src/runtime/trpc/routers/reports.ts`
- CLI/TUI sprints/report command/screens.

Fix:

- Remove `apps/cli/src/sprints.ts` direct PGlite path.
- Merge `apps/web/src/lib/server/sprints.ts` into application sprints.

### Step 4: Docs/Memory/Search

Reuse existing services and routers.

Fix REST fallbacks and web page direct DB reads.

### Step 5: Repos/Artifacts/Notifications

Reuse:

- `src/services/artifacts.ts`
- repo/artifact/notification routers/routes/screens.

Fix:

- Product-kernel store usage.
- Artifact store mismatch.
- Repo route/service unconfigured states.

### Step 6: Migrations

Do not rewrite all migrations into one file manually.

Required outcome:

- One runtime migrator: MikroORM.
- Product-kernel SQL migration path disabled for runtime.
- Legacy local DB upgrade path explicit and tested.

Approach:

- Keep existing MikroORM migration files.
- Add a single compatibility migration/adopter if local product-kernel DB exists.
- Update tests to seed through MikroORM migrator, not product-kernel SQL migrator.

## Anti-Rewrite Rules

- Do not replace working CLI/TUI command surfaces if they can be repointed to application services.
- Do not rewrite all routers; thin adapters can survive.
- Do not rewrite all entities/repositories; they are the foundation.
- Do not rewrite tests wholesale; classify, then migrate useful assertions to integration/E2E.
- Do not preserve ProductDb shims as final architecture.
