## Decisions Made

- Kept the product SQL migration runner behavior available through `applyProductMigrations()` while removing the prohibited `runMigrations` runtime surface.
- Added `events.project_id` in the Phase 9.5 migration because the `Event` entity already declared it and outbox tests exposed the schema drift.
- Registered `Notification` in MikroORM config because the application unread-count query needs entity metadata.
- Used a minimal notify-client interface for the subscription bridge so PGlite and Postgres can both provide fast-path delivery without application code calling `pglite.query()`.
