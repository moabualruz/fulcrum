# Plan 60: App/Core Repository Structure Standardization

Superseded note: Plan 61 finished the workspace contract by declaring root `workspaces: ["apps/*"]`, moving web dependency resolution into root `bun.lock`, and deleting `apps/web/bun.lock`.

## Research Inputs

- Turborepo workspace docs: runnable applications belong under `apps/`; shared libraries belong under package/core areas; app packages should be package-graph leaves.
- Nx repo docs: modern Nx no longer forces one integrated-vs-package-based taxonomy, but still emphasizes clear project boundaries and independent graph nodes.
- SvelteKit project docs: SvelteKit owns an app-local `src/routes`, `src/lib`, `static`, and config set. Keep it as a self-contained app root.
- Monorepo TypeScript guidance: avoid ambiguous cross-app imports; use explicit aliases for app boundaries and shared code.
- Detailed persisted research: `09.5-60-REPO-STRUCTURE-STANDARDIZATION-RESEARCH.md`.

## Decisions

- Move runnable surfaces from root `src` to top-level `apps`:
  - `apps/web`
  - `apps/cli`
  - `apps/tui`
  - `apps/server`
- Keep core product/business layers in root `src` for this phase:
  - `src/application`
  - `src/db`
  - `src/domain`
  - supporting shared modules.
- Add app package manifests so each local surface has a named package identity.
- Keep web source/config isolated under `apps/web`, but dependency resolution is now unified in root `bun.lock`.
- Add TypeScript aliases:
  - `@/*` -> `src/*`
  - `@fulcrum/cli/*` -> `apps/cli/src/*`
  - `@fulcrum/tui/*` -> `apps/tui/src/*`
  - `@fulcrum/server/*` -> `apps/server/src/*`
  - `@fulcrum/web/*` -> `apps/web/src/*`
- Update boundary guards so no future runnable surface directories reappear directly under root `src`.
