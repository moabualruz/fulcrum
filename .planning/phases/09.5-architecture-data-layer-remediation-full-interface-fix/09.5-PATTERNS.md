# Phase 9.5 — Pattern Map

## Purpose

Concrete implementation analogs for Phase 9.5 plans. Read before executing any plan that creates `src/application/**`, rewires adapters, or removes ProductDb/product-kernel runtime paths.

## Adapter Patterns

| Adapter | Existing File | Required Shape |
|---------|---------------|----------------|
| tRPC | `apps/server/src/runtime/trpc/routers/tasks.ts` | validate input, call `src/application/**`, map AppError to tRPC error, no `em.` access. |
| REST/Hono | `apps/server/src/api/hono.ts`, `apps/server/src/api/routes/*.ts` | single Hono app, `@hono/zod-openapi` route schemas, call application commands/queries, no product-kernel stores. |
| Web loaders/actions | `apps/web/src/routes/**/+page.server.ts`, `+server.ts` | parse params/form data, call application query/command, return identical data shape. |
| CLI | `apps/cli/src/local-caller.ts`, `apps/cli/src/commands/**` | use `createLocalCaller()` for data workflows, preserve stdout/stderr/exit codes and `--json`. |
| TUI | `apps/tui/src/index.ts`, `apps/tui/src/screens/**` | use `buildCaller()` data queries; remove `enrichTuiCaller()` direct DB enrichment. |
| Workers | `src/orchestration/symphony/**`, `src/notifications/**` | state mutations through application commands; read-only EM allowed only behind application query or explicitly documented performance path. |

## Data Flow

```
Web loader/action -> src/application/{domain}/{queries,commands}.ts -> MikroORM repository/entity -> database
tRPC procedure    -> src/application/{domain}/{queries,commands}.ts -> MikroORM repository/entity -> database
Hono route        -> src/application/{domain}/{queries,commands}.ts -> MikroORM repository/entity -> database
CLI command       -> createLocalCaller() -> tRPC -> application -> MikroORM -> database
TUI screen        -> buildCaller()       -> tRPC -> application -> MikroORM -> database
Worker            -> application command/query -> MikroORM -> outbox/EventBus/search/notifications
```

## Error Taxonomy Pattern

Application errors in `src/application/errors.ts`:
- `AppValidationError` → tRPC: `BAD_REQUEST`, Hono: 400, CLI: exit 2, TUI: inline message
- `AppUnauthorizedError` → tRPC: `UNAUTHORIZED`, Hono: 401, CLI: exit 1, TUI: redirect to auth
- `AppForbiddenError` → tRPC: `FORBIDDEN`, Hono: 403, CLI: exit 1, TUI: "Access denied"
- `AppNotFoundError` → tRPC: `NOT_FOUND`, Hono: 404, CLI: exit 1, TUI: "Not found"
- `AppConflictError` → tRPC: `CONFLICT`, Hono: 409, CLI: exit 1, TUI: "Conflict"
- `AppInvariantError` → tRPC: `INTERNAL_SERVER_ERROR`, Hono: 500, CLI: exit 1, TUI: crash log
- `AppExternalDependencyError` → tRPC: `INTERNAL_SERVER_ERROR`, Hono: 502, CLI: exit 1, TUI: "Service unavailable"

## Authorization Boundary Pattern

Transport layer (tRPC middleware, Hono middleware, CLI auth, TUI auth) → extracts user/org context.
Application layer → enforces permissions at command/query entrypoints.

```ts
// src/application/tasks/commands.ts
export async function createTask(ctx: AppContext, input: CreateTaskInput): Promise<TaskDto> {
  assertOrgMember(ctx.userId, ctx.orgId); // throws AppForbiddenError
  // ... business logic
}
```

Interfaces NEVER check business permissions — only transport authentication.

## Zod Schema Ownership Pattern

Schemas live in `src/application/{domain}/schema.ts`. Interface adapters import and reference them.

```ts
// src/application/tasks/schema.ts
export const CreateTaskSchema = z.object({ title: z.string().min(1), projectId: z.string().uuid() });
export type CreateTaskInput = z.infer<typeof CreateTaskSchema>;

// apps/server/src/router/tasks.router.ts (adapter)
import { CreateTaskSchema } from '../../application/tasks/schema';
tasks.input(CreateTaskSchema).mutation(({ input, ctx }) => createTask(ctx, input));
```

## Transactional Outbox Pattern

```ts
// src/application/outbox/outbox.entity.ts
@Entity()
export class DomainEventOutbox {
  @PrimaryKey() id!: string;
  @Property() aggregateType!: string;
  @Property() aggregateId!: string;
  @Property() eventType!: string;
  @Property({ type: 'json' }) payload!: Record<string, unknown>;
  @Property() createdAt: Date = new Date();
  @Property({ nullable: true }) processedAt?: Date;
}

// In application command (same transaction):
await em.transactional(async (txEm) => {
  txEm.persist(task);
  txEm.persist(txEm.create(DomainEventOutbox, {
    aggregateType: 'task', aggregateId: task.id,
    eventType: 'task.created', payload: { taskId: task.id, title: task.title }
  }));
});

// Worker polls unprocessed rows, dispatches to EventBus, marks processedAt.
```

## QueryBuilder Migration Pattern (replacing raw SQL)

Before (raw SQL):
```ts
conn.execute<CountRow[]>(`SELECT count(*)::text AS c FROM tasks WHERE org_id = $1 AND status NOT IN ('completed','cancelled')`, [orgId])
```

After (QueryBuilder):
```ts
const count = await em.createQueryBuilder(Task, 't')
  .where({ org: orgId, status: { $nin: ['completed', 'cancelled'] } })
  .getCount();
```

## Command/Query Function Signatures

```ts
// src/application/tasks/commands.ts
export async function createTask(em: EntityManager, ctx: AppContext, input: CreateTaskInput): Promise<TaskDto> { ... }
export async function updateTask(em: EntityManager, ctx: AppContext, taskId: string, input: UpdateTaskInput): Promise<TaskDto> { ... }
export async function deleteTask(em: EntityManager, ctx: AppContext, taskId: string): Promise<void> { ... }

// src/application/tasks/queries.ts
export async function getTask(em: EntityManager, ctx: AppContext, taskId: string): Promise<TaskDto> { ... }
export async function listTasks(em: EntityManager, ctx: AppContext, filters: TaskFilters): Promise<TaskDto[]> { ... }
```

Commands use `em.transactional()`. Queries use read-only EM fork. Both receive `AppContext` for auth.
