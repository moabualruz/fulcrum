# Plan 60 Research: Repository Structure Standardization

Superseded note: Plan 61 unified `apps/*` under the root Bun workspace and removed `apps/web/bun.lock`. Root `bun.lock` is now the package graph source of truth.

## External Patterns Checked

### Turborepo

- Source: https://turborepo.com/repo/docs/handbook/workspaces
- Relevant pattern: package-manager workspaces commonly group runnable applications under `apps/` and shared libraries under `packages/` or another shared source area.
- Fulcrum decision: place runnable local surfaces under `apps/cli`, `apps/tui`, `apps/web`, and `apps/server` so each interface is a first-class app boundary instead of being mixed into root `src`.

### Nx

- Source: https://nx.dev/docs
- Relevant pattern: modern Nx focuses on explicit project graph nodes and enforceable boundaries rather than one required repo style.
- Fulcrum decision: add app-level package manifests and TypeScript aliases so local clients and server adapters become explicit project nodes, while shared core remains in root `src` for this phase.

### SvelteKit

- Source: https://svelte.dev/docs/kit/project-structure
- Relevant pattern: SvelteKit apps own their app-local `src/routes`, `src/lib`, `static`, and config files.
- Fulcrum decision: keep the web client self-contained at `apps/web` with its SvelteKit config, static assets, lockfile, tests, and generated output under that app root.

### Monorepo TypeScript Guidance

- Source: https://monorepo.tools/typescript
- Relevant pattern: cross-project imports should be explicit and tool-readable; ambiguous relative imports across app boundaries make refactors brittle.
- Fulcrum decision: use explicit aliases for shared core and app boundaries:
  - `@/*` -> `src/*`
  - `@fulcrum/cli/*` -> `apps/cli/src/*`
  - `@fulcrum/tui/*` -> `apps/tui/src/*`
  - `@fulcrum/server/*` -> `apps/server/src/*`
  - `@fulcrum/web/*` -> `apps/web/src/*`

## Codebase Integration Findings

### Current Producer/Consumer Map

| Producer | Consumers | Required Stable Path |
|---|---|---|
| CLI binary | user shell, installer, release scripts, hook recipes | `apps/cli/src/main.ts` |
| CLI command dispatcher | CLI tests, generated command snapshots, local app callers | `apps/cli/src/index.ts` |
| TUI client | TUI command, TUI parity tests | `apps/tui/src/index.ts` |
| Web app | `fulcrum web`, SvelteKit tests, Playwright tests | `apps/web` |
| Local server adapters | web API routes, REST tests, tRPC tests, CLI/TUI local callers | `apps/server/src` |
| Application layer | web/CLI/TUI/server adapters | `src/application` |
| Persistence layer | application services and composition roots only | `src/db` |

### Files That Must Not Break

- `package.json` binary and scripts
- `scripts/build-all.ts`
- `scripts/ci.ts`
- `scripts/cli/codegen.ts`
- `scripts/ci/codegen.ts`
- `scripts/check-module-boundaries.ts`
- `apps/web/svelte.config.js`
- `apps/cli/src/index.ts`
- `apps/server/src/trpc/router.ts`
- `src/architecture/repo-structure.test.ts`
- `src/architecture/boundary.test.ts`

### Data Flow After Standardization

Local clients remain local-first:

1. CLI and TUI invoke local callers or application services in-process.
2. Web route handlers run inside the local SvelteKit app and call local server/application adapters.
3. Server adapters expose Hono REST and tRPC transport, but business workflows remain in `src/application`.
4. Persistence stays behind application/composition boundaries in `src/db`.

### Constraints

- Root workspaces are allowed after Plan 61 because lockfile ownership is intentionally unified in root `bun.lock`.
- Do not move business/domain code into `apps`; apps must remain invocation/visualization/transport layers.
- Do not flatten SvelteKit internals out of the app root; SvelteKit expects app-local config and source layout.
- Do not introduce remote-server assumptions. All clients must keep local execution paths.
