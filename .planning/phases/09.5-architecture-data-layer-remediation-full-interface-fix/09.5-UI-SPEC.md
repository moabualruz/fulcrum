Accent (`--primary`) reserved for:
1. Active/selected sidebar nav item background + text

3. Focused input ring (`--ring`)
4. Command palette selected result highlight

Accent is NOT used on: hover states (use `--accent` / `--sidebar-accent` muted hover instead), info labels, icons in resting state, table headers.

Dark mode: tokens defined in `.dark` block in app.css — preserved as-is, no changes.

## Page State Requirements

Every page affected by loader migration must maintain all four states:

| State | Implementation |
|-------|---------------|
| Loading | SvelteKit streaming `+page.server.ts` `load()` return + Svelte `{#await}` or skeleton via `<Skeleton>` shadcn component |
| Empty | `{#if items.length === 0}` block — see Copywriting Contract below |
| Error | SvelteKit error boundary (`+error.svelte`) + inline field errors from `AppValidationError` mapped to form |
| Loaded | Normal render — no change to existing layout |

SSR contract: loader migration (direct DB → application service) must produce identical `data` shape. Pages must not change. Visual regression = zero.

- Error display: field-level errors from `AppValidationError` map to `aria-describedby` error message below input

- Row height: 40px (operational density)
- Header: `text-xs font-medium text-muted-foreground uppercase tracking-wide`
- Sortable column indicator: Lucide `ArrowUpDown` (16px) inline after header text

## Huashu Design Application

Phase 9.5 uses Huashu Design as a review lens for operational density, not a complete redesign.

Principles applied:
1. **Information density first** — 14px body, 40px table rows, 36px nav items. No whitespace inflation.
2. **Progressive disclosure** — settings grouped under single "Settings" nav entry; sub-settings navigated in-panel.
3. **Status-surface alignment** — empty/error/loading states always visible at the same layout position as loaded content (no layout shift).
4. **Monochromatic base + single accent** — zinc palette with near-black primary. No decorative color usage.
5. **Icon + label always** — no icon-only nav in expanded sidebar state. Screen reader accessible.

Huashu review checklist (executor must verify before marking phase done):
- [ ] No page uses a hero/marketing layout (centered large text, full-width image headers)
- [ ] All data tables have at minimum: sort affordance, empty state, row actions
- [ ] All forms have field-level error display
- [ ] Sidebar groups are labeled with muted text headers
- [ ] No nav item links to a non-existent route
- [ ] Command palette results match actual available routes/actions
- [ ] All pages render without SvelteKit `+error.svelte` under normal SSR conditions after loader migration

## CLI UX Contract

Phase 9.5 migrates CLI commands from direct PGlite to application services via `createLocalCaller()` tRPC path. The following UX contracts MUST be preserved.

### Command Signature Preservation
Every existing CLI command must retain its current flags, arguments, and help text after migration. No breaking changes to:
- `fulcrum import` — `--format`, `--project`, `--input`, `--column-map`, `--json`, `--dry-run`
- `fulcrum sprints` — list/create/start/close subcommands
- `fulcrum artifact` — CRUD subcommands
- `fulcrum export` — `--format`, `--project`, `--output`
- `fulcrum mcp` — register/list/probe subcommands
- `fulcrum db` — migrate/seed/status subcommands (exception: may call migrator directly per D-28)
- `fulcrum notify` — send/list subcommands
- `fulcrum doctor` — health check subcommands

### Output Format Contract
- **stdout:** Human-readable by default. `--json` flag produces machine-parseable JSON on commands that support it.
- **stderr:** Error messages only. Format: `fulcrum <command>: <message>` (existing pattern).
- **Exit codes:** `0` = success, `1` = application error, `2` = usage/argument error. No change.
- **Interactive vs non-interactive:** Commands that prompt must detect TTY and fail gracefully in non-interactive mode (piped input).

### CLI Test Contract
- **20+ existing test files** in `apps/cli/src/*.test.ts` — all must pass after migration.
- **Integration tests:** CLI commands that previously called PGlite directly must produce identical output when routed through application services.
- **Exit code tests:** Every error path must verify correct exit code (1 or 2).
- **JSON output tests:** Commands with `--json` must produce parseable JSON with stable field names.
