## Filing an issue

Before filing, check [HANDOVER.md §6](../HANDOVER.md) to see if the item is already tracked. Outstanding work is listed there with scope and context. Items already in HANDOVER are either in-flight or explicitly deferred — a duplicate issue is noise.

For genuinely new bugs or proposals:
- Describe the observed behavior and the expected behavior.
- Include `fulcrum doctor --json` output (redact secrets before pasting).
- Include the `fulcrum --version` or the git SHA (`git rev-parse --short HEAD`) from your build.
- If a skill is wrong, include the tool's `--help` output showing the correct behavior and the skill's actual content (`fulcrum skills lint <path>` output).

## Commit format

Fulcrum uses [Conventional Commits](https://www.conventionalcommits.org/). Every commit must match:

```
type(scope): subject
```

**Types:**

| Type | Use for |
|---|---|
| `feat` | New capability shipped to users |
| `fix` | Bug fix |
| `docs` | Documentation only |
| `refactor` | Code change with no behavior change |
| `test` | Adding or fixing tests |
| `chore` | Maintenance (deps bump, config, scripts) |
| `perf` | Performance improvement |
| `build` | Build system or compiler changes |
| `ci` | CI configuration changes |

**Scope** (optional but encouraged): the file or layer touched (`install`, `hooks`, `skills`, `mcp`, `doctor`, `upstream-skills`, `registry`, `compress`, `eval`, `caveman`).

**Subject:** imperative, lowercase, ≤50 chars, no trailing period.

**Body** (optional): use for the *why* when it isn't obvious from the subject. What failure mode does this fix? What decision was made and why? Link to HANDOVER §4 if this closes a decision item.

**Examples:**

```
feat(hooks): add detection-aware enable/disable with --all flag

fix(doctor): populate caveman section from config + per-agent install

docs(mcp): add cloudflare suite auth table (HANDOVER §6.0b)

test(install): cover assertNotAgentsPath guard

chore(deps): bump bun to 1.2.8
```

`git-cliff` parses these to generate `CHANGELOG.md`. A malformed commit silently breaks the CHANGELOG release automation.

## Branch policy

- Branch off `main`.
- One logical change per branch. Bisect granularity matters.
- Fast-forward merges to `main` — no merge commits, no squash-merge divergence.
- No PRs in current operating mode (see [HANDOVER.md §5](../HANDOVER.md)). Direct fast-forward merge is the workflow until the project switches modes.
- Branch naming: `feat/<slug>`, `fix/<slug>`, `docs/<slug>`, `refactor/<slug>`, matching the conventional commit type.

## CI requirement

`bun run ci` must be fully green before any merge. Six stages must all pass:

```
1. fulcrum install --dry-run       # install smoke
2. bun run typecheck               # tsc --noEmit (strict mode, no any)
3. bun test                        # full test suite
4. bun run build:all               # 5 platform binaries
5. bun run skills:lint             # 29 skills, all pass frontmatter union rules
6. bun run compress -- --check     # hard gate: every .md must have .original.md sibling
```

Stage 6 is a hard gate — CI fails if any markdown file that should be compressed lacks its `.original.md` sibling. This covers: `docs/*.md`, `skills/*/SKILL.md`, `skills/*/references/*.md`, `rules/AGENTS.md`, `AGENTS.md`, `skills/SOURCES.md`. Exceptions: `HANDOVER.md` and `README.md` are not compressed (they serve cold-read audiences).

Run CI locally before pushing:

```bash
PATH="$HOME/.bun/bin:/opt/homebrew/bin:$PATH" bun run ci
```

## Caveman compression contract

Every new or edited markdown file covered by the compress gate must follow the two-file pattern:

```
docs/my-new-doc.original.md   ← human-edit form; the source of truth you edit
docs/my-new-doc.md            ← compressed agent-read form; generated by bun run compress
```

**Workflow for adding a new doc:**

1. Write the verbose version at `<path>.original.md`.
2. Run `bun run compress` — this creates `<path>.md` (compressed) and leaves `<path>.original.md` intact.
3. Commit both files.
4. To update the doc: edit `.original.md`, re-run `bun run compress`, commit both.

**Never edit the compressed `.md` directly.** Your edits will be overwritten on the next `bun run compress` run. Always edit the `.original.md`.

**CI enforces this.** `bun run compress -- --check` exits 1 if any covered `.md` lacks an `.original.md` sibling. This blocks merge.

The compress toolchain is `scripts/compress-with-caveman.sh`, which calls the caveman compress module. Caveman must be installed: `claude plugin install caveman@caveman`.

## Skill content correctness

Fulcrum enforces a strict policy: **never re-author content the vendor already publishes.**

- If a tool vendor ships an official SKILL.md (in their repo, under their org), that file must be mirrored verbatim into agents the vendor does not ship for. Do not rewrite, summarize, or "improve" it — that introduces drift and authoring debt.
- For tools with no official vendor skill, author a skill in `skills/<name>/` verified against the tool's `--help` output or upstream README. Do not rely on memory or training data for flag values, defaults, or subcommands.
- `fulcrum skills lint` validates frontmatter shape and the five required `## `sections. It does **not** validate that flags, default values, or subcommands are accurate. Content correctness is the author's job.
- Previous bulk authoring found a 46% content-error rate. Verify inline before submitting.

See [docs/mcp.md §1](mcp.md) for the official-first policy and mirror contract. See [docs/skills.md §5](skills.md) for the authoring template and [docs/skills.md §7](skills.md) for the verification harness.

## Code style

### TypeScript

- Strict mode (`"strict": true` in `tsconfig.json`). No `any`.
- No `// @ts-ignore` without an accompanying comment explaining why it is unavoidable.
- No `as unknown as T` casts without a type-guard.
- Prefer `const` over `let`; never `var`.
- All public functions and exported types have explicit return types.

### Operations must be idempotent

Every install, splice, or register operation must be safe to run multiple times with the same result. This is a hard requirement — `fulcrum install` is routinely re-run after updates. Tests must cover the idempotency case (run twice, assert same outcome).

### Hooks must fail-open

If a hook's required external tool is missing, exit 0 (log to stderr). A missing `gitleaks` should not break the session. The only exception is `lint-gate` — it exits 2 intentionally when lint violations are found, but exits 0 when the linter is not installed.

### Never write to `~/.agents/`

`~/.agents/` is a shared folder that pollutes every agent's context. Use only agent-specific paths. The `assertNotAgentsPath()` function in `install.ts` enforces this at runtime; any code path that might write to a configurable path must call it. See [HANDOVER.md §4](../HANDOVER.md) decision record.

### File I/O patterns

- Use `~/.fulcrum/state/<project-slug>/` for per-project state.
- Use `~/.fulcrum/state/global/` for cross-project state.
- Use `/tmp/<slug>.*` for ephemeral hook state (index SHA cache, test-on-edit log).
- Never write to the working repository from a hook. Hooks are observers, not participants.

## Reviewer expectations

A well-formed contribution has all of the following:

**Tests in scratch HOME.** Tests that touch the filesystem use a scratch HOME (`mkdtemp`) and restore `process.env.HOME` in cleanup. No tests write to the real `~` during `bun test`.

**Doctor delta documented.** If the change affects what `fulcrum doctor` reports (new tool, new layer, new MCP, changed verdict logic), the `DoctorReport` interface and `apps/cli/src/doctor.ts` are updated, and a test covers the new section.

**Doc delta committed.** If the change affects user-visible behavior, one of the per-topic docs in `docs/` is updated. If a new OS layer lands, `docs/<layer>.md` is created (per [HANDOVER.md §6 cross-layer rules](../HANDOVER.md)) and added to the README documents table and HANDOVER §9.

**Compress gate passes.** Any new `.md` file in `docs/`, `skills/`, or `rules/` that is not exempt (HANDOVER.md, README.md) has an `.original.md` sibling. `bun run compress -- --check` exits 0.

**Conventional commit message.** Subject ≤50 chars, type matches the change, scope is present when non-obvious.

**No new scope without approval.** If you discover a useful improvement while working on an approved task, propose it first (name it, describe impact, what it touches) and wait. See [AGENTS.md conventions](../AGENTS.md).
