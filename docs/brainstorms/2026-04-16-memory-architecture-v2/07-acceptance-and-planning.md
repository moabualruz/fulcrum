## 11. Acceptance Criteria

The feature is "done" when all of the following are true:

1. Every hook write in §1 produces a row with non-NULL `kind`, `tier`, and `provenance` when flag is on.
2. Every hook write path is covered by a sanitization-roundtrip test: planted fence / injection / credential / invisible-Unicode never reaches the DB in raw form.
3. Every non-primary `context_type` that attempts to write a non-`delegation_summary` kind → silently dropped, telemetry event recorded.
4. `recall_memory` MCP tool insertions into `memory_recall_events` are 1:1 with returned results.
5. `fulcrum dream --phase=deep` on a corpus containing ≥3 short-term rows meeting thresholds promotes ≥1 to durable AND appends to the correct native project-context file AND deletes the short-term row.
6. `PreCompact` extractor on a ≥200-turn Claude session yields ≥1 `pre_compact_extract` memory per compaction event.
7. `update_task(status=completed)` followed by session Stop produces exactly one of `task_outcome` or `session_summary` (not both) with matching `run_id`.
8. Gemini `BeforeAgent` stub is deleted from `agent-integration/gemini/hooks/hooks.json`.
9. Pi cockpit writes `file_patch` memories for a Pi-dispatched Write/Edit, reachable via `recall_memory`.
10. Token audit: agents running a representative task workload with flag on show no auto-injected memory content in their prompts (no text wrapped in `<fulcrum-recall>` that the agent didn't request via `recall_memory`).
11. Opening `{globalDataDir()}/memory/` in Obsidian shows a working graph view with wikilinks resolved, tags navigable, and Dataview queries over frontmatter functional.
12. `query_memory(linked_to: '[[decision:X]]')` returns all pages backlinking to X in O(log n) via the `memory_wikilinks` index.
13. `query_memory(tags: ['auth'], kind: ['file_patch'])` returns expected matches without touching L2.
14. No short-term entry has `embedded=1`; every durable entry has `embedded=1` after Dreaming deep phase completes.
15. Dreaming light phase on a vault with a dangling `[[missing:X]]` link reports it in `light/YYYY-MM-DD.md`.
16. Dreaming deep phase on a candidate that contradicts an existing durable entry produces a new durable entry with `supersedes` set and the old entry marked replaced (not deleted).
17. **PCI watcher is a process singleton.** Two concurrent `start_agent_run` calls against the same project root result in ONE chokidar instance. Refcount observable via `http://localhost:4721/content-index`. Second `start` does not emit duplicate `content_change` events.
18. **PCI watcher survives session churn.** Starting and stopping 10 back-to-back sessions in <30s produces at most ONE watcher init + ONE watcher teardown event.
19. **`search_code(text: 'sessionId', hybrid: true)`** returns chunks from `packages/auth/*` ranked by RRF across FTS + vec + symbol hits.
20. **`code_context(symbol: 'resolveSessionId')`** returns callers, callees, imports, nearest-neighbor chunks, **and** any durable memory entries reachable via `about` / `mentions` edges.
21. **Incremental ingest.** Touching `a.ts` re-embeds only its changed chunks, not the whole file; unchanged sibling files do not re-embed.
22. **Cross-process safety.** Starting a second `fulcrum serve mcp` in a different terminal for the same project root does NOT start a second watcher; it reads the SQLite store while the first process owns change detection. Lock file at `{globalDataDir()}/project-index-<hash>.lock` reflects the owning PID.
23. **Kuzu graph unifies memory + code.** `code_context(symbol: X)` and `recall_memory(query: "decisions about X")` both succeed and return results linked via Kuzu `about` edges; neither sees an empty result for a known-linked pair.
24. **Central store invariant.** The only SQLite database file on disk is `{globalDataDir()}/db/fulcrum.db`. There is no project-local or workspace-local DB. Starting two sessions in two different projects shares this one file; queries scope via `workspace_id` + `project_id` predicates.
25. **Portable pathing.** Every `code_files.rel_path`, `memories.vault_path`, and memory frontmatter `file_paths` value is project-root-relative. Grep of the central DB for `/home/`, `/Users/`, or `C:\\` returns zero matches outside the `projects.root_path` / `root_realpath` columns.
26. **Project move.** `fulcrum project relocate` updates `projects.root_path` and `projects.root_realpath`; after move, all `recall_memory` / `search_code` / `code_context` results still resolve correctly when joined with the new root.
27. **Scoped search — project (default).** `search_code(text: 'X')` issued from a run under `project_id=P1` returns only chunks with `project_id=P1`. No leakage from other projects in the central DB.
28. **Scoped search — workspace.** `search_code(text: 'X', scope: 'workspace')` returns chunks across all `project_id` rows sharing the run's `workspace_id`.
29. **Scoped search — global.** `recall_memory(query: 'X', scope: 'global')` issued from an authorized role returns cross-workspace results, each annotated with `workspace_id` + `project_id`. Issued from an unauthorized role, returns a policy-denied result (§12.12).
30. **Safety floor enforced.** `recall_memory(query: 'X')` where all candidates score below `min_score` returns `[]` with `reason: "below min_score"` — never near-miss noise.
31. **Global pointer pre-filter.** `scope: 'global'` queries that produce zero hits in the pointer collection (`global_index.md`) short-circuit without fanning into full FTS + vec + graph across all projects.
32. **Write-ahead log round-trip.** Writing a memory, losing L1, and running `fulcrum memory replay-wal` re-derives the row from the WAL + L0 vault. Memory contents sha256-match pre-loss.
33. **Normalize-version silent rebuild.** Bumping the sanitizer version and restarting the MCP server triggers re-processing of rows where `normalize_version < current` in the background; no restart downtime.
34. **WAL redaction.** Running `grep -r 'password' {globalDataDir()}/db/wal/*.jsonl` returns zero matches even if a raw memory write contained a credential (sanitizer strips before write, WAL records only sha256).
35. **Benchmark floor.** Running Fulcrum's recall pipeline on the LongMemEval corpus produces R@5 ≥ 90% on the short-term tier (prior art baseline 96.6% — we allow regression margin while we're still tuning hybrid RRF weights).
36. **Cold install works end-to-end.** Fresh install, no agent has created tasks / teams / workflow_runs, no operator has toggled rules, Pi cockpit not started. Agent can: start a session, write a memory via hook, edit a file (PCI indexes it), call all 6 recall tools successfully. `list_tasks` returns `[]`, not an error.
37. **No auto-activation.** Starting the MCP server never creates a task, team_instance, workflow_run, or spawns the Pi cockpit. Running a baseline agent session produces no `tasks` / `team_*` / `workflow_runs` rows unless the agent explicitly called a creation tool.
38. **Action surface is stable across paths.** Every action (`recall_memory`, `create_task`, `invoke_team`, `run_workflow`, etc.) is reachable via `fulcrum action exec <name>` at all times (CLI-first). When MCP is added, a selectively filtered subset appears as MCP tools with matching names. `invoke_team` returns role-policy-denied for non-CoS roles (not feature-unavailable). `create_task` always succeeds when called. Agent doesn't need to know "is task tracking on?" — the action is always there.
39. **Pi cockpit requires explicit command.** `fulcrum pi cockpit start` is the only way to spawn the Pi process and bind its hooks. `fulcrum pi cockpit stop` cleanly unbinds. Server restart never re-spawns it; must be invoked again. Baseline installs have cockpit code on disk but no running process.
40. **`project_context` is shape-stable across installs.** Same tool call against a cold install vs. an install with dozens of tasks / teams / workflow_runs returns the same response shape; the cold response simply omits groups whose source tables are empty — no null fields, no error metadata, no placeholders.
41. **Workflows are always loadable.** `fulcrum workflow list` returns all workflow definitions on disk at all times (from `workflows/*.yaml` + any installed extensions). `run_workflow` with an unknown name errors; with a known name, creates a `workflow_run` row and proceeds. Nothing auto-runs.
42. **Policy rules are all defined; `enabled` is the only knob.** `fulcrum policy rules list` returns every rule in the distribution with its current `enabled` state. Enabling a rule is operator-only; secret-scan always-on. Agents cannot toggle rules.
43. **`list_activations` MCP tool (if built) is read-only.** Returns `{pi_cockpit, enabled_rules, available_workflows, installed_skills}` without side effects. Calling it never activates anything.
44. **CLI-first coverage invariant.** Every capability is reachable via `fulcrum action exec <name>`. `fulcrum action list` returns the complete surface. MCP is a selectively filtered overlay — every MCP tool maps 1:1 to a CLI action; no MCP-only capabilities exist.
45. **MCP is opt-in install.** Fresh install of Fulcrum on a CLI-first-capable agent (Claude Code / Gemini / Codex / OpenCode / Pi) produces no MCP server process unless the user runs `fulcrum serve mcp`. Hooks configured in the agent host's native settings drive everything via CLI shell-outs.
46. **Parity between CLI and MCP paths.** For every action exposed through both paths, the same domain function executes (same sanitize, same WAL, same guard, same Kuzu reducer). Behavior is path-identical; only the transport differs.
47. **External sync refs visible.** With a Plane-synced task T, `project_context(task_id: T).related.external_refs` returns the shadow ticket metadata (system, external_id, url, last_synced_at). `sync_status` action returns queue depth + pending conflicts.
48. **Git PR → code chain navigable.** `git_pr_context --pr N` returns commits, files touched, reviews, linked tasks. `project_context(file: X)` includes the last landed PR via `landed_in` → `part_of` traversal.
49. **Adapter telemetry.** Every `agent_run` has `executed_by` edge to an `agent_adapter` node. `list_adapters` action returns the registry. Analytics can group-by adapter.
50. **Prose ingestion covers in-repo markdown + configs.** PCI watcher ingests `README.md`, `AGENTS.md`, `CLAUDE.md`, `CHANGELOG.md`, `docs/**/*.md`, `package.json`, `tsconfig.json`, `*.yaml` config. Chunks land in `code_chunks` with `kind='prose'` and are reachable via `search_code(lang: ['md'])` or `search_code(text: 'X')`.
51. **Monitor graph endpoints work.** `GET /graph/query?cypher=...` returns JSON results. `GET /project-context?file=X` mirrors the action. Dashboard "Graph" tab renders a force-directed view of the current project.
52. **CoS context is a graph query, not a store.** `build_cos_context` runs a parameterized graph query; result is cached 5min, invalidated on task/run/block events. No table stores the rendered snapshot.
53. **A2A card stability.** `fulcrum action exec get_agent_card --role software_engineer` returns a valid Google A2A AgentCard JSON derived from current `agent_definitions` row. Edits to the definition reflect in the card immediately.
54. **Policy audit.** `policy_audit --from T1 --to T2` returns a decision log with rule_id, tool_call, decision, reason. `project_context(run_id: R).related.policy_events` exposes per-run policy decisions.
55. **Team membership traversal.** `project_context(team_instance_id: T).members` returns `[{role_slot, agent_profile, joined_at, left_at?}]` via `member_of` edges.
56. **Artifact conformance.** `project_context(artifact_id: A).related.contract` returns the contract the artifact was produced against, with validation status.
57. **Analytics reachable.** `get_analytics --dimension project --from T1 --to T2` returns the rollup rows for the scope. Cold install returns empty (no rollups yet); enabled `analytics-enabled` rule starts producing rows.
58. **Event-bus taxonomy enforced.** Every event type listed in §1.5 has a reducer with a registered event-type constant. A PR that adds a reducer without a matching constant fails CI.
59. **Orthogonal tables deliberately absent.** Grep of Kuzu graph reducers against `advisory_locks` / `display_id_sequences` / `agent_state_projection` / `schema` / `embedding_registry` returns no hits. These are documented as orthogonal in §1.5.

## 12. Open Questions for Planning (ce:plan resolves)

Only items where direct research adoption is ambiguous or implementation-level decisions remain. Defaulted to reference implementations values below; planning may revisit.

1. **PreCompact extractor model.** Default: Claude Haiku. Fallback chain per prior art: configured → session's current model → Haiku → skip. Timeout: 5s.
2. **Dreaming thresholds tuning.** Default: prior art's published values (≥3 / ≥3 / ≥0.8 / half-life 14d / maxAge 30d). Before first promotion, a one-time offline sweep on the 249 imported sessions reports what these thresholds would promote — operator reviews before enabling cron.
3. **Sanitizer false-positive tolerance.** Default: conservative. Redact only exact-match fence markers + clear-signature credentials. Heuristic injection detection logs an event but does not redact unless pattern confidence is high. Tunable per-install via config.
4. **Claude Code native MEMORY.md integration.** Dreaming appends to `~/.claude/projects/<slug>/memory/MEMORY.md` — this is the user's private auto-memory file (per `~/.claude/CLAUDE.md`). Verify this is the right target and does not conflict with Claude Code's own memory management.
5. **Pi context_type derivation.** When Pi is the user-facing runtime → `primary`. When Pi is spawned by chief_of_staff → `subagent` with `parent_run_id`. When Pi runs a scheduled trigger → `cron`. Planning confirms the dispatch points for each.
6. **Kind extensibility.** Enum should be an open set, not a closed enum, to allow future additions (`review_comment`, `merge_outcome`, etc.) without migration churn. Planning picks: TEXT with CHECK constraint vs. separate kinds table.
7. **Code embedding on ingest — cost guardrails.** A fresh `ingestProject` on a large repo can be thousands of embedding calls. Default: embed synchronously under a rate limit with a background queue; expose `fulcrum content-index status` showing queue depth. Planning decides: cold-start progress bar / partial-index readiness threshold.
8. **Language coverage.** AST chunker currently supports TS/JS/TSX/JSX only; Python/Java/Go/Rust/C/C++ fall back to regex-syntax chunker. Planning: adopt additional tree-sitter grammars behind a flag, or accept regex fallback as good-enough for v2.
9. **Gitignore respect.** The watcher must honor `.gitignore` globs — current `ingestProject` uses a hardcoded exclusion list. Planning picks: `ignore` npm package vs. shell out to `git ls-files`.
10. **Watcher scope in multi-workspace monorepos.** When the project has multiple workspaces (e.g., this repo's `packages/*`), one watcher at the repo root vs. one per workspace. Default: one at repo root; planning confirms this matches `FULCRUM_WORKSPACE` conventions.
11. **Rename detection tuning.** Chokidar's 500ms rename-pair heuristic can be fooled by rapid save-delete-save patterns. Planning decides: accept occasional mis-classification vs. use git-rename detection on a periodic sweep.
12. **Global-scope policy — which roles?** `scope: 'global'` exposes cross-workspace knowledge. Default policy (defaulted to most restrictive): `chief_of_staff` ALLOWED, `software_engineer` / `test_engineer` / `reviewer` DENIED in other workspaces (allowed only in their own workspace). Planning confirms with `fulcrum-policy` rules and the `SYSTEM_INVARIANTS` table. Candidate approvers (configurable per install): any L1 role; any role with explicit `can_query_global` capability.
13. **Session-scope storage.** Where does `scope: 'session'` data live? Option A: transient in-memory rolling window per `run_id` (lost on restart). Option B: persisted to a `session_transcripts` table alongside memories, scoped to run. Planning picks based on whether session-scope recall should survive crash.
14. **Index rebuild safety.** Reingesting a project from scratch (e.g., after schema migration) should not race with live writes. Planning decides: drain watchers + freeze writes during reindex vs. dual-write to a shadow table.
15. **RRF vs. weighted-sum fusion.** Current plan uses RRF (Reciprocal Rank Fusion) for FTS + vec + graph. prior art's benchmarked pipeline uses weighted linear combination (`0.6 vec + 0.4 bm25_normalized`) — simpler, empirically strong (96.6% R@5 on LongMemEval with MiniLM-L6 + no LLM). Planning runs a head-to-head ablation against Fulcrum's test corpus before committing; preserves the option to swap fusion in one place if prior art's weighted scheme wins.
16. **Global-pointer collection refresh cadence.** `global_index.md` is rebuilt by Dreaming REM phase. Planning decides: full rebuild nightly vs. incremental append per new durable entry. Full-nightly is simpler; incremental is fresher but needs to handle supersession edits correctly.
17. **Benchmark harness.** Adopt a pinned LongMemEval subset as Fulcrum's recall regression bench (prior art-inspired). Planning specifies: which splits, how often CI runs it, what constitutes a regression (§11.35 default: ≥90% R@5).
18. **WAL retention + compliance.** 90-day default retention is a guess. Planning confirms against any data-retention requirements the user has and sets per-install configurable TTL.
19. **Invocation CLI shape (§1.4).** `fulcrum workflow {list|run}`, `fulcrum policy rules {list|enable|disable}`, `fulcrum pi cockpit {start|stop|status}`. No `skills install` command — skills are always-present files on disk, loaded natively by agent hosts. No `workflow install` — definitions always ship with Fulcrum. Planning confirms exact names, error shapes, and whether to build a `list_activations` MCP tool (read-only, no side effects).
20. **Skill authoring + distribution.** Skills ship in-repo under `agent-integration/skills/` and native host paths. Planning confirms: (a) do we ship one superset to every host, or per-host subsets tuned to each agent's native capabilities; (b) does Dreaming's proposal pipeline (§8.2) generate new candidate skills, and if so is there a promotion workflow before they land in the shipped set.
21. **Workflow definition format.** YAML in `workflows/*.yaml` is the assumed default. Planning confirms schema, hot-reload semantics (does edit-on-disk invalidate in-memory definitions mid-session?), and versioning.
22. **Rule toggling UX.** Operator-only toggling of `policy_rules.enabled` — via CLI or dashboard? Per-workspace or global? Planning specifies the rule management surface.
23. **Selective MCP exposure — which actions?** The MCP overlay is a subset of CLI actions. Planning picks the default filtered set. Candidates: (a) "recall-only" for agent hosts that want read but not mutation; (b) role-based profiles (`--profile software_engineer`, `--profile chief_of_staff`) matching the existing `fulcrum serve mcp --profile` flag; (c) "write-side" that excludes destructive orchestration actions (`invoke_team`); (d) "full" for agents that can't use CLI-first at all. Verify mapping against existing 23-tool MCP surface in `packages/cli/src/mcp-tools.ts`.
24. **Which agent hosts need MCP installed vs which use CLI-first?** Planning confirms per-host: Claude Code (CLI-first via hooks+skills), Gemini (CLI-first), Codex (CLI-first), OpenCode (CLI-first), Pi (CLI-first via cockpit). Non-CLI-first candidates: any agent host that can't invoke shell commands or doesn't support hook configuration files.
25. **Parity enforcement.** Planning specifies a test that asserts every CLI action has a domain function, and every MCP tool in the selective set dispatches to the same domain function. Prevents drift.
26. **Git ingestion strategy.** Three options: (a) periodic `git log` walker via Dreaming light phase, (b) post-commit / post-merge git hook writing directly via `fulcrum action exec record_commit`, (c) operator-invoked `fulcrum git backfill`. Planning picks. Default probably (a) + (b); (c) for initial backfill.
27. **External-ref sync cadence.** Webhook-driven vs poll-based for Plane / Jira / GitHub. Planning confirms per-adapter strategy and the conflict-resolution UI.
28. **Adapter identity scheme.** `agent_adapter.id` stable across restarts? Planning picks: `{executor_uri, model, version}` tuple vs. opaque ULID.
29. **Graph query language on monitor.** Cypher (Kuzu-native) vs. custom JSON traversal DSL. Planning picks based on exposure risk (Cypher is powerful; unsafe if exposed publicly).
30. **Prose chunker selection.** Markdown-aware chunker lives where? Planning picks between: extend existing `packages/memory/src/chunkers/ast-chunker.ts` vs. new `packages/memory/src/chunkers/markdown-chunker.ts`. Also: overlap policy for prose (code has zero overlap; prose wants some).
31. **Per-host plugin standardization.** Pending deliverable from `docs/research/plugin-standards-per-agent-host.md` (research agent in flight). Planning consumes that doc and specifies the concrete `agent-integration/<host>/` upgrade PRs.
