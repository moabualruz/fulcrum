# Fulcrum Codebase Audit — 2026-04-15

**Scope:** Full audit across all 11 packages + agent integration files  
**Method:** Deep source reading + cross-reference against 2025-2026 industry standards  
**Verdict:** Sophisticated scaffold. Core data model is solid. Critical runtime bugs exist. Large capability gaps. Needs 6 targeted fixes + 5 structural changes before production trust.

## Executive Summary

Fulcrum covers all the right domains: task tracking, memory, policy, teams, workflows, and multi-agent orchestration across 11 well-organized packages. The data model is well-normalized. The MCP server is built on the official SDK and the tool schemas are comprehensive. The memory package's L0/L1/L2 layering is architecturally sound. The policy engine is correctly designed.

**The honest problem:** There is a wide gap between what the type system describes and what executes correctly in production.

- The policy engine is fully implemented but **never wired into the enforcement path** — the HTTP endpoint that hooks call is a hardcoded stub that bypasses the engine entirely.
- The semantic extractor returns `[]` permanently — the L2 Kuzu graph has structural edges but zero LLM-derived semantic edges.
- The worker adapter exists but nothing dispatches work to it — there is no actual agent launch mechanism.
- The embedding registry silently returns `null` for 6 of 7 configured providers — any non-local config degrades silently to FTS5-only with no warning.
- The SSE stream that powers the dashboard uses the wrong column name (`event_id` vs `evt_id`) — it has never worked.
- The HTTP MCP transport spawns a new server per request, destroying all session state.

This is a sophisticated shell. The bones are good. The soft tissue is missing or disconnected.

## CRITICAL ISSUES — Must Fix Before Any Production Use

### C-1: O(N) Full-Corpus Embedding Scan — OOM Under Real Load
**File:** `packages/core/src/memory.ts:155–174`  
**Standard violated:** Vector dedup must use ANN index query, not full table scan

`writeMemory` loads every embedding blob for the entire workspace+project into Node.js memory:
```typescript
SELECT *, embedding FROM memories WHERE workspace_id = ? AND project_id = ?
```
Then iterates with an in-process cosine similarity loop. A workspace with 10,000 memories = ~40MB of float32 vectors serialized through the SQLite driver on **every write**. This will OOM under any real workload.

The `@fulcrum/memory` `write.ts` correctly uses SHA256 dedup instead. The core version is still reachable via `core/runs.ts:7`.

**Fix:** Replace full-scan loop with a single ANN nearest-neighbor query via sqlite-vec, or adopt the SHA256 dedup path from `@fulcrum/memory`. Best fix: delete `core/src/memory.ts` entirely (see C-6).

---

### C-2: MCP Resource `memory` Calls Recall With Empty Query — Always Broken
**File:** `packages/cli/src/mcp-server.ts:226`  
**Standard violated:** MCP resource reads must not trigger domain validation errors

```typescript
const data = await options.handleToolCall('recall_memory', {
  query: '',   // ← throws FulcrumError('query must not be empty')
  workspace_id,
  project_id,
  limit: 50,
})
```

Both `recallMemory` implementations throw on empty input. Any MCP client fetching `fulcrum://{workspace_id}/memory/{project_id}` gets a server error. This resource has never worked.

**Fix:** Remove the resource or implement it as a direct DB read (SELECT recent memories, no query needed) bypassing the recall API.

---

### C-3: HTTP Transport Spawns New McpServer Per Request — Session State Destroyed
**File:** `packages/cli/src/mcp-server.ts:362–376`  
**Standard violated:** MCP spec — one McpServer instance per client session

```typescript
const httpServer = createServer(async (req, res) => {
  const mcpServer = createFulcrumMcpServer(options)  // new instance every request
  const transport = new StreamableHTTPServerTransport(...)
  await mcpServer.connect(transport)
  await transport.handleRequest(req, res)
})
```

Streamable HTTP transport exists for **persistent sessions**. Creating a new `McpServer` per request throws away all session state, defeats capability negotiation, and doubles tool-registration work on every call. The SDK requires one `McpServer` per session.

**Fix:** Maintain a session map keyed by session ID from the transport. Reuse the server instance for the same session ID.

---

### C-4: Monitor Write Endpoints Entirely Unauthenticated
**File:** `packages/monitor/src/server.ts`  
**Standard violated:** OAuth 2.1 / bearer token auth; principle of least privilege

`POST /tasks`, `POST /runs`, `PATCH /tasks/:id`, `POST /memory/write`, `POST /runs/:id/complete`, `POST /runs/:id/block` — all unauthenticated. Any local process or browser script can:
- Create fake task completions
- Inject arbitrary memories (including with `importance: 1.0`)
- Block legitimate runs
- Fake agent run records

`POST /runs/:id/complete` auto-writes `task_outcome` memories. This is a high-severity backdoor into the memory system.

**Fix:** Generate a shared secret at vault init, store it in `~/.fulcrum/token`. Require `Authorization: Bearer <token>` on all mutating endpoints. Read-only endpoints (GET) can remain open for dashboard use.

---

### C-5: Agent Definitions Not Workspace-Scoped — Silent Multi-Workspace Collision
**File:** `packages/core/src/agent-definitions.ts:51–53, 90`  
**Standard violated:** Multi-tenancy isolation — per-entity uniqueness must include tenant ID

```typescript
const existing = db.prepare('SELECT id FROM agent_definitions WHERE role = ?').get(input.role)
// Missing: AND workspace_id = ?
```

Uniqueness enforced globally across workspaces. Workspace A registers `software_engineer` with `claude-opus-4-5` — workspace B silently fails to register its own definition. In a multi-project setup, the first installer wins for all projects.

**Fix:** Add `workspace_id` column to `agent_definitions`. Change uniqueness constraint to `(workspace_id, role)`. Update all queries.

---

### C-6: SSE Stream Uses Non-Existent Column — Dashboard Events Never Work
**File:** `packages/monitor/src/server.ts:100–108`  
**Standard violated:** Basic SQL correctness

```typescript
// SSE queries events WHERE event_id > ?
// But the events table uses evt_id (TEXT/ULID), not event_id
```

The `events` table schema defines `evt_id` (TEXT ULID). The SSE stream queries `event_id` (non-existent column). This query returns zero rows silently — the SSE stream that powers real-time dashboard updates has never delivered a single event.

**Fix:** Change the SSE query to use `rowid` as cursor (stable, monotonically increasing) and filter by `rowid > ?`. Store the last `rowid` as the SSE cursor.

## MAJOR ISSUES — Fix Before Trusting the System

### M-1: Policy Engine Fully Implemented — Never Called
**File:** `packages/monitor/src/server.ts:653–671`  
**Standard violated:** Defense in depth — security policy must be enforced at runtime, not advisory-only

```typescript
// /policy/check endpoint — the path Claude Code hooks call
const isTeamInvoke = body.action.includes('invoke_team')
const callerIsL1 = isL1(role as AgentRole)
if (isTeamInvoke && !callerIsL1) {
  return c.json({ allowed: false, reason: 'Only chief_of_staff may invoke teams' })
}
return c.json({ allowed: true, reason: '' })  // everything else is always allowed
```

`packages/policy/src/engine.ts` — with system invariants, per-workspace DB rules, glob matchers, regex patterns, audit logging — is never called from the HTTP API. The PreToolUse hook calls this endpoint. Therefore **99% of policy enforcement is permanently disabled**. Role boundaries are comments in markdown files.

**Fix:** Wire the endpoint to `evaluatePolicy` from `@fulcrum/policy`. Pass the full `EvaluatePolicyInput`. Log via `logPolicyEvent`. This is a ~10-line change with massive security impact.

---

### M-2: Two Divergent `recallMemory` Implementations — Silent Split Brain
**Files:** `packages/core/src/memory.ts`, `packages/memory/src/recall.ts`

Two different implementations with the same function signature but different behaviors:
- Core version: no L0 vault write, no extraction pipeline, no graph enqueue, vulnerable to FTS5 injection (see M-9)
- Memory package: proper L0/L1/L2 pipeline, SHA256 dedup, secure FTS5 escaping

`core/runs.ts:7` imports the core (degraded) version. MCP tools use the memory package version. Agents running via the control plane get different memory behavior depending on which code path triggers the write. This is a silent data integrity issue.

**Fix:** Delete `core/src/memory.ts`. `@fulcrum/core` owns types; `@fulcrum/memory` owns all I/O. Update `runs.ts` to use a lightweight inline INSERT or import from `@fulcrum/memory`.

---

### M-3: N+1 Query Pattern in `listTasks`
**File:** `packages/core/src/tasks.ts:69–88`

`hydrateTask` fires 2 queries per task row — one for `task_labels`, one for `task_relations`. Listing 100 tasks = 201 synchronous SQLite queries. A Kanban board render is a 200-query serial scan.

**Fix:** Two batch queries using `IN (...)` with collected task IDs, then merge results in memory.

---

### M-4: No Task State Machine — Arbitrary Transitions Accepted
**File:** `packages/core/src/tasks.ts:147–207`

`updateTask` accepts any status value without validation. A task can move `completed → queued`, or `cancelled → running`. There is no guard. This corrupts the lifecycle model and breaks CoS context summaries that assume monotonic progression.

**Fix:** Define `VALID_TRANSITIONS` map. Reject invalid transitions with `FulcrumError`. Minimum: `completed` and `cancelled` are terminal — no transitions out without explicit `reopen` action.

---

### M-5: Embedding Registry Silently Returns `null` for 6 of 7 Providers
**File:** `packages/core/src/embedding/registry.ts:11–19`

```typescript
if (config.embedding.text.provider === 'local') {
  textProvider = new LocalEmbeddingProvider(config.embedding.text)
}
// OpenAI, Voyage, Cohere, Ollama, Jina, custom — silently no-op
```

A user configuring `provider: 'openai'` gets `textProvider = null`, FTS5-only search, no embeddings, no warning. The config validation accepts all 7 provider names. This is a silent capability cliff.

**Fix:** `else { throw new Error(\`Embedding provider '${provider}' is not implemented\`) }`. Or implement the providers. voyage-code-3 via Voyage AI and text-embedding-3-large via OpenAI are the highest priority (see research section for why voyage-code-3 is the right choice for code).

---

### M-6: `completeHandoff` Has No Status Guard
**File:** `packages/core/src/handoffs.ts:201–217`

`claimHandoff` validates status; `completeHandoff` does not. Calling `completeHandoff` on a `cancelled` or already `completed` handoff produces duplicate `handoff_consumed` events and corrupts the handoff lifecycle.

**Fix:** Add `if (existing.status !== 'claimed') throw new FulcrumError(...)` before the UPDATE.

---

### M-7: Plans Emit Wrong Event Type
**File:** `packages/planning/src/plans.ts:91–99`

```typescript
emitEvent({ evt_type: 'task_status_changed', object_type: 'plan', ... })
```

Plans are not tasks. Downstream consumers of `task_status_changed` (CoS context builder, janitor, monitor) will misprocess these events. Plan status changes must use a dedicated event type.

**Fix:** Add `plan_status_changed` to the `EventType` union in `core/src/events.ts`.

---

### M-8: `getTeamOps()` Defeats TypeScript — `Record<string, unknown>`
**File:** `packages/core/src/index.ts:139–143`

```typescript
export async function getTeamOps(): Promise<Record<string, unknown>> {
  // @ts-ignore — dynamic sibling import
  const mod = await import('@fulcrum/teams')
  return mod as unknown as Record<string, unknown>
}
```

Every caller gets `Record<string, unknown>` — no type safety, no autocomplete, no compile-time validation. A misspelled method name fails silently at runtime. The circular dependency (teams → core) that drove this workaround is real but the fix is wrong.

**Fix:** Define a `TeamOps` interface in `core/src/team-ops.ts` (types only, zero imports). Have `@fulcrum/teams` implement it at registration time. Remove `@ts-ignore`.

---

### M-9: FTS5 Injection via Raw Query Pass-Through
**File:** `packages/core/src/memory.ts:282–289`

The core `recallMemory` passes the user's raw query string directly to `FTS5 MATCH`. An injection like `NOT content:*` or `"-*"` will crash with `SQLITE_ERROR`. The `@fulcrum/memory` version correctly tokenizes and double-quotes terms. Since M-2 fix (delete core/memory.ts) resolves this transitively, it is listed for awareness only.

---

### M-10: `recallMemory` Discards Kuzu L2 Ordering
**File:** `packages/memory/src/recall.ts:186–191`

When Kuzu L2 returns results, they are fetched from SQLite without preserving vector similarity order:
```typescript
const rows = db.prepare(`SELECT m.* FROM memories m WHERE m.memory_id IN (...)`).all(...ids)
// SQLite IN clause order is non-deterministic
```

The L2 ranking (by vector similarity) is thrown away. The returned order is random.

**Fix:** After the SQLite fetch, remap rows to match the `l2Results` ordering using a Map lookup by memory_id.

## MINOR ISSUES

**m-1** `core/memory.ts:293–294` — LIKE fallback sets `rank: 0` which after `normalizeFtsRank(0)` yields score `1.0` — a LIKE match ranks equal to a perfect BM25 match. Use `rank: -1` as the sentinel.

**m-2** `memory/src/chunkers/ingest.ts:25` — `SYNTAX_BOUNDARIES` regex only matches `function` and `class`. Arrow functions, object methods, decorators, TypeScript interfaces all missed. Files using arrow-function style produce one giant chunk. Fix: use tree-sitter (already a dep) instead of regex.

**m-3** `core/src/embedding/reranker.ts:41–42` — assumes flat `Float32Array` for logits. Cross-encoders with `[n_pairs, 1]` output work; binary classifiers with `[n_pairs, 2]` output (relevance/irrelevance logit pairs) produce wrong scores. Add shape validation.

**m-4** `memory/src/scoring.ts:42–46` — freshness `= 0` for >90-day memories hard-gates their score to 0. A 91-day-old memory with perfect relevance is permanently invisible. Change to soft logarithmic decay, not binary cutoff.

**m-5** `sync/src/sync.ts:19–38` — `buildManager` constructs a new `PlaneAPIClient` on every `syncAll` call. Harmless now; will matter if initialization becomes expensive. Singleton the client.

**m-6** `agent-integration/skills/complete-agent-run/SKILL.md:28` — references `summary` parameter; the MCP tool schema defines `output_summary`. Inconsistency will cause agents to use the wrong parameter name.

**m-7** Migrations file is a single monolithic string of 31K tokens. No per-migration rollback. Future schema changes risk corrupting the entire migration history. Split into `migrations/001_*.ts`, `002_*.ts`, etc.

**m-8** All `async` functions in `tasks.ts`, `policy.ts`, `handoffs.ts`, `teams.ts` are synchronously blocking (better-sqlite3 is sync). Functions return `Promise<T>` with no `await` points. Misleads maintainers and prevents event loop yield during bulk operations.

## MISSING ENTIRELY

### X-1: No Agent Dispatch
The control plane tracks agents but does not launch them. `start_agent_run` records state; it does not cause any agent to execute. `worker/src/adapters/claude-code.ts` exists but is dead code — nothing wires from MCP tool handlers to it. Documentation implies active orchestration; the implementation is passive logging.

**What's needed:** A dispatch layer that, when `start_agent_run` is called, either (a) invokes the Claude Code CLI in a subprocess with the appropriate task context, or (b) exposes a webhook/polling endpoint that a waiting agent process can use to receive its assignment.

---

### X-2: Semantic Extraction Is a Stub
**File:** `packages/memory/src/extractors/semantic.ts`

Returns `[]` permanently. The Kuzu graph has structural edges (IMPORTS, DEFINES, CALLS) but zero LLM-derived semantic edges (ABOUT, CRITIQUES, RECOMMENDS, RELATED_TO). The L2 graph's primary value proposition over FTS5 is absent. Graph recall is structural only.

**What's needed:** An LLM extraction pass that reads chunks and emits semantic entity/relationship tuples. These tuples populate the Kuzu graph. Without this, the graph layer adds complexity without delivering better recall than FTS5.

---

### X-3: No Runtime Policy Enforcement for Tool Calls
The policy engine (M-1) is wired nowhere in the real tool call path. Role boundaries (L1 cannot write code; L2 cannot spawn workers) are in markdown role files that agents can simply ignore. A software_engineer agent calling `start_agent_run` to spawn a team is allowed by the system.

**What's needed:** The PreToolUse hook → monitor → `evaluatePolicy` → block path must work end-to-end. Currently the endpoint bypasses the engine.

---

### X-4: No Rate Limiting or Memory Quotas
An agent calling `write_memory` in a tight loop grows the vault unbounded. No per-workspace memory quota, no rate limiter, no GC trigger, no dedup for content-identical writes at the HTTP API level.

**What's needed:** Per-workspace write budget (configurable, defaulting to e.g. 10,000 entries). Rate limit at the MCP tool level (token bucket per workspace). Expose usage stats in the monitor.

---

### X-5: No Recovery for Stale/Orphaned Runs
The janitor marks stale runs. There is no mechanism to retry a stale run, reassign its task, or notify the CoS. A task with a stale run is permanently blocked with no automated recovery.

**What's needed:** Stale run → reassign task to `queued`, emit `run_stale` event, notify CoS via heartbeat or webhook.

---

### X-6: 6 of 7 Embedding Providers Are Stubs
OpenAI, Voyage, Cohere, Ollama, Jina, custom — all accepted in config, all silently produce `null`. The system degrades to FTS5-only with no signal to the user.

**Priority order for implementation:**
1. **voyage-code-3** (Voyage AI) — best code retrieval model (2024-2025), Matryoshka embeddings
2. **text-embedding-3-large** (OpenAI) — general purpose, broadly available
3. **Ollama** — local inference, privacy-sensitive environments
4. Others: Cohere, Jina, Anthropic (when available)

---

### X-7: No A2A Agent Card
The Google A2A protocol (v1.0, March 2026, Linux Foundation) defines a standard `/.well-known/agent.json` Agent Card for agent interoperability. Fulcrum agents have no machine-readable capability advertisement. They cannot be discovered or invoked by A2A-compatible orchestrators.

**What's needed:** Generate an Agent Card per registered agent definition. Expose `GET /.well-known/agent.json` from the monitor server. Include skill descriptions with input/output modes.

---

### X-8: No Hybrid Search (BM25 + Vector + RRF)
Current recall pipeline: FTS5 (BM25) **or** Kuzu L2 (vector) — selected by config flag. There is no fusion. The correct architecture is:

```
Query → [FTS5/BM25] + [Vector ANN]  →  RRF fusion  →  Cross-encoder reranking  →  Top-K
```

Hybrid search consistently outperforms single-modality retrieval for code (exact symbol names favor BM25; semantic similarity favors vectors). RRF fusion is 5 lines of code once both retrievers exist.

## Recommended Architecture Changes (Structural, Not Bug Fixes)

### SA-1: Delete `core/src/memory.ts` — Single Memory Authority
`@fulcrum/core` owns types. `@fulcrum/memory` owns all I/O. Eliminates split-brain, FTS5 injection, OOM scan, and divergent behavior in one change.

### SA-2: Define `TeamOps` Interface in Core — Kill `@ts-ignore`
`core/src/team-ops.ts` with types only (no imports). `@fulcrum/teams` registers against it. Eliminates the circular dependency workaround and restores type safety.

### SA-3: Wire Policy Engine End-to-End
`/policy/check` → `evaluatePolicy` → `logPolicyEvent`. Currently the most impactful security gap. 10-line change, massive security uplift.

### SA-4: Split Monolithic Migration String Into Versioned Files
`migrations/001_initial.ts`, `002_*.ts`, etc. Applied sequentially by the migration runner. Enables per-migration rollback and reduces future change risk.

### SA-5: Implement voyage-code-3 + Hybrid Search Pipeline
The memory package's L2 path is the system's competitive differentiator. Without real code embeddings and hybrid search, the system delivers lower recall quality than a simple grep. This is the highest-leverage capability investment.

### SA-6: Add A2A Agent Card Generation
Position Fulcrum as an A2A-compatible control plane. Generate agent cards from registered agent definitions. Enables interoperability with Copilot, Gemini, and other A2A-compatible orchestrators.

## Performance and Data Model Audit (Pass 2 — 2026-04-15)

### NEW CRITICAL: `PRAGMA foreign_keys` Never Enabled
**File:** `packages/core/src/db/client.ts`

All `REFERENCES ... ON DELETE CASCADE` constraints declared in every table are silently unenforced. Deleting a workspace does NOT cascade-delete tasks, runs, memories, events, epics, issues, or anything. Orphan rows accumulate forever. One-line fix: add `PRAGMA foreign_keys = ON` to `_configureDb()`.

### NEW CRITICAL: L2 Recall Fetches Rows Without Workspace Filter — Data Isolation Bug
**File:** `packages/memory/src/recall.ts:185`

```typescript
// Missing: AND m.workspace_id = ?
const rows = db.prepare(`SELECT m.* FROM memories m WHERE m.memory_id IN (...)`).all(...ids)
```

If the Kuzu graph returns a memory_id from a different workspace (possible in multi-workspace deployments), the SQLite query returns it without any access control check. Cross-workspace memory leakage in the L2 path.

### Data Model Bugs

**Dual representation for task dependencies:** `tasks.depends_on` (JSON array) AND `task_relations` table with `relation_type = 'blocks'` — both exist, are maintained separately, and can diverge. Remove `depends_on` JSON column entirely; use `task_relations` as the single source.

**`agent_runs.events` JSON blob grows O(N) per heartbeat:** Every heartbeat reads the full JSON array, appends one event, writes back. At 100 heartbeats = 100 read+parse+serialize+write cycles of growing blobs. Fix: separate `run_events(event_id, run_id, ts, event_type, payload)` table.

**`memories.freshness` never decays:** Stored as a static snapshot at write time. `computeFreshness()` in `scoring.ts` is dead code — never called by write or janitor paths. Every memory retains its initial freshness forever. Freshness computation should happen at query time from `updated_at`.

**`scope` CHECK constraint silently dropped on new databases:** MIGRATION_005 tries to add `CHECK(scope IN ('global','project','file'))` but MIGRATION_002 already added the column without CHECK. On new databases, MIGRATION_005's `ALTER` is skipped (column exists), and the CHECK is never applied. Any string is valid in `scope`.

**Timestamp format inconsistency:** SQLite DDL uses `datetime('now')` format (`2026-04-15 10:30:00`); application code uses `new Date().toISOString()` format (`2026-04-15T10:30:00.000Z`). Cross-table timestamp comparisons will sort incorrectly when rows from both formats are compared. Standardize on one.

**`monitor/src/metrics.ts:139` — wrong column `event_type`:** Should be `evt_type`. Memory recall counts in all analytics rollups are permanently 0.

**`monitor/src/metrics.ts:778` — `replayRun` uses `json_extract` on `events` without index:** Full table scan at O(N_events) per replay. Should use a `run_id` column on `events` or `correlation_id`.

## Security Audit (Pass 2 — 2026-04-15)

### NEW CRITICAL: Path Traversal via Unsanitized IDs in Vault File Paths
**File:** `packages/memory/src/vault/client.ts:117–159`

`workspace_id`, `project_id`, `task_id`, and `memory_id` are passed directly to `path.join()` without sanitization. Any caller controls their workspace_id.

**PoC:**
```json
POST /memory/write
{ "workspace_id": "../../../../.ssh", "project_id": "authorized_keys", "content": "ssh-rsa AAAA..." }
```
Resolves to a path outside the vault. With the right traversal, this is a file write-anywhere = code execution.

**Fix:** Validate all ID segments against a strict allowlist before entering any `path.join()`:
```typescript
if (!/^[a-zA-Z0-9_\-]{1,128}$/.test(id)) throw new FulcrumError('Invalid ID for path use', 'invalid_input')
```

### NEW CRITICAL: Cross-Workspace Memory Exfiltration via `query_scope: 'global'`
**File:** `packages/memory/src/recall.ts:56–59`

`buildWhereClause` with `query_scope: 'global'` adds NO WHERE clause — returns `{ clauses: ['1=1'], params: [] }`. Any agent in any workspace can read ALL memories across ALL workspaces.

**PoC:**
```
mcp__fulcrum__recall_memory({ query: "api key", workspace_id: "my_ws", query_scope: "global" })
// Returns memories from every other workspace in the DB
```

**Fix:** Remove `global` scope or gate behind explicit admin capability. At minimum: always filter to calling agent's workspace.

### Complete Policy Bypass Map

Six distinct bypass paths — any one of them defeats all policy enforcement:

1. **`/policy/check` stub** — Engine never called; hardcoded stub allows everything except `invoke_team` by non-L1
2. **Self-reported identity** — `actor_id` is caller-supplied; `actor_id: "pi/chief_of_staff"` passes the only real check

4. **Monitor HTTP endpoints have no policy gate** — Domain mutations via HTTP API sidestep the hook path

### Attack Scenarios (Concrete)

### NEW CRITICAL: TOCTOU Race in `acquireLock`
**File:** `packages/core/src/locks.ts:70–91`

Three operations — `DELETE WHERE expires_at < now`, `SELECT WHERE resource_key = ?`, `INSERT` — execute as separate statements with no enclosing `db.transaction()`. Two concurrent agents can both see the SELECT returning no rows and both attempt INSERT, resulting in either a uniqueness violation or a double-granted lock.

**Fix:** Wrap all three statements in `db.transaction(() => { ... })`. SQLite serializes writers; the transaction makes check-then-insert atomic.

---

### NEW CRITICAL: `completeAgentRun` / `blockAgentRun` Lack Terminal State Guards
**File:** `packages/core/src/runs.ts:286, 343`

Neither function checks `existing.status` before updating. Calling `completeAgentRun` on an already-blocked run transitions it back to `finished`. `heartbeatAgentRun` after completion silently mutates `updated_at` on a finished run, corrupting the janitor's staleness calculation.

**Fix:**
```typescript
const TERMINAL = new Set(['finished', 'aborted', 'failed', 'blocked'])
if (TERMINAL.has(existing.status)) {
  throw new FulcrumError('invalid_state', `Run ${run_id} is already terminal`)
}
```
Apply to `completeAgentRun`, `blockAgentRun`, and `heartbeatAgentRun`.

### NEW CRITICAL: `'stale'` Status Not Handled — Stale Runs Appear Active
**File:** `packages/core/src/status-category.ts`

`'stale'` is a valid `AgentRunStatus` but is absent from all four status sets. The function's catch-all returns `'active'`. A workspace with 10 stale (dead) runs appears to have 10 active agents. CoS makes scheduling decisions based on fabricated WIP count.

**Fix:** Add `'stale'` to `BLOCKED_STATUSES`.

### NEW CRITICAL: Label Replacement in `updateTask` Not Atomic

`DELETE FROM task_labels` + per-label `INSERT INTO task_labels` + task `UPDATE` are three separate statements outside any transaction. Process crash between DELETE and INSERT permanently loses all task labels.

**Fix:** Wrap task UPDATE + label DELETE + label INSERTs in a single `db.transaction()`.

### NEW Major: `cos-context.ts:80` LIKE Injection via Goal String

### Cross-Cutting Patterns Requiring Standardization

1. **Bare `Error` vs `FulcrumError`** — 4+ sites use `new Error(...)` instead of `FulcrumError(code, message)`. Add ESLint rule banning bare `Error` in domain packages.

2. **Missing `db.transaction()` around multi-statement writes** — `tasks.ts` (create + labels), `tasks.ts` (update + labels), `locks.ts` (DELETE + SELECT + INSERT), `handoffs.ts` (UPDATE + event INSERT). All need transactions.

4. **No terminal state guard on run lifecycle** — `completeAgentRun`, `blockAgentRun`, `heartbeatAgentRun` all need the same guard pattern. Extract `assertRunIsLive(run_id, db)` helper.
